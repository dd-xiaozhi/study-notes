## 1. ACL 访问控制详解

### 1.1 ACL 概述

ACL（Access Control List）是 Redis 6.0 引入的全新访问控制机制，用于替代传统的 `requirepass` 简单密码认证。ACL 提供了更细粒度的权限控制，允许对不同用户设置不同的命令权限和键空间访问权限。

**ACL 的核心优势：**

- 细粒度权限控制：可以控制用户对特定命令和键的访问权限
- 多用户支持：支持创建多个具有不同权限的用户
- 最小权限原则：默认拒绝，只授予必要的权限
- 运行时动态修改：无需重启即可修改用户权限
- 连接元数据追踪：可记录用户执行的命令和访问的键

### 1.2 ACL 规则语法

ACL 规则由多个规则标记组成，用空格分隔，按照从左到右的顺序应用。

**基本语法结构：**

```sh
# 创建用户的基本语法
ACL SETUSER username [rule1] [rule2] [rule3] ...

# 启用用户的完整语法示例
ACL SETUSER alice on >password ~cached:* +get +mget -@all
```

**规则标记说明：**

| 规则标记 | 说明 | 示例 |
|---------|------|------|
| `on` | 启用用户 | `on` |
| `off` | 禁用用户 | `off` |
| `>+password` | 设置密码 | `>+mypassword123` |
| `>-password` | 删除密码 | `>-mypassword123` |
| `nopass` | 无需密码（不推荐） | `nopass` |
| `~pattern` | 允许访问的键模式 | `~app:*` |
| `%R~pattern` | 只读键模式（Redis 7.0+） | `%R~read:*` |
| `+command` | 允许执行的命令 | `+get` |
| `-command` | 禁止执行的命令 | `-flushall` |
| `+@category` | 允许某类命令 | `+@read` |
| `-@category` | 禁止某类命令 | `-@dangerous` |
| `allcommands` | 允许所有命令 | `+allcommands` |
| `nocommands` | 禁止所有命令 | `-allcommands` |

**命令分类（@category）：**

```sh
@read        # 读取类命令：get, mget, hget, lrange 等
@write       # 写入类命令：set, mset, hset, lpush 等
@admin       # 管理类命令：config, flushall, shutdown 等
@dangerous   # 危险类命令：flushdb, keys, debug 等
@published   # 发布订阅类命令：publish, subscribe 等
@transaction # 事务类命令：multi, exec, discard 等
@scripting   # 脚本类命令：eval, evalsha 等
@connection  # 连接管理命令：auth, ping, select 等
@server      # 服务器管理命令：dbsize, info, time 等
@keyspace    # 键空间命令：scan, keys 等
@fast        # 快速命令（O(1)复杂度）
@slow        # 慢速命令
@blocking    # 阻塞命令
@writing     # 写入命令
@reading     # 读取命令
@set         # Set 类型相关命令
@sortedset   # Sorted Set 类型相关命令
@list        # List 类型相关命令
@hash        # Hash 类型相关命令
@string      # String 类型相关命令
@bitmap      # Bitmap 类型相关命令
@hyperloglog # HyperLogLog 类型相关命令
@geo         # 地理位置相关命令
@stream      # Stream 类型相关命令
@pubsub      # 发布订阅命令
```

```sh

ACL SETUSER readonly_user on nopass ~readonly:* +@read -@write
```

**实战示例 - 多种用户角色配置：**


## 2. 密码策略

### 2.1 密码复杂度要求

虽然 Redis 本身不强制密码复杂度，但生产环境中应遵循严格的密码策略。

**推荐密码策略：**

```sh

- 必须包含：大写字母、小写字母、数字、特殊字符
```

### 2.3 密码过期策略（ACL EXPIRES）

Redis 本身不提供密码过期功能，但可以通过以下方式实现：

**方式一：结合外部认证服务**

```java
// 应用层面实现密码过期检查
public class RedisAuthService {

    private JedisPool jedisPool;
    private Map<String, Long> passwordExpiryMap = new ConcurrentHashMap<>();

    public boolean authenticate(String username, String password) {
        // 1. 检查用户密码是否过期
        Long expiryTime = passwordExpiryMap.get(username);
        if (expiryTime != null && System.currentTimeMillis() > expiryTime) {
            throw new PasswordExpiredException("密码已过期，请联系管理员");
        }

        // 2. 执行认证
        try (Jedis jedis = jedisPool.getResource()) {
            return "OK".equals(jedis.auth(password));
        }
    }
}
```

**方式二：使用 Lua 脚本实现密码过期（Redis 7.0+）**

```lua
-- password_expiry.lua
-- 结合 Redis ACL 和外部存储实现密码过期

local function check_password_expiry(username)
    local expiry_key = "pwd:expiry:" .. username
    local expiry = redis.call('GET', expiry_key)

    if expiry then
        local ttl = redis.call('TTL', expiry_key)
        if ttl <= 0 then
            return redis.error_reply("PASSWORD_EXPIRED")
        end
    end

    return redis.call('ACL', 'GETUSER', username)
end

return check_password_expiry(KEYS[1])
```

### 2.4 密码验证失败锁定

Redis 原生不提供账户锁定功能，需要通过外部机制实现。

**方式一：应用层实现失败锁定**

```java
// RedisLoginAttemptService.java
public class RedisLoginAttemptService {

    private static final int MAX_ATTEMPTS = 5;
    private static final int LOCKOUT_DURATION_SECONDS = 1800; // 30分钟

    private JedisPool jedisPool;

    public boolean login(String username, String password) {
        String attemptKey = "login:attempts:" + username;

        // 检查是否已锁定
        String locked = jedisPool.getResource().get(attemptKey + ":locked");
        if ("true".equals(locked)) {
            throw new AccountLockedException("账户已锁定，请30分钟后再试");
        }

        // 验证密码
        try {
            jedisPool.getResource().auth(password);
            // 登录成功，清除失败记录
            clearAttempts(attemptKey);
            return true;
        } catch (JedisConnectionException e) {
            // 登录失败，记录失败次数
            handleFailedAttempt(attemptKey);
            throw new AuthenticationFailedException("用户名或密码错误");
        }
    }

    private void handleFailedAttempt(String attemptKey) {
        try (Jedis jedis = jedisPool.getResource()) {
            long attempts = jedis.incr(attemptKey);

            if (attempts >= MAX_ATTEMPTS) {
                // 达到最大失败次数，锁定账户
                jedis.setex(attemptKey + ":locked", LOCKOUT_DURATION_SECONDS, "true");
                jedis.del(attemptKey);
                log.warn("用户 {} 因多次登录失败已被锁定 {} 秒", attemptKey, LOCKOUT_DURATION_SECONDS);
            }
        }
    }

    private void clearAttempts(String attemptKey) {
        jedisPool.getResource().del(attemptKey, attemptKey + ":locked");
    }
}
```

**方式二：使用 Redis Cell 实现速率限制**

```lua
-- rate_limit.lua - 使用 Redis Cell 实现登录速率限制
local function login_rate_limit(username)
    local key = "rate_limit:login:" .. username
    local limit = 5  -- 最大尝试次数
    local window = 1800  -- 时间窗口（秒）

    local current = redis.call('GET', key)

    if current and tonumber(current) >= limit then
        return 0, "账户已被锁定"
    end

    if current then
        redis.call('INCR', key)
    else
        redis.call('SET', key, 1, 'EX', window)
    end

    return 1, "OK"
end

return login_rate_limit(KEYS[1])
```

## 3. 危险命令禁用

### 3.1 FLUSHDB/FLUSHALL 风险分析

`FLUSHDB` 和 `FLUSHALL` 是 Redis 中最危险的命令，它们会清空当前数据库或所有数据库中的所有数据。

**风险场景：**

| 命令 | 风险等级 | 影响范围 | 潜在损失 |
|------|---------|---------|---------|
| FLUSHDB | 高 | 当前数据库 | 当前库所有数据 |
| FLUSHALL | 极高 | 所有数据库 | 全量数据 |
| FLUSHDB ASYNC | 高 | 当前数据库（异步） | 当前库所有数据 |
| FLUSHALL ASYNC | 极高 | 所有数据库（异步） | 全量数据 |

### 3.2 CONFIG 命令风险分析

`CONFIG` 命令允许在运行时修改 Redis 配置，可能导致：

- 配置被恶意修改
- 服务器性能下降
- 安全漏洞引入
- 服务中断

**CONFIG 命令风险项：**

```sh
# 危险配置项
CONFIG SET requirepass ""           # 清空密码
CONFIG SET protected-mode no        # 关闭保护模式
CONFIG SET bind 0.0.0.0             # 绑定到所有地址
CONFIG SET dir /tmp                 # 修改数据存储路径
CONFIG SET dbfilename evil.rdb     # 修改备份文件名
CONFIG SET maxmemory 0              # 无内存限制
CONFIG SET loglevel debug           # 修改日志级别
```

### 3.4 命令重命名实战

**重命名命令的优势：**

1. 保留命令功能但防止误操作
2. 需要使用自定义名称执行命令
3. 攻击者无法使用标准命令

**重命名策略：**

```sh
# redis.conf - 推荐的重命名配置

# 高危命令 - 完全禁用（设置为空字符串）
rename-command FLUSHDB ""
rename-command FLUSHALL ""
rename-command FLUSHDBASYNC ""
rename-command FLUSHALLASYNC ""

# 高危命令 - 重命名为复杂随机字符串
rename-command CONFIG "CONFIG_z9x8y7w6v5u4t3s2"
rename-command KEYS "KEYS_m1n2o3p4q5r6s7t8"
rename-command DEBUG "DEBUG_k1l2m3n4o5p6q7r8"
rename-command BGSAVE "BGSAVE_a1b2c3d4e5f6g7h8"
rename-command SAVE "SAVE_i1j2k3l4m5n6o7p8"
rename-command SHUTDOWN "SHUTDOWN_q9r8s7t6u5v4w3x"

# 中危命令 - 保留但重命名
rename-command SCAN "SCAN_y1z2a3b4c5d6e7f8"
rename-command CLIENT "CLIENT_v1w2x3y4z5a6b7c8"
rename-command INFO "INFO_d9e8f7g6h5i4j3k2"
rename-command SLOWLOG "SLOWLOG_L2m3n4o5p6q7r8s9"
```

**应用中使用重命名后的命令：**

```java
public class RedisSafeCommands {

    private JedisPool jedisPool;

    // 使用重命名后的 CONFIG 命令

        try (Jedis jedis = jedisPool.getResource()) {
            // 调用重命名后的 CONFIG 命令
            return jedis.sendCommand("CONFIG_z9x8y7w6v5u4t3s2", "GET", parameter).toString();
        }
    }

    // 使用重命名后的 KEYS 命令
    public Set<String> scanKeys(String pattern) {
        try (Jedis jedis = jedisPool.getResource()) {
            // 调用重命名后的 KEYS 命令
            return jedis.sendCommand("KEYS_m1n2o3p4q5r6s7t8", pattern).toSet();
        }
    }
}
```

## 4. 网络安全加固

### 4.1 bind 配置最佳实践

`bind` 配置指定 Redis 监听的网络接口，正确的配置可以防止未授权访问。

**bind 配置选项：**

```sh
# redis.conf

# 监听所有接口（不推荐，除非关闭保护模式）
bind 0.0.0.0

# 监听特定 IP（推荐）
bind 127.0.0.1                    # 本地开发
bind 10.0.1.100                    # 应用服务器 IP

# 监听多个接口
bind 127.0.0.1 10.0.1.100

# 监听所有私有 IP（Redis 6.0+）
bind 0.0.0.0 ::1
bind 127.0.0.1

# 使用网络接口名称（Redis 6.0+）
bind lo eth0
```

**不同环境配置建议：**

```sh
# 开发环境
bind 127.0.0.1

# 测试环境
bind 127.0.0.1 10.0.1.50

# 生产环境 - 应用服务器网络
bind 127.0.0.1 10.0.1.100 10.0.1.101 10.0.1.102

# 生产环境 - Kubernetes 环境
bind 0.0.0.0  # 配合 protected-mode 和网络策略
```

### 4.2 protected-mode 使用

`protected-mode` 是 Redis 内置的安全保护机制，当没有设置密码且 bind 非本地地址时，会拒绝非本地连接。

**protected-mode 配置：**

```sh
# redis.conf

# 开启保护模式（默认开启）
protected-mode yes

# 关闭保护模式（仅在完全信任网络中使用）
protected-mode no
```

**protected-mode 行为规则：**

```
+------------------+------------------------+------------------------+
|     配置         |     bind               |     requirepass        |
+------------------+------------------------+------------------------+
| protected-mode   | 非本地地址             | 未设置                 |
| yes (默认)       | 拒绝远程连接           | 不允许连接             |
| yes              | 本地地址               | 允许本地连接           |
| yes              | 非本地地址             | 允许密码认证连接       |
| no               | 任意地址               | 允许连接               |
+------------------+------------------------+------------------------+
```

**安全配置建议：**

```sh
# 推荐的生产配置组合
bind 10.0.1.100                    # 只监听应用网络
protected-mode yes                 # 开启保护模式
requirepass "your_strong_password" # 启用强密码认证
```

### 4.4 SSL/TLS 配置（Redis 6.0+）

Redis 6.0 开始支持 SSL/TLS 加密连接。

#### 4.4.1 生成 SSL 证书

```sh
# 创建证书目录
mkdir -p /etc/redis/tls
cd /etc/redis/tls

# 生成 CA 证书
openssl genrsa -out ca.key 4096
openssl req -x509 -new -nodes -sha512 -days 3650 \
    -key ca.key \
    -out ca.crt \
    -subj "/C=CN/ST=Beijing/L=Beijing/O=Company/OU=IT/CN=Redis CA"

# 生成服务器证书
openssl genrsa -out redis.key 4096

# 创建服务器证书请求配置文件
cat > redis.cnf <<EOF
[req]
distinguished_name = req_distinguished
x509_extensions = v3_req
prompt = no

[req_distinguished]
C = CN
ST = Beijing
L = Beijing
O = Company
OU = IT
CN = redis.internal

[v3_req]
subjectAltName = @alt_names
basicConstraints = CA:FALSE
keyUsage = digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth, clientAuth

[alt_names]
DNS.1 = redis.internal
DNS.2 = redis
IP.1 = 10.0.1.100
IP.2 = 127.0.0.1
EOF

# 生成服务器证书
openssl req -new -key redis.key -out redis.csr -config redis.cnf
openssl x509 -req -sha512 -days 3650 \
    -extfile redis.cnf \
    -extensions v3_req \
    -CA ca.crt -CAkey ca.key -CAcreateserial \
    -in redis.csr \
    -out redis.crt

# 生成客户端证书
openssl genrsa -out client.key 4096
openssl req -new -key client.key -out client.csr \
    -subj "/C=CN/ST=Beijing/L=Beijing/O=Company/OU=IT/CN=Redis Client"

openssl x509 -req -sha512 -days 3650 \
    -CA ca.crt -CAkey ca.key -CAcreateserial \
    -in client.csr \
    -out client.crt

# 合并客户端证书和密钥（用于某些客户端）
cat client.crt client.key > client.pem

# 设置权限
chmod 600 *.key
chmod 644 *.crt *.pem
```

## 5. 生产环境安全清单

### 5.1 最小权限原则

遵循最小权限原则，只授予用户和进程完成任务所需的最小权限。

**用户权限设计矩阵：**

| 用户角色 | 允许的命令 | 允许的键模式 | 用途 |
|---------|-----------|-------------|------|
| 应用读写 | +@read +@write | ~app:* | 应用程序数据访问 |
| 应用只读 | +@read | ~* | 读副本访问 |
| 监控 | +@read +@fast +ping +info | ~* | 监控和健康检查 |
| 管理员 | +@all | ~* | 完整管理权限 |
| 备份 | +@read +save +bgsave | ~* | 数据备份 |
| 清理 | +@write +del +flushdb | ~cache:* | 缓存清理 |

**示例配置：**

```sh
# redis.conf - 创建最小权限用户

# 应用主用户 - 读写应用数据
ACL SETUSER app_master on >app_master_pass ~app:* +@read +@write -@dangerous -flushdb -flushall -keys -config -debug

# 应用只读用户 - 用于报表和分析
ACL SETUSER app_readonly on >app_readonly_pass ~* +@read -@write +@fast +info +cluster

# 监控用户 - 用于 Prometheus 等监控系统
ACL SETUSER monitor on >monitor_pass ~* -@write +ping +info +slowlog +command +client

# 备份用户 - 用于备份脚本
ACL SETUSER backup on >backup_pass ~* -@write +@read +save +bgsave +lastsave +info +config

# 缓存清理用户 - 用于定时清理任务
ACL SETUSER cache_cleaner on >cleaner_pass ~cache:* -@read +@write +del +flushdb +@dangerous
```

**审计脚本示例：**

```sh
#!/bin/bash
# redis_audit.sh - Redis 安全审计脚本

REDIS_HOST="localhost"
REDIS_PORT="6379"
REPORT_FILE="/var/log/redis/audit_$(date +%Y%m%d_%H%M%S).log"

echo "=== Redis 安全审计报告 ===" > ${REPORT_FILE}
echo "审计时间: $(date)" >> ${REPORT_FILE}
echo "" >> ${REPORT_FILE}

# 检查用户配置
echo "--- 用户配置 ---" >> ${REPORT_FILE}
redis-cli -h ${REDIS_HOST} -p ${REDIS_PORT} ACL LIST >> ${REPORT_FILE}
echo "" >> ${REPORT_FILE}

# 检查密码配置
echo "--- 密码配置 ---" >> ${REPORT_FILE}
password=$(redis-cli -h ${REDIS_HOST} -p ${REDIS_PORT} CONFIG GET requirepass | tail -1)
if [ -z "$password" ] || [ "$password" == "" ]; then
    echo "[警告] Redis 未设置密码!" >> ${REPORT_FILE}
else
    echo "[正常] Redis 已设置密码" >> ${REPORT_FILE}
fi
echo "" >> ${REPORT_FILE}

# 检查保护模式
echo "--- 保护模式 ---" >> ${REPORT_FILE}
redis-cli -h ${REDIS_HOST} -p ${REDIS_PORT} CONFIG GET protected-mode >> ${REPORT_FILE}
echo "" >> ${REPORT_FILE}

# 检查 bind 配置
echo "--- 绑定地址 ---" >> ${REPORT_FILE}
redis-cli -h ${REDIS_HOST} -p ${REDIS_PORT} CONFIG GET bind >> ${REPORT_FILE}
echo "" >> ${REPORT_FILE}

# 检查危险命令
echo "--- 危险命令状态 ---" >> ${REPORT_FILE}
redis-cli -h ${REDIS_HOST} -p ${REDIS_PORT} CONFIG GET rename-command >> ${REPORT_FILE}
echo "" >> ${REPORT_FILE}

# 检查连接
echo "--- 活动连接 ---" >> ${REPORT_FILE}
redis-cli -h ${REDIS_HOST} -p ${REDIS_PORT} CLIENT LIST >> ${REPORT_FILE}
echo "" >> ${REPORT_FILE}

# 检查慢查询
echo "--- 最近 10 条慢查询 ---" >> ${REPORT_FILE}
redis-cli -h ${REDIS_HOST} -p ${REDIS_PORT} SLOWLOG GET 10 >> ${REPORT_FILE}
echo "" >> ${REPORT_FILE}

# 检查 ACL 日志
echo "--- ACL 认证日志 ---" >> ${REPORT_FILE}
redis-cli -h ${REDIS_HOST} -p ${REDIS_PORT} ACL LOG GET 20 >> ${REPORT_FILE}

echo "审计完成，报告已保存到: ${REPORT_FILE}"
```

1. **ACL 访问控制**：Redis 6.0+ 提供的细粒度权限控制，支持命令级别和键模式的权限管理

- 生产环境必须启用 ACL 和密码认证
- 危险命令必须重命名或禁用
- 网络访问必须通过防火墙限制
- TLS 加密是生产环境的标准配置
- 定期进行安全审计和日志分析
