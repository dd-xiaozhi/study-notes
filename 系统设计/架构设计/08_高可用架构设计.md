# 第8章 高可用架构设计

## 8.1 高可用架构概述

高可用性（High Availability，HA）是指系统在期望的性能水平下持续运行的能力，通常通过减少停机时间来衡量。在现代分布式系统中，高可用架构是确保业务连续性的核心基础设施。

### 8.1.1 为什么需要高可用架构

在互联网应用中，任何非计划内的服务中断都可能造成严重的业务损失：

- **电商场景**：一次持续10分钟的平台故障可能导致数百万的交易损失
- **金融系统**：服务不可用可能引发监管合规问题和客户信任危机
- **即时通讯**：可用性问题直接导致用户流失

## 8.2 衡量指标

### 8.2.1 可用性（Availability）

可用性是最直观的高可用衡量指标，通常用百分比表示：

```
可用性 = 系统正常工作时间 / (系统正常工作时间 + 停机时间) × 100%
```

常见的可用性等级：

| 可用性等级 | 停机时间/年 | 停机时间/月 | 停机时间/周 |
|-----------|------------|-------------|-------------|
| 99%       | 3.65天     | 7.3小时     | 1.68小时    |
| 99.5%     | 1.83天     | 3.65小时    | 50.4分钟    |
| 99.9%     | 8.76小时   | 43.8分钟    | 10.1分钟    |
| 99.99%    | 52.6分钟   | 4.38分钟    | 1.01分钟    |
| 99.999%   | 5.26分钟   | 26.3秒      | 6.05秒      |

### 8.2.2 MTBF（Mean Time Between Failures）

**平均故障间隔时间**，衡量系统两次故障之间的平均正常运行时间。

```
MTBF = 总运行时间 / 故障次数
```

**示例计算**：

```python
# 假设系统在一年内运行了365天，其中发生了2次故障
total_uptime_hours = 365 * 24 - (2 * 4)  # 减去2次故障的4小时停机时间
failure_count = 2

mtbf_hours = total_uptime_hours / failure_count
mtbf_days = mtbf_hours / 24

print(f"MTBF: {mtbf_hours} 小时 ≈ {mtbf_days:.1f} 天")
# 输出: MTBF: 4372 小时 ≈ 182.2 天
```

### 8.2.3 MTTR（Mean Time To Repair）

**平均修复时间**，衡量系统从故障状态恢复到正常运行所需的平均时间。

```
MTTR = 总修复时间 / 修复次数
```


**公式推导**：

```
可用性 = MTBF / (MTBF + MTTR)
```

这意味着要提高可用性，我们需要：
- **提高 MTBF**：增加系统可靠性，减少故障发生
- **降低 MTTR**：快速检测故障、快速恢复服务

```java
public interface LoadBalancer {

}
```

```java
public class RoundRobinLoadBalancer implements LoadBalancer {
    private final AtomicInteger index = new AtomicInteger(0);

    @Override
    public String select(List<String> servers) {
        if (servers == null || servers.isEmpty()) {
            throw new IllegalArgumentException("服务器列表不能为空");
        }
        int pos = Math.abs(index.getAndIncrement() % servers.size());
        return servers.get(pos);
    }
}
```

```java
public class WeightedRoundRobinLoadBalancer implements LoadBalancer {
    private final Map<String, Integer> serverWeights;
    private final AtomicInteger currentIndex = new AtomicInteger(-1);
    private final AtomicInteger currentWeight = new AtomicInteger(0);

    public WeightedRoundRobinLoadBalancer(Map<String, Integer> serverWeights) {
        this.serverWeights = serverWeights;
    }

    @Override
    public String select(List<String> servers) {
        int totalWeight = servers.stream()
                .mapToInt(s -> serverWeights.getOrDefault(s, 1))
                .sum();

        while (true) {
            int idx = (currentIndex.get() + 1) % servers.size();
            int weight = currentWeight.get();

            if (idx == 0) {
                weight = currentWeight.get() - 1;
                if (weight <= 0) {
                    weight = totalWeight;
                }
                currentWeight.set(weight);
            }

            currentIndex.set(idx);
            String server = servers.get(idx);
            int serverWeight = serverWeights.getOrDefault(server, 1);

            if (serverWeight >= weight) {
                return server;
            }
        }
    }
}
```

#### Etcd 高可用选主

```go
// Go 语言 etcd选主实现
package main

import (
    "context"
    "fmt"
    "log"
    "time"

    "github.com/coreos/etcd/clientv3"
    "github.com/coreos/etcd/clientv3/concurrency"
)

type EtcdLeaderElection struct {
    client *clientv3.Client
    session *concurrency.Session
    election *concurrency.Election
}

func NewEtcdLeaderElection(endpoints []string, prefix string) (*EtcdLeaderElection, error) {
    client, err := clientv3.New(clientv3.Config{
        Endpoints:   endpoints,
        DialTimeout: 5 * time.Second,
    })
    if err != nil {
        return nil, err
    }

    session, err := concurrency.NewSession(client)
    if err != nil {
        return nil, err
    }

    election := concurrency.NewElection(session, prefix)

    return &EtcdLeaderElection{
        client:   client,
        session:  session,
        election: election,
    }, nil
}

// 参与竞选
func (e *EtcdLeaderElection) Campaign(ctx context.Context, leaderValue string) error {
    return e.election.Campaign(ctx, leaderValue)
}

// 获取当前leader
func (e *EtcdLeaderElection) Observe(ctx context.Context) (<-chan string, error) {
    ch := make(chan string, 1)

    go func() {
        for resp := range e.election.Chan(ctx) {
            if len(resp.Kvs) > 0 {
                select {
                case ch <- string(resp.Kvs[0].Value):
                default:
                }
            }
        }
    }()

    return ch, nil
}

// 释放leader权限
func (e *EtcdLeaderElection) Resign(ctx context.Context) error {
    return e.election.Resign(ctx)
}

func main() {
    endpoints := []string{"http://localhost:2379"}
    election, err := NewEtcdLeaderElection(endpoints, "/myapp/leader")
    if err != nil {
        log.Fatal(err)
    }

    ctx := context.Background()

    // 参与竞选
    err = election.Campaign(ctx, "server-1")
    if err != nil {
        log.Fatal(err)
    }

    // 观察leader变化
    ch, err := election.Observe(ctx)
    if err != nil {
        log.Fatal(err)
    }

    select {
    case leader := <-ch:
        fmt.Printf("当前Leader: %s\n", leader)
    case <-time.After(10 * time.Second):
        fmt.Println("获取Leader超时")
    }

    // 释放权限
    defer election.Resign(ctx)
}
```

## 8.4 容错设计

容错设计确保系统在部分组件故障时仍能继续提供服务，通过预防、检测和恢复机制最大化系统可用性。

### 8.4.1 限流（Rate Limiting）

限流保护系统在流量突增时不被冲垮，通过限制单位时间内的请求数量来保护下游服务。

#### 限流算法

**令牌桶算法实现**：

```java
public class TokenBucketRateLimiter {
    private final long capacity;           // 桶容量
    private final long refillRate;        // 每秒补充的令牌数
    private volatile long tokens;         // 当前令牌数
    private volatile long lastRefillTime; // 上次补充时间

    public TokenBucketRateLimiter(long capacity, long refillRate) {
        this.capacity = capacity;
        this.refillRate = refillRate;
        this.tokens = capacity;
        this.lastRefillTime = System.nanoTime();
    }

    public synchronized boolean tryAcquire() {
        refill();
        if (tokens > 0) {
            tokens--;
            return true;
        }
        return false;
    }

    public synchronized boolean tryAcquire(int permits) {
        refill();
        if (tokens >= permits) {
            tokens -= permits;
            return true;
        }
        return false;
    }

    private void refill() {
        long now = System.nanoTime();
        long elapsed = now - lastRefillTime;

        // 计算应该补充的令牌数
        long newTokens = (elapsed * refillRate) / 1_000_000_000L;
        if (newTokens > 0) {
            tokens = Math.min(capacity, tokens + newTokens);
            lastRefillTime = now;
        }
    }

    public long getAvailableTokens() {
        return tokens;
    }
}
```

```java
    private final int maxRequests;
    private final Deque<Long> timestamps;

    public SlidingWindowRateLimiter(int windowSizeInSeconds, int maxRequests) {
        this.windowSizeInSeconds = windowSizeInSeconds;
        this.maxRequests = maxRequests;
        this.timestamps = new ConcurrentLinkedDeque<>();
    }

    public synchronized boolean tryAcquire() {
        long now = System.currentTimeMillis();
        long windowStart = now - windowSizeInSeconds * 1000L;

        // 清理窗口外的请求记录
        while (!timestamps.isEmpty() && timestamps.peekFirst() < windowStart) {
            timestamps.pollFirst();
        }

        if (timestamps.size() < maxRequests) {
            timestamps.offerLast(now);
            return true;
        }
        return false;
    }

    public int getCurrentRequestCount() {
        long now = System.currentTimeMillis();
        long windowStart = now - windowSizeInSeconds * 1000L;

        return (int) timestamps.stream()
                .filter(t -> t >= windowStart)
                .count();
    }
}
```

### 8.4.2 熔断（Circuit Breaker）

熔断器模式在检测到下游服务持续故障时，快速失败并阻止请求继续发送到故障服务。

#### 熔断器状态机

```mermaid
stateDiagram-v2
    [*] --> 关闭: 初始化
    关闭 --> 打开: 故障率超过阈值
    打开 --> 半开: 熔断超时
    半开 --> 关闭: 请求成功
    半开 --> 打开: 请求失败
    打开 --> [*]: 重置

    note right of 关闭
        正常处理请求
        统计失败率
    end note

    note right of 打开
        直接返回降级响应
        不发送请求到下游
    end note

    note right of 半开
        允许单个请求通过
        测试下游是否恢复
    end note
```

#### 熔断器实现

```java
public class CircuitBreaker {

    public enum State {
        CLOSED,    // 关闭状态：正常处理请求
        OPEN,      // 打开状态：快速失败
        HALF_OPEN  // 半开状态：尝试恢复
    }

    private final String name;
    private final int failureThreshold;     // 触发熔断的失败次数
    private final long recoveryTimeout;    // 熔断恢复超时
    private final long halfOpenMaxAttempts;// 半开状态允许的尝试次数

    private volatile State state = State.CLOSED;
    private volatile int failureCount = 0;
    private volatile int successCount = 0;
    private volatile long lastFailureTime = 0;
    private volatile int halfOpenAttempts = 0;

    private final AtomicLong totalRequests = new AtomicLong(0);
    private final AtomicLong failedRequests = new AtomicLong(0);

    public CircuitBreaker(String name, int failureThreshold,
                          long recoveryTimeout, int halfOpenMaxAttempts) {
        this.name = name;
        this.failureThreshold = failureThreshold;
        this.recoveryTimeout = recoveryTimeout;
        this.halfOpenMaxAttempts = halfOpenMaxAttempts;
    }

    public <T> T execute(Callable<T> action, Callable<T> fallback) throws Exception {
        if (!allowRequest()) {
            return fallback.call();
        }

        totalRequests.incrementAndGet();

        try {
            T result = action.call();
            recordSuccess();
            return result;
        } catch (Exception e) {
            recordFailure();
            return fallback.call();
        }
    }

    private boolean allowRequest() {
        switch (state) {
            case CLOSED:
                return true;

            case OPEN:
                // 检查是否应该转换到半开状态
                if (System.currentTimeMillis() - lastFailureTime >= recoveryTimeout) {
                    transitionToHalfOpen();
                    return true;
                }
                return false;

            case HALF_OPEN:
                // 限制半开状态的尝试次数
                return halfOpenAttempts < halfOpenMaxAttempts;

            default:
                return false;
        }
    }

    private void recordSuccess() {
        switch (state) {
            case CLOSED:
                failureCount = 0;
                break;
            case HALF_OPEN:
                successCount++;
                if (successCount >= halfOpenMaxAttempts) {
                    transitionToClosed();
                }
                break;
        }
    }

    private void recordFailure() {
        lastFailureTime = System.currentTimeMillis();
        failedRequests.incrementAndGet();
        failureCount++;

        switch (state) {
            case CLOSED:
                if (failureCount >= failureThreshold) {
                    transitionToOpen();
                }
                break;
            case HALF_OPEN:
                transitionToOpen();
                break;
        }
    }

    private void transitionToOpen() {
        state = State.OPEN;
        System.out.println(name + " 转换到 OPEN 状态");
    }

    private void transitionToHalfOpen() {
        state = State.HALF_OPEN;
        halfOpenAttempts = 1;
        successCount = 0;
        System.out.println(name + " 转换到 HALF_OPEN 状态");
    }

    private void transitionToClosed() {
        state = State.CLOSED;
        failureCount = 0;
        successCount = 0;
        halfOpenAttempts = 0;
        System.out.println(name + " 转换到 CLOSED 状态");
    }

    public State getState() {
        return state;
    }

    public double getFailureRate() {
        long total = totalRequests.get();
        if (total == 0) return 0;
        return (double) failedRequests.get() / total;
    }
}
```

```java
    T getFallback();
    boolean isDegraded();
}

public class ProductService implements DegradableService<ProductDetail> {

    private final ProductDetailService productDetailService;
    private final ReviewService reviewService;
    private final RecommendationService recommendationService;

    // 降级标志
    private volatile boolean detailDegraded = false;
    private volatile boolean reviewDegraded = false;
    private volatile boolean recommendationDegraded = false;

    public ProductDetail getProductDetail(Long productId) {
        ProductDetail detail = new ProductDetail();
        detail.setProductId(productId);

        // 核心数据必须获取
        try {
            detail.setBasicInfo(productDetailService.getBasicInfo(productId));
        } catch (Exception e) {
            throw new ServiceException("商品信息获取失败");

        if (!reviewDegraded) {
            try {
                detail.setReviews(reviewService.getReviews(productId));
            } catch (Exception e) {
                reviewDegraded = true;
                detail.setReviews(getDefaultReviews());
            }
        }

        if (!recommendationDegraded) {
            try {
                detail.setRecommendations(recommendationService.getRecommendations(productId));
            } catch (Exception e) {
                recommendationDegraded = true;
                detail.setRecommendations(Collections.emptyList());
            }
        }

        return detail;
    }

    private List<Review> getDefaultReviews() {
        return Collections.singletonList(
            new Review("系统繁忙，评价暂不可用", LocalDateTime.now())
        );
    }
}
```

### 8.4.4 回退（Fallback）

回退是在服务调用失败时，返回一个预设的默认值或缓存数据，保证业务流程继续执行。

#### Fallback 设计模式

```java
public class FallbackFactory {

    // 静态配置的回退值
    private static final Map<String, Object> STATIC_FALLBACKS = new HashMap<>();

    // 缓存的回退值
    private final Cache<String, Object> fallbackCache;

    static {
        STATIC_FALLBACKS.put("user.name", "Guest");
        STATIC_FALLBACKS.put("product.stock", "100");
        STATIC_FALLBACKS.put("order.maxItems", "50");
    }

    public <T> T getFallback(String key, Class<T> type, Supplier<T> primarySupplier) {
        try {
            T result = primarySupplier.get();
            // 成功时更新缓存
            if (result != null) {
                fallbackCache.put(key, result);
            }
            return result;
        } catch (Exception e) {
            // 失败时尝试从缓存获取
            T cached = getFromCache(key, type);
            if (cached != null) {
                return cached;
            }

            // 最后尝试静态配置
            return getStaticFallback(key, type);
        }
    }

    @SuppressWarnings("unchecked")
    private <T> T getFromCache(String key, Class<T> type) {
        Object value = fallbackCache.getIfPresent(key);
        if (value != null && type.isInstance(value)) {
            return (T) value;
        }
        return null;
    }

    @SuppressWarnings("unchecked")
    private <T> T getStaticFallback(String key, Class<T> type) {
        Object value = STATIC_FALLBACKS.get(key);
        if (value != null && type.isInstance(value)) {
            return (T) value;
        }
        // 返回类型默认值
        return getDefaultValue(type);
    }

    private <T> T getDefaultValue(Class<T> type) {
        if (type == String.class) return (T) "";
        if (type == Integer.class) return (T) Integer.valueOf(0);
        if (type == Long.class) return (T) Long.valueOf(0L);
        if (type == Boolean.class) return (T) Boolean.FALSE;
        if (type == List.class) return (T) Collections.emptyList();
        return null;
    }
}
```

```java
public class FallbackDecorator<T> implements RemoteService<T> {

    private final RemoteService<T> primary;
    private final RemoteService<T> fallback;

        this.primary = primary;
        this.fallback = fallback;
    }

    @Override
    public T call() throws Exception {
        try {
            return primary.call();
        } catch (Exception e) {
            System.out.println("主服务调用失败，触发fallback: " + e.getMessage());
            return fallback.call();
        }
    }

    public static void main(String[] args) throws Exception {
        RemoteService<String> primary = () -> {
            throw new RuntimeException("服务不可用");
        };

        RemoteService<String> fallback = () -> "Fallback Response";

        FallbackDecorator<String> decorator = new FallbackDecorator<>(primary, fallback);
        String result = decorator.call();
        System.out.println(result); // 输出: Fallback Response
    }
```

**Java Redis Sentinel 客户端**：

```java
import org.apache.commons.pool2.impl.GenericObjectPoolConfig;
import redis.clients.jedis.JedisPooled;
import redis.clients.jedis.Jedis;
import redis.clients.jedis.exceptions.JedisConnectionException;
import redis.clients.jedis.exceptions.JedisException;

public class RedisHighAvailabilityClient {

    private JedisPooled jedisPool;
    private final String masterName;
    private volatile String currentMaster;

    public RedisHighAvailabilityClient(String masterName, String... sentinelNodes) {
        this.masterName = masterName;

        String sentinelConfig = Arrays.stream(sentinelNodes)
            .map(node -> node.split(":")[0] + ":" + node.split(":")[1])
            .collect(Collectors.joining(","));

        GenericObjectPoolConfig poolConfig = new GenericObjectPoolConfig();
        poolConfig.setMaxTotal(100);
        poolConfig.setMaxIdle(50);
        poolConfig.setMinIdle(10);
        poolConfig.setTestOnBorrow(true);
        poolConfig.setTestOnReturn(true);
        poolConfig.setTestWhileIdle(true);

        // 方式1：使用JedisSentinelPool
        useJedisSentinelPool(sentinelNodes, poolConfig);
    }

    private void useJedisSentinelPool(String[] sentinelNodes, GenericObjectPoolConfig config) {
        Set<String> sentinelSet = new HashSet<>(Arrays.asList(sentinelNodes));

        JedisSentinelPool pool = new JedisSentinelPool(
            masterName,
            sentinelSet,
            config,
            3000,    // connectionTimeout
            3000,    // soTimeout
            "password123"
        );

        this.jedisPool = new JedisPooled(pool.getResource());
        this.currentMaster = pool.getCurrentHostMaster().getHost();
    }

    public String get(String key) {
        return executeWithRetry(() -> jedisPool.get(key));
    }

    public void set(String key, String value) {
        executeWithRetry(() -> {
            jedisPool.set(key, value);
            return null;
        });
    }

    public <T> T executeWithRetry(RedisOperation<T> operation) {
        int maxRetries = 3;
        int retryCount = 0;

        while (retryCount < maxRetries) {
            try {
                return operation.execute();
            } catch (JedisConnectionException e) {
                retryCount++;
                if (retryCount >= maxRetries) {
                    throw new JedisException("Redis operation failed after " + maxRetries + " retries", e);
                }
                // 等待后重试
                try {
                    Thread.sleep(100 * retryCount);
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    throw new JedisException("Operation interrupted", ie);
                }
            }
        }
        throw new JedisException("Should not reach here");
    }

    @FunctionalInterface
    interface RedisOperation<T> {
        T execute();
    }
}
```

**Redis Cluster 方案**：

```java
import redis.clients.jedis.HostAndPort;
import redis.clients.jedis.JedisCluster;
import redis.clients.jedis.exceptions.JedisClusterException;

public class RedisClusterClient {

    private final JedisCluster cluster;

    public RedisClusterClient(Set<HostAndPort> nodes) {
        GenericObjectPoolConfig poolConfig = new GenericObjectPoolConfig();
        poolConfig.setMaxTotal(100);
        poolConfig.setMaxIdle(50);

        this.cluster = new JedisCluster(
            nodes,
            3000,      // connectionTimeout
            3000,      // soTimeout
            5,         // maxRedirections
            "password123",
            poolConfig
        );
    }

    public String get(String key) {
        try {
            return cluster.get(key);
        } catch (JedisClusterException e) {
            // 处理集群特定异常
            throw new RuntimeException("Redis cluster operation failed", e);
        }
    }

    public void set(String key, String value) {
        try {
            cluster.set(key, value);
        } catch (JedisClusterException e) {
            throw new RuntimeException("Redis cluster operation failed", e);
        }
    }

    // 自动重定向处理
    public void setWithRedirect(String key, String value) {
        int maxRetries = 5;
        for (int i = 0; i < maxRetries; i++) {
            try {
                cluster.set(key, value);
                return;
            } catch (JedisClusterException e) {
                if (i == maxRetries - 1) {
                    throw e;
                }
                // MOVED 重定向会自动处理
            }
        }
    }

    public void close() {
        cluster.close();
    }
}
```

#### 1. 消除单点故障（Single Point of Failure）

**原则**：系统中不应存在任何单点组件，所有关键组件都应有冗余备份。

#### 2. 冗余设计（Redundancy）

**原则**：通过复制和冗余确保系统具有处理单点故障的能力。

| 冗余级别 | 说明 | 成本 | 适用场景 |
|---------|------|------|---------|
| 1+1冗余 | 两套完全独立系统 | 高 | 核心业务 |
| N+1冗余 | N套主用 + 1套备用 | 中高 | 重要服务 |
| N+M冗余 | N套主用 + M套备用 | 中 | 规模服务 |
| N+0冗余 | N套负载分担 | 中低 | 高吞吐场景 |

#### 3. 故障隔离（Failure Isolation）

**原则**：采用舱壁模式（Bulkhead Pattern）隔离故障，防止故障扩散。

```java
// 舱壁模式实现
public class BulkheadService {

    // 不同依赖使用独立的线程池
    private final ExecutorService userServicePool =
        Executors.newFixedThreadPool(10);

    private final ExecutorService orderServicePool =
        Executors.newFixedThreadPool(20);

    private final ExecutorService paymentServicePool =
        Executors.newFixedThreadPool(5);

    public CompletableFuture<User> getUser(Long userId) {
        return CompletableFuture.supplyAsync(
            () -> userService.call(userId),
            userServicePool
        );
    }

    public CompletableFuture<Order> createOrder(Order order) {
        return CompletableFuture.supplyAsync(
            () -> orderService.create(order),
            orderServicePool
        );
    }

    public CompletableFuture<Payment> processPayment(Payment payment) {
        return CompletableFuture.supplyAsync(
            () -> paymentService.process(payment),
            paymentServicePool
        );
    }
}
```

#### 5. 监控告警（Monitoring）

**原则**：建立完善的监控体系，实现故障的早发现、早处理。

```java
// 健康检查接口实现
@RestController
@RequestMapping("/actuator")
public class HealthIndicator {

    @Autowired
    private DatabaseService databaseService;

    @Autowired
    private RedisService redisService;

    @Autowired
    private ExternalService externalService;

    @GetMapping("/health")
    public Health health() {
        Health.Builder builder = new Health.Builder();

        boolean allHealthy = true;

        // 数据库健康检查
        if (!checkDatabase()) {
            builder.down().withDetail("database", "unavailable");
            allHealthy = false;
        }

        // 缓存健康检查
        if (!checkRedis()) {
            builder.down().withDetail("redis", "unavailable");
            allHealthy = false;
        }

        // 外部依赖健康检查
        if (!checkExternal()) {
            builder.withDetail("external", "degraded");
        }

        if (allHealthy) {
            builder.up();
        }

        return builder.build();
    }

    private boolean checkDatabase() {
        try {
            return databaseService.healthCheck();
        } catch (Exception e) {
            return false;
        }
    }

    private boolean checkRedis() {
        try {
            return redisService.healthCheck();
        } catch (Exception e) {
            return false;
        }
    }

    private boolean checkExternal() {
        try {
            return externalService.healthCheck();
        } catch (Exception e) {
            return false;
        }
    }
}
```

#### 6. 优雅降级（Graceful Degradation）

**原则**：当系统无法处理全部请求时，有计划地关闭非核心功能，保证核心业务可用。

```java
public class GracefulDegradationManager {

    private final Map<String, FeatureFlag> features = new ConcurrentHashMap<>();

    public GracefulDegradationManager() {
        // 初始化功能开关
        features.put("recommendation", new FeatureFlag(true, Priority.HIGH));
        features.put("comment", new FeatureFlag(true, Priority.MEDIUM));
        features.put("ad", new FeatureFlag(true, Priority.LOW));
        features.put("analytics", new FeatureFlag(false, Priority.LOW));
    }

    public boolean isFeatureEnabled(String featureName) {
        FeatureFlag flag = features.get(featureName);
        return flag != null && flag.enabled;
    }

    public void setFeatureEnabled(String featureName, boolean enabled) {
        FeatureFlag flag = features.get(featureName);
        if (flag != null) {
            flag.enabled = enabled;
        }
    }

    public void degradeToPriority(Priority maxPriority) {
        features.values().forEach(flag -> {
            if (flag.priority.getValue() > maxPriority.getValue()) {
                flag.enabled = false;
            }
        });
    }

    public void restoreAll() {
        features.values().forEach(flag -> flag.enabled = true);
    }

    public static class FeatureFlag {
        volatile boolean enabled;
        Priority priority;

        public FeatureFlag(boolean enabled, Priority priority) {
            this.enabled = enabled;
            this.priority = priority;
        }
    }

    public enum Priority {
        CRITICAL(1),
        HIGH(2),
        MEDIUM(3),
        LOW(4);

        private final int value;

        Priority(int value) {
            this.value = value;
        }

        public int getValue() {
            return value;
        }
    }
}
```

## 8.7 本章小结

本章系统介绍了高可用架构设计的核心知识：

1. **高可用指标**：通过可用性、MTBF、MTTR三个核心指标量化系统可靠性
2. **高可用模式**：负载均衡、集群、主备切换、异地多活构成完整的高可用体系
3. **容错设计**：限流、熔断、降级、回退形成立体的容错防护网
4. **工程实践**：微服务高可用和数据库高可用方案提供了落地参考
5. **设计原则**：消除单点、冗余设计、故障隔离、快速恢复、监控告警、优雅降级

高可用架构不是一次性设计完成的，需要持续迭代和优化。通过监控发现问题，通过容错保护系统，通过自动化提升效率，最终实现业务的高可用目标。
