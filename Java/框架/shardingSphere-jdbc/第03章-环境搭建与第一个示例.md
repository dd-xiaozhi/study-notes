# 第3章 环境搭建与第一个示例

本章将详细介绍如何搭建 ShardingSphere-JDBC 开发环境，并创建一个完整可运行的示例程序。通过本章的学习，你将掌握开发环境的配置、分片规则的创建、以及如何验证分片是否生效。

## 3.1 环境要求

在开始搭建 ShardingSphere-JDBC 开发环境之前，需要确保你的开发环境满足以下最低要求。

### 3.1.1 JDK 版本要求

ShardingSphere-JDBC 5.x 版本需要 JDK 8 或更高版本。建议使用 JDK 11 或 JDK 17 以获得更好的性能和安全性支持。

| ShardingSphere 版本 | JDK 版本要求 |
|---------------------|--------------|
| 5.0.x | JDK 8 及以上 |
| 5.1.x | JDK 8 及以上 |
| 5.2.x | JDK 8 及以上（推荐 JDK 11+）|
| 5.3.x | JDK 8 及以上（推荐 JDK 11+）|
| 5.4.x | JDK 8 及以上（推荐 JDK 17）|

**验证 JDK 版本：**

```bash
java -version
javac -version
```

输出类似如下内容表示配置正确：

```
java version "1.8.0_321"
Java(TM) SE Runtime Environment (build 1.8.0_321-b12)
Java HotSpot(TM) 64-Bit Server VM (build 25.321-b12, mixed mode)
```

### 3.1.2 MySQL 版本要求

ShardingSphere-JDBC 支持 MySQL 5.7 和 MySQL 8.0 版本。建议使用 MySQL 8.0 以获得更好的性能和新特性支持。

| MySQL 版本 | 支持情况 | 推荐程度 |
|------------|----------|----------|
| MySQL 5.6 | 兼容 | 不推荐 |
| MySQL 5.7 | 完全支持 | 推荐 |
| MySQL 8.0 | 完全支持 | 强烈推荐 |

**验证 MySQL 版本：**

```bash
mysql --version
```

### 3.1.3 Maven 版本要求

ShardingSphere-JDBC 基于 Maven 进行依赖管理和构建。建议使用 Maven 3.6.x 或更高版本。

| Maven 版本 | 支持情况 | 推荐程度 |

| Maven 3.6.x | 完全支持 | 强烈推荐 |

## 3.2 Maven 依赖配置

ShardingSphere-JDBC 采用模块化设计，可以根据实际需求引入相应的模块。以下是常用的依赖配置。

### 3.2.1 核心依赖

对于大多数分片场景，只需要引入 `shardingsphere-jdbc-core` 核心模块即可。

**使用 Maven 中央仓库（推荐稳定版本 5.4.1）：**

```xml
<dependency>
    <groupId>org.apache.shardingsphere</groupId>
    <artifactId>shardingsphere-jdbc-core</artifactId>
    <version>5.4.1</version>
</dependency>
```

**如果使用 Spring Boot，可以使用 Spring Boot Starter：**

```xml
<dependency>
    <groupId>org.apache.shardingsphere</groupId>
    <artifactId>shardingsphere-jdbc-core-spring-boot-starter</artifactId>
    <version>5.4.1</version>
</dependency>
```

### 3.2.2 各模块依赖坐标

以下表格列出了 ShardingSphere-JDBC 的主要模块及其依赖坐标，可以根据业务需求选择性地引入。

| MySQL 驱动 | mysql-connector-java | 连接 MySQL 数据库 |

### 3.2.3 依赖版本说明

在引入 ShardingSphere 依赖时，需要注意以下几个版本的匹配问题：

1. **ShardingSphere 版本与 JDK 版本匹配**
   - ShardingSphere 5.4.x 支持 JDK 8/11/17
   - ShardingSphere 5.3.x 支持 JDK 8/11

2. **MySQL 驱动版本与 MySQL 服务器版本匹配**
   - MySQL 8.0 服务器需要使用 8.0.x 版本的驱动
   - MySQL 5.7 服务器可以使用 5.1.x 或 8.0.x 版本的驱动

3. **Spring Boot 版本与 ShardingSphere 版本匹配**
   - Spring Boot 2.7.x 适配 ShardingSphere 5.4.x
   - Spring Boot 2.5.x ~ 2.6.x 适配 ShardingSphere 5.3.x

## 3.3 搭建 MySQL 数据库环境

为了测试分片功能，需要搭建 MySQL 数据库环境。本节介绍两种搭建方式：Docker Compose 自动化部署和手动安装。

### 3.3.1 使用 Docker Compose 搭建

Docker 是最推荐的数据库环境搭建方式，可以快速创建和销毁环境。

**前置条件：**

- 已安装 Docker Desktop（Windows/Mac）或 Docker Engine（Linux）
- Docker 版本 20.10.x 或更高

**创建 docker-compose.yml 文件：**

```yaml
version: '3.8'

services:
  mysql-node0:
    image: mysql:8.0
    container_name: mysql-node0
    environment:
      MYSQL_ROOT_PASSWORD: root123456
      MYSQL_ROOT_HOST: '%'
      TZ: Asia/Shanghai
    ports:
      - "3306:3306"
    volumes:
      - ./mysql/node0/data:/var/lib/mysql
      - ./mysql/node0/init:/docker-entrypoint-initdb.d
      - ./mysql/node0/conf:/etc/mysql/conf.d
    command:
      - --server-id=1
      - --default-authentication-plugin=mysql_native_password
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
    networks:
      - sharding-network

  mysql-node1:
    image: mysql:8.0
    container_name: mysql-node1
    environment:
      MYSQL_ROOT_PASSWORD: root123456
      MYSQL_ROOT_HOST: '%'
      TZ: Asia/Shanghai
    ports:
      - "3307:3306"
    volumes:
      - ./mysql/node1/data:/var/lib/mysql
      - ./mysql/node1/init:/docker-entrypoint-initdb.d
      - ./mysql/node1/conf:/etc/mysql/conf.d
    command:
      - --server-id=2
      - --default-authentication-plugin=mysql_native_password
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
    networks:
      - sharding-network

networks:
  sharding-network:
    driver: bridge
```

**创建 MySQL 配置文件（可选）：**

如果需要自定义 MySQL 配置，可以在 `mysql/node0/conf/my.cnf` 和 `mysql/node1/conf/my.cnf` 中添加配置：

```ini
[mysqld]
# 服务器 ID，唯一标识
server-id = 1

# 端口
port = 3306

# 字符集
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci

# 时区
default-time-zone = '+08:00'

# 最大连接数
max_connections = 200

# 允许其他容器访问
bind-address = 0.0.0.0
```

**启动 MySQL 集群：**

```bash
# 创建目录结构
mkdir -p mysql/node0/data mysql/node0/init mysql/node0/conf
mkdir -p mysql/node1/data mysql/node1/init mysql/node1/conf

# 启动所有 MySQL 容器
docker-compose up -d

# 查看容器状态
docker-compose ps
```

**验证 MySQL 连接：**

```bash
# 测试 node0 连接
mysql -h 127.0.0.1 -P 3306 -uroot -proot123456 -e "SELECT VERSION();"

# 测试 node1 连接
mysql -h 127.0.0.1 -P 3307 -uroot -proot123456 -e "SELECT VERSION();"
```

### 3.3.2 手动安装 MySQL

如果无法使用 Docker，可以手动安装 MySQL。

**Windows 系统安装步骤：**

1. 下载 MySQL 安装包
   - 访问 https://dev.mysql.com/downloads/mysql/
   - 下载 MySQL 8.0 Installer

2. 运行安装程序，选择"Developer Default"安装类型

3. 配置 root 密码为 `root123456`

4. 配置端口：
   - node0 使用 3306
   - node1 使用 3307

**Linux 系统安装步骤（Ubuntu）：**

```bash
# 安装 MySQL 服务器
sudo apt update
sudo apt install mysql-server

# 启动 MySQL 服务
sudo systemctl start mysql
sudo systemctl enable mysql

# 安全初始化
sudo mysql_secure_installation

# 登录 MySQL
sudo mysql -u root -p
```

**Linux 系统安装步骤（CentOS）：**

```bash
# 添加 MySQL Yum 源
sudo yum install -y https://dev.mysql.com/get/mysql80-community-release-el8-4.noarch.rpm

# 安装 MySQL 服务器
sudo yum install -y mysql-community-server

# 启动 MySQL 服务
sudo systemctl start mysqld
sudo systemctl enable mysqld

# 查看初始密码
sudo grep 'temporary password' /var/log/mysqld.log

# 登录并修改密码
mysql -u root -p
```

### 3.3.3 创建分片数据库和表

成功启动 MySQL 后，需要创建用于分片的数据库和表结构。

**连接 MySQL：**

```bash
# 使用 mysql 命令行连接
mysql -h 127.0.0.1 -P 3306 -uroot -proot123456
mysql -h 127.0.0.1 -P 3307 -uroot -proot123456
```

**在两个节点上分别创建数据库：**

```sql
-- 在 node0（端口 3306）上执行
CREATE DATABASE IF NOT EXISTS ds_0 DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 在 node1（端口 3307）上执行
CREATE DATABASE IF NOT EXISTS ds_1 DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

**或者使用一条命令创建两个数据库（在两个节点都执行）：**

```sql
CREATE DATABASE IF NOT EXISTS ds_0 DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE DATABASE IF NOT EXISTS ds_1 DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

**创建分片表结构：**

下面的 SQL 用于创建订单表`t_order`和订单详情表`t_order_item`，这两个表将按照 user_id 进行分片。

```sql
-- 创建 t_order 表
CREATE TABLE IF NOT EXISTS `t_order` (
    `order_id` BIGINT NOT NULL AUTO_INCREMENT,
    `user_id` BIGINT NOT NULL,
    `status` VARCHAR(50) NOT NULL DEFAULT 'PENDING',
    `amount` DECIMAL(10, 2) NOT NULL DEFAULT 0.00,
    `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`order_id`),
    INDEX `idx_user_id` (`user_id`),
    INDEX `idx_status` (`status`),
    INDEX `idx_create_time` (`create_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

-- 创建 t_order_item 表（关联表）
CREATE TABLE IF NOT EXISTS `t_order_item` (
    `item_id` BIGINT NOT NULL AUTO_INCREMENT,
    `order_id` BIGINT NOT NULL,
    `user_id` BIGINT NOT NULL,
    `product_name` VARCHAR(200) NOT NULL,
    `price` DECIMAL(10, 2) NOT NULL DEFAULT 0.00,
    `quantity` INT NOT NULL DEFAULT 1,
    PRIMARY KEY (`item_id`),
    INDEX `idx_order_id` (`order_id`),
    INDEX `idx_user_id` (`user_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

**在两个节点上都需要创建这些表：**可以在 node0 和 node1 上分别执行上述 SQL 语句。

## 3.4 YAML 配置文件详解

ShardingSphere-JDBC 支持两种配置方式：YAML 配置文件和 Java API 配置。本节详细介绍 YAML 配置文件的各种配置项。

### 3.4.1 配置文件基础结构

ShardingSphere-JDBC 的 YAML 配置文件通常命名为 `shardingsphere.yml`，其基础结构如下：

```yaml
# 数据源配置
dataSources:
  ds_0:
    dataSourceClassName: com.zaxxer.hikari.HikariDataSource
    driverClassName: com.mysql.cj.jdbc.Driver
    jdbcUrl: jdbc:mysql://127.0.0.1:3306/ds_0?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: root
    password: root123456
    poolProps:
      maximumPoolSize: 20
      minimumIdle: 5
      connectionTimeout: 30000
      idleTimeout: 600000
      maxLifetime: 1800000
  ds_1:
    dataSourceClassName: com.zaxxer.hikari.HikariDataSource
    driverClassName: com.mysql.cj.jdbc.Driver
    jdbcUrl: jdbc:mysql://127.0.0.1:3307/ds_1?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: root
    password: root123456
    poolProps:
      maximumPoolSize: 20
      minimumIdle: 5

# 规则配置
rules:
  - !SHARDING
    tables:
      # 分片表配置
    bindingTables:
      # 绑定表配置
    defaultDatabaseStrategy:
      # 默认库分片策略
    defaultTableStrategy:
      # 默认表分片策略
  - !READ_WRITE_SPLITTING
    # 读写分离配置
  - !ENCRYPT
    # 数据加密配置
```

### 3.4.2 数据源配置详解

数据源配置是 ShardingSphere-JDBC 的基础，定义了应用连接数据库的方式。

**HikariCP 数据源配置：**

```yaml
dataSources:
  ds_0:
    # 数据源类名，ShardingSphere 会根据此自动创建数据源
    dataSourceClassName: com.zaxxer.hikari.HikariDataSource
    
    # MySQL 驱动类名
    driverClassName: com.mysql.cj.jdbc.Driver
    
    # JDBC URL，注意数据库名需要与分片对应
    jdbcUrl: jdbc:mysql://127.0.0.1:3306/ds_0?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
    
    # 数据库用户名
    username: root
    
    # 数据库密码
    password: root123456
    
    # 连接池属性（可选）
    poolProps:
      # 最大连接数
      maximumPoolSize: 20
      # 最小空闲连接数
      minimumIdle: 5
      # 连接超时时间（毫秒）
      connectionTimeout: 30000
      # 空闲超时时间（毫秒）
      idleTimeout: 600000
      # 连接最大生命周期（毫秒）
      maxLifetime: 1800000
```

**Druid 数据源配置：**

```yaml
dataSources:
  ds_0:
    dataSourceClassName: com.alibaba.druid.pool.DruidDataSource
    driverClassName: com.mysql.cj.jdbc.Driver
    jdbcUrl: jdbc:mysql://127.0.0.1:3306/ds_0?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai
    username: root
    password: root123456
    poolProps:
      # Druid 特有配置
      initialSize: 5
      minIdle: 5
      maxActive: 20
      maxWait: 60000
      timeBetweenEvictionRunsMillis: 60000
      minEvictableIdleTimeMillis: 300000
      validationQuery: SELECT 1
      testWhileIdle: true
      testOnBorrow: false
      testOnReturn: false
```

### 3.4.3 分片规则配置详解

分片规则是 ShardingSphere-JDBC 的核心配置，定义了数据如何分布到各个数据节点。

**标准分片表配置：**

```yaml
rules:
  - !SHARDING
    tables:
      t_order:
        # 实际数据节点，格式为：数据源.表名
        actualDataNodes: ds_${0..1}.t_order
        
        # 分片策略
        tableStrategy:
          # 按照 user_id 进行分片
          standard:
            # 分片列
            shardingColumn: user_id
            # 分片算法名称
            shardingAlgorithmName: t_order_mod
        
        # 主键生成策略（可选）
        keyGenerateStrategy:
          column: order_id
          keyGeneratorName: snowflake
    
    # 绑定表配置，用于关联查询优化
    bindingTables:
      - t_order,t_order_item
    
    # 默认数据库分片策略
    defaultDatabaseStrategy:
      standard:
        shardingColumn: user_id
        shardingAlgorithmName: database_mod
    
    # 默认表分片策略
    defaultTableStrategy:
      standard:
        shardingColumn: user_id
        shardingAlgorithmName: table_mod
    
    # 分片算法定义
    shardingAlgorithms:
      # 取模分片算法
      t_order_mod:
        type: CLASS_BASED
        props:
          algorithmClassName: com.example.algorithm.ModShardingAlgorithm
          strategy: STANDARD
      # 哈希分片算法
      t_order_hash:
        type: INLINE
        props:
          algorithm-expression: ds_${user_id % 2}
      # 基于时间范围的分片算法
      t_order_range:
        type: CLASS_BASED
        props:
          algorithmClassName: com.example.algorithm.RangeShardingAlgorithm
    
    # 主键生成器定义
    keyGenerators:
      snowflake:
        type: SNOWFLAKE
        props:
          worker-id: 1
          max-vibration-offset: 3
```

### 3.4.4 分片算法配置

ShardingSphere-JDBC 内置了多种分片算法，同时也支持自定义算法。

**内置算法示例：**

```yaml
# 取模算法（Inline）
shardingAlgorithms:
  # 表达式分片算法
  t_order_mod:
    type: INLINE
    props:
      # 分片表达式，${} 中使用 Groovy 表达式
      algorithm-expression: ds_${user_id % 2}
      # 是否启用重写（解决 IN/AND/OR 问题）
      allow-range-query-with-inline-sharding: false

# 标准分片算法
shardingAlgorithms:
  t_order_standard:
    type: STANDARD
    props:
      # 分片算法实现类
      algorithm-class-name: com.example.algorithm.StandardShardingAlgorithm

# 基于时间范围的算法
shardingAlgorithms:
```

```java
import org.apache.shardingsphere.driver.api.yaml.YamlShardingSphereDataSourceFactory;
import org.apache.shardingsphere.infra.config.algorithm.AlgorithmConfiguration;
import org.apache.shardingsphere.sharding.api.config.ShardingRuleConfiguration;

import org.apache.shardingsphere.sharding.api.config.strategy.keygen.KeyGenerateStrategyConfiguration;
import org.apache.shardingsphere.sharding.api.config.strategy.sharding.StandardShardingStrategyConfiguration;

import java.sql.SQLException;

import java.util.HashMap;

    private static Map<String, DataSource> createDataSourceMap() {
        Map<String, DataSource> dataSourceMap = new HashMap<>();

        // ds_0
        HikariDataSource ds0 = new HikariDataSource();
        ds0.setDriverClassName("com.mysql.cj.jdbc.Driver");
        ds0.setJdbcUrl("jdbc:mysql://127.0.0.1:3306/ds_0?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai");
        ds0.setUsername("root");
        ds0.setPassword("root123456");
        ds0.setMaximumPoolSize(20);
        ds0.setMinimumIdle(5);
        dataSourceMap.put("ds_0", ds0);

        // ds_1
        HikariDataSource ds1 = new HikariDataSource();
        ds1.setDriverClassName("com.mysql.cj.jdbc.Driver");
        ds1.setJdbcUrl("jdbc:mysql://127.0.0.1:3307/ds_1?useUnicode=true&characterEncoding=UTF-8&serverTimezone=Asia/Shanghai");
        ds1.setUsername("root");
        ds1.setPassword("root123456");
        ds1.setMaximumPoolSize(20);
        ds1.setMinimumIdle(5);
        dataSourceMap.put("ds_1", ds1);

        return dataSourceMap;
    }

    private static ShardingRuleConfiguration createShardingRuleConfiguration() {
        ShardingRuleConfiguration config = new ShardingRuleConfiguration();

        // 配置 t_order 表
        ShardingTableRuleConfiguration orderTable = new ShardingTableRuleConfiguration("t_order", "ds_${0..1}.t_order");
        orderTable.setTableStrategy(createTableStrategy());
        orderTable.setKeyGenerateStrategy(new KeyGenerateStrategyConfiguration("order_id", "snowflake"));
        config.getTables().add(orderTable);

        // 配置 t_order_item 表
        ShardingTableRuleConfiguration orderItemTable = new ShardingTableRuleConfiguration("t_order_item", "ds_${0..1}.t_order_item");
        orderItemTable.setTableStrategy(createTableStrategy());
        orderItemTable.setKeyGenerateStrategy(new KeyGenerateStrategyConfiguration("item_id", "snowflake"));
        config.getTables().add(orderItemTable);

        shardingAlgorithms.put("inline", createInlineAlgorithm("ds_${user_id % 2}"));

    }

    private static AlgorithmConfiguration createSnowflakeAlgorithm() {
```

```java
        jdbcTemplate.update(sql,
                order.getUserId(),
                order.getStatus(),
                order.getAmount(),
                LocalDateTime.now(),
                LocalDateTime.now()
        );
        // 对于自增主键，需要通过其他方式获取

        return null;

        String sql = "INSERT INTO t_order (user_id, status, amount, create_time, update_time) VALUES (?, ?, ?, ?, ?)";
        jdbcTemplate.update(connection -> {
            var ps = connection.prepareStatement(sql, new String[]{"order_id"});
            ps.setLong(1, order.getUserId());
            ps.setString(2, order.getStatus());
            ps.setBigDecimal(3, order.getAmount());
            ps.setTimestamp(4, java.sql.Timestamp.valueOf(LocalDateTime.now()));
            ps.setTimestamp(5, java.sql.Timestamp.valueOf(LocalDateTime.now()));
            return ps;
        });
    }

    public Order findById(Long orderId) {
        String sql = "SELECT * FROM t_order WHERE order_id = ?";
        return jdbcTemplate.queryForObject(sql, orderRowMapper, orderId);
    }

    public List<Order> findByUserId(Long userId) {
        String sql = "SELECT * FROM t_order WHERE user_id = ?";
        return jdbcTemplate.query(sql, orderRowMapper, userId);
    }

    public List<Order> findAll() {
        String sql = "SELECT * FROM t_order";
        return jdbcTemplate.query(sql, orderRowMapper);
    }

    public void update(Order order) {
        String sql = "UPDATE t_order SET status = ?, amount = ?, update_time = ? WHERE order_id = ?";
        jdbcTemplate.update(sql,
                order.getStatus(),
                order.getAmount(),
                LocalDateTime.now(),
                order.getOrderId()
        );
    }

    public void delete(Long orderId) {
        String sql = "DELETE FROM t_order WHERE order_id = ?";
```

```java
            .itemId(rs.getLong("item_id"))
            .orderId(rs.getLong("order_id"))
            .userId(rs.getLong("user_id"))
            .productName(rs.getString("product_name"))
            .price(rs.getBigDecimal("price"))
            .quantity(rs.getInt("quantity"))
            .build();

    public void insert(OrderItem orderItem) {
        String sql = "INSERT INTO t_order_item (order_id, user_id, product_name, price, quantity) VALUES (?, ?, ?, ?, ?)";
        jdbcTemplate.update(sql,
                orderItem.getOrderId(),
                orderItem.getUserId(),
                orderItem.getProductName(),
                orderItem.getPrice(),
                orderItem.getQuantity()
        );
    }

    public OrderItem findById(Long itemId) {
        String sql = "SELECT * FROM t_order_item WHERE item_id = ?";
        return jdbcTemplate.queryForObject(sql, orderItemRowMapper, itemId);
    }

    public List<OrderItem> findByOrderId(Long orderId) {
        String sql = "SELECT * FROM t_order_item WHERE order_id = ?";
        return jdbcTemplate.query(sql, orderItemRowMapper, orderId);
    }

    public List<OrderItem> findByUserId(Long userId) {
        String sql = "SELECT * FROM t_order_item WHERE user_id = ?";
        return jdbcTemplate.query(sql, orderItemRowMapper, userId);
    }
}
```

## 3.7 验证分片是否生效

完成以上步骤后，需要验证分片是否真正生效。本节介绍几种验证方法。

### 3.7.1 查看日志输出

在 application.yml 中配置了 `sql-show: true`，ShardingSphere 会输出 SQL 执行日志。

观察日志中的路由信息：

```
[INFO ] 2024-01-15 10:30:00.123 [http-nio-8080-exec-1] ShardingSphere-SQL: Actual SQL: ds_0 ::: SELECT * FROM t_order WHERE user_id = ?
```

这表明：
- SQL 被路由到了 `ds_0` 数据源
- 分片规则生效

### 3.7.2 直接查询数据库验证

连接到两个 MySQL 节点，验证数据是否按照分片规则分布。

**查看 ds_0 上的数据：**

```sql
mysql -h 127.0.0.1 -P 3306 -uroot -proot123456 -e "SELECT * FROM ds_0.t_order;"
```

**查看 ds_1 上的数据：**

```sql
mysql -h 127.0.0.1 -P 3307 -uroot -proot123456 -e "SELECT * FROM ds_1.t_order;"
```

预期结果：
- `user_id % 2 == 0` 的数据在 `ds_0` 上
- `user_id % 2 == 1` 的数据在 `ds_1` 上

**例如：**

如果创建了 user_id 为 1、2、3、4 的订单：
- user_id=1,3 的订单应该在 ds_1（奇数）
- user_id=2,4 的订单应该在 ds_0（偶数）

### 3.7.3 使用管理接口验证

ShardingSphere 提供了管理接口，可以查看分片状态。

需要在 application.yml 中添加配置：

```yaml
          # 可以使用 file 或内存模式
```

### 3.7.5 验证绑定表

绑定表是分片中常用的优化手段，验证方法：

```bash
# 添加订单明细
curl -X POST http://localhost:8080/api/orders/1/items \
  -H "Content-Type: application/json" \
  -d '{"userId": 1, "productName": "商品A", "price": 50.00, "quantity": 2}'

# 在两个节点查看
mysql -h 127.0.0.1 -P 3306 -uroot -proot123456 -e "SELECT * FROM ds_0.t_order_item;"
mysql -h 127.0.0.1 -P 3307 -uroot -proot123456 -e "SELECT * FROM ds_1.t_order_item;"
```

由于 t_order 和 t_order_item 是绑定表，它们会按照相同的分片键（user_id）进行分片，关联查询时只在同一个数据源内进行。

### 3.7.6 常见验证问题

**问题1：所有数据都到一个节点**

可能原因：
- 分片键的值都相同
- 分片算法表达式错误
- 分片键未传递

解决方法：
- 检查分片算法表达式：`ds_${user_id % 2}`
- 检查是否正确传递了分片键的值
- 确认 user_id 的值范围

**问题2：查询时全库扫描**

可能原因：
- 未指定分片键的查询
- 使用了 `*` 作为分片键但算法不支持

解决方法：
- 查看日志中的 `Actual SQL`
- 如果显示 `ds_${0..1}` 说明进行了全库扫描
- 优化 SQL，添加分片键条件

**问题3：主键冲突**

可能原因：
- 两个节点的主键同时使用自增
- Snowflake 算法在多个节点上配置相同

解决方法：
- 使用 ShardingSphere 的主键生成策略
- 确保不同节点使用不同的 snowflake worker-id

## 3.9 使用 ShardingSphere-SQL 测试

ShardingSphere 提供了 SQL 测试工具，可以帮助验证分片配置和 SQL 路由是否正确。

### 3.9.1 ShardingSphere-SQL 执行原理

ShardingSphere-SQL 执行流程：

1. **SQL 解析**：将 SQL 解析为抽象语法树（AST）
2. **SQL 改写**：根据分片规则改写 SQL（去掉不必要的分片条件等）
3. **SQL 路由**：根据分片规则计算 SQL 应路由到哪个数据源/表
4. **SQL 执行**：在目标数据源执行改写后的 SQL
5. **结果归并**：将多数据源的结果合并返回

### 3.9.2 SQL 解析测试

使用 ShardingSphere 的 SQL 解析器可以查看 SQL 如何被解析：

```java
import org.apache.shardingsphere.sql.parser.api.SQLParserEngine;
import org.apache.shardingsphere.sql.parser.api.SQLVisitorEngine;
import org.apache.shardingsphere.sql.parser.core.ParseAST;
import org.apache.shardingsphere.sql.parser.core.SQLParserFactory;
```

### 3.9.5 常用 SQL 测试场景

**场景1：INSERT 测试**

```sql
-- 测试插入
INSERT INTO t_order (user_id, status, amount) VALUES (1, 'PENDING', 100.00);
INSERT INTO t_order (user_id, status, amount) VALUES (2, 'PENDING', 200.00);
INSERT INTO t_order (user_id, status, amount) VALUES (3, 'PENDING', 300.00);
```

预期结果：user_id 为奇数路由到 ds_1，为偶数路由到 ds_0

**场景2：查询测试**

```sql
-- 按分片键查询（单节点路由）
SELECT * FROM t_order WHERE user_id = 1;

-- 范围查询（多节点路由）
SELECT * FROM t_order WHERE user_id > 0 AND user_id < 100;

-- 全库查询
SELECT * FROM t_order;
```

**场景3：更新测试**

```sql
-- 按分片键更新（单节点）
UPDATE t_order SET status = 'PAID' WHERE user_id = 1 AND order_id = 123;

-- 不带分片键更新（多节点）
UPDATE t_order SET status = 'PAID' WHERE status = 'PENDING';
```

**场景4：删除测试**

```sql
-- 按分片键删除（单节点）
DELETE FROM t_order WHERE user_id = 1 AND order_id = 123;

-- 全表删除
DELETE FROM t_order;
```

**场景5：关联查询测试**

```sql
-- 绑定表关联查询（同节点）
SELECT o.*, i.* FROM t_order o
JOIN t_order_item i ON o.order_id = i.order_id
WHERE o.user_id = 1;

-- 非绑定表关联查询（可能跨节点）
SELECT * FROM t_order o
JOIN other_table t ON o.user_id = t.user_id;
```

### 3.9.7 SQL 兼容性注意事项

**不支持的 SQL 类型：**

1. 跨分片的排序操作（需要应用层处理）
2. 跨分片的分组操作（需要应用层处理）
3. 跨分片的聚合函数（需要应用层处理）
4. 跨分片的子查询（部分支持）

**支持的 SQL 类型：**

- 单表查询
- 按分片键的 CRUD
- 绑定表关联查询
- 跨节点 UNION（合并结果）

**注意事项：**

1. 分片键必须使用 `=` 条件，不能仅使用 `IN`、`BETWEEN`、`LIKE` 等范围条件
2. 尽量避免跨分片的表关联
3. 合理设计分片键，避免热点数据
