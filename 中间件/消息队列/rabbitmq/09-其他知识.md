# 1、幂等性
## 1.1 概述
<font style="color:rgb(18, 18, 18);">幂等是指一个方法被多次重复执行的时候所期望的结果要和第一次执行所期望的结果保持一致。简单点来说就是多次操作的返回结果是一样的。比如查询操作是幂等的，更新是非幂等的。</font>

<font style="color:rgb(18, 18, 18);">案例：比如我们去购物，下单完后进行支付，但是由于网络的原因提交成功的消息未能返回给用户，这个时候操作是已经完成了的，但是用户没有感知到，此时用户再次按下提交按钮就会发送二次请求，此时就会造成重复消费。如果接口不幂等，那么最终结果就是用户被扣了两次费用，这样是不可取的，我们应该对接口做幂等。</font>



**消息被重复消费**

消息在被消费的时候由于网络原因导致消费者未能及时应答，此时服务器就会将消息给另外的消费者进行消费，那么当网络恢复正常时就会重复提交 ack，导致消息被消费了两次



## 1.2 如何保证幂等性?
业界的主流方案是：

1. 唯一ID + 指纹码机制
2. Redis原子性



### 1.2.1 唯一ID + 指纹码机制
在生产者发送消息的时候给每条消息设置全局ID，可以是时间戳、UUID或者雪花算法来保证唯一ID。

指纹码：业务的一些特殊信息，比如是用户的ID，以此来确保消息的唯一性



### 1.2.2 Redis原子性
使用Redis的 `setnx` 命令，它天然具有幂等性







# 2、优先级队列
## 2.1 概述
此队列的作用就是让拥有优先级的消息先行，比如我们在医院排队等待治疗，但是有个人它的病急需治疗，那么此时医院就会优先治疗他。那么优先队列也是同样的道理，有些消息是非常紧急或者他非常重要的就可以设置优先级来让它先被消费。



## 2.2 设置优先队列
**消费者设置**

队列设置 `x-max-priority` 参数来将队列消息进行排序，它的值就是表示消息优先级的最大值

比如设置 `x-max-priority` 为 10，那么消息就会按照 0-10 的优先级进行排序，优先级越大那么它就会越靠前，也就是越快被消费，如果不设置此参数，那么此队列就不是优先队列。

```java
Map<String, Object> params = new HashMap<>();
params.put("x-max-priority", 10);
```

优先队列在web控制台显示如下：
![](https://cdn.nlark.com/yuque/0/2023/png/12747499/1691998770134-914254bc-7692-494f-8a6f-8f264f3338db.png)



**生产者设置**

生产方需要指定消息的优先级，`priority` 属性进行设置，不设置的消息优先级为 0

```java
AMQP.BasicProperties build = new AMQP.BasicProperties().builder().priority(5).build();
```



## 2.3 实战演练
**生产者**

```java
public class Product {

    public static void main(String[] args) throws Exception {
        Channel channel = RabbitMQUtil.getChannel();
        Connection connection = channel.getConnection();
        AMQP.BasicProperties properties = new AMQP.BasicProperties().builder().priority(5).build();
        for (int i = 0; i < 1000; i++) {
            String msg = "info" + i;
            if (i == 5) {
                channel.basicPublish("", "key1", properties, msg.getBytes(StandardCharsets.UTF_8));
            } else {
                channel.basicPublish("", "key1",null, msg.getBytes(StandardCharsets.UTF_8));
            }
        }
    }
}
```

**消费者**

```java
public class Consumer {

    public static void main(String[] args) throws Exception {
        Channel channel = RabbitMQUtil.getChannel();
        Map<String, Object> params = new HashMap<>();
        params.put("x-max-priority", 10);
        channel.queueDeclare("hello", false, false, false, params);
        DeliverCallback deliverCallback = (consumerTag, message) -> {
            String msg = new String(message.getBody(), StandardCharsets.UTF_8);
            System.out.println("收到消息：" + msg);
        };
        channel.basicConsume("hello", true,  deliverCallback, consumerTag -> { System.out.println("消息未能处理"); });
    }
}
```



**测试**

先启动生产者，过一会再启动消费者，这是为了让消息堆积
![](https://cdn.nlark.com/yuque/0/2023/png/12747499/1691998618654-0b637f85-f8cf-42dc-8367-d9fd404aeef3.png)

可以看到由于 i=5 的消息的优先级为 0，所以它是最后被消费的~~~

:::warning
**注意**：如果消费端的消费速度大于生产速度或者 Broker 中没有消息堆积，设置优先级队列是没有意义的，因为生成一条就被消费，所以对于 Broker来说就是至少有一条消息了，所以设置优先队列无意义，但是对于大型的系统来说，每天的日活量上亿或者几十亿，那么这个时候设置优先队列是非常有用的。

:::





# 3、惰性队列
## 3.1 概述
RabbitMQ 从 3.6.0 版本开始引入了惰性队列的概念。惰性队列的消息存储在硬盘上，需要的时候就读入内存，然后再被消费。这样的好处就是即使是宕机了也不会导致消息的丢失，缺点就是在保存到磁盘的时候需要部分资源来操作，如果消息过多的话就会导致阻塞队列，导致无法接收最新的消息。



**对比默认的队列**
![](https://cdn.nlark.com/yuque/0/2023/png/12747499/1692003268683-f144dc08-ffc2-4b0a-b3bd-0be63e64cc70.png)

在发送 1 百万条消息，每条消息大概占 1KB 的情况下，普通队列占用内存是 1.2GB，而惰性队列仅仅占用 1.5MB。
