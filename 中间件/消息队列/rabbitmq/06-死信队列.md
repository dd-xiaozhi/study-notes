# 1、概述
消息出现下面的几种情况：

+ 消息被拒绝
+ 队列达到最大长度，无法加入新的消息
+ 消息的超过设定的时间未被消费

就会导致消息成为死信

简单来说就是 未能被正常处理的消息（BB那么多~~~😂）





# 2、死信交换机

全称 <font style="color:rgb(18, 18, 18);">Dead Letter Exchange </font>简称 `DLX`。这破玩意就是一个普通的交换机，它是一个接盘侠，负责接收人家不要或者没被处理的消息。

一般消息成为死信后会被 RabbitMQ 清理，但是我们可以绑定一个死信队列来接收这些消息，使他们重新成为活信

<font style="color:rgb(18, 18, 18);"></font>

**<font style="color:rgb(18, 18, 18);">那么队列如何绑定 </font>**`**<font style="color:rgb(18, 18, 18);">DLX</font>**`**<font style="color:rgb(18, 18, 18);">呢？</font>**

<font style="color:rgb(18, 18, 18);">创建队列的时候设置两个参数</font>

+ <font style="color:rgb(18, 18, 18);">x-dead-letter-exchange：指定此队列的死信队列</font>
+ <font style="color:rgb(18, 18, 18);">x-dead-letter-routing-keyt：指定此队列向DLX发送死信的routing key，因为这个时候该队列相当于一个生产者，发送消息要指定routing key</font>

## 3.1 基本实验环境搭建
1. 创建 `X交换机`，`Y死信交换机`
2. 创建 `QA队列`、`QD 死信队列`
3. 对应交换机绑定对应队列
4. 让 `QA队列` 和 `Y死信交换机` 进行绑定

**代码实现**

+ 配置交换机和队列

```java
/**
* 配置交换机和队列
*
* @author xiaozhi
*/
@Configuration
public class RabbitMQConfig {

    public static final String X_EXCHANGE = "X";
    public static final String Y_DEAD_LETTER_EXCHANGE = "Y";
    public static final String QUEUE_A = "QA";
    public static final String DEAD_LETTER_QUEUE = "QD";

    @Bean("xExchange")
    public DirectExchange xExchange() {
        return new DirectExchange(X_EXCHANGE);
    }

    @Bean("yExchange")
    public DirectExchange yExchange() {
        return new DirectExchange(Y_DEAD_LETTER_EXCHANGE);
    }

    @Bean("queueA")
    public Queue queueA() {
        Map<String, Object> params = new HashMap<>();
        // 声明当前队列绑定死信交换机
        params.put("x-dead-letter-exchange", Y_DEAD_LETTER_EXCHANGE);
        // 声明当前队列的死信路由key
        params.put("x-dead-letter-routing-key", "YD");
        return QueueBuilder.durable(QUEUE_A).withArguments(params).build();
    }

    // 声明队列A绑定X交换机
    @Bean
    public Binding queryBindingX(@Qualifier("queueA") Queue queueA,
                                 @Qualifier("xExchange") DirectExchange xExchange) {
        return BindingBuilder.bind(queueA).to(xExchange).with("XA");
    }

    // 声明死信队列
    @Bean("queueD")
    public Queue queueD() {
        return new Queue(DEAD_LETTER_QUEUE);
    }

    // 给死信交换机绑定队列
    @Bean
    public Binding queueBindingD(@Qualifier("queueD") Queue queueD,
                                 @Qualifier("yExchange") DirectExchange yExchange) {
        return BindingBuilder.bind(queueD).to(yExchange).with("YD");
    }
}
```

+ 生产者生产消息

```java
@Slf4j
@RestController
public class SendMsgController {

    @Resource
    private RabbitTemplate rabbitTemplate;

    @GetMapping("/ttl/{msg}")
    public void acceptInput(@PathVariable("msg") String msg) {
        msg = "来自 xiaozhi 的消息：" + msg;
        rabbitTemplate.convertAndSend(RabbitMQConfig.X_EXCHANGE, "XA", msg);
        log.info("时间：{}, 发送消息：{}", new Date(), msg);
    }
}
```

定义了一个消息接口，通过这个接口来传递消息

`RabbitTemplate#convertAndSend`：转换并发送，这个方法是可以将队列转换成字节流进行传输

:::color1
Tip：在 生产者（消息发送方）设置过期时间是对当前发送的消息进行了 ttl 设置，如果是在 消费者（消息接收方）设置的话就是对整个队列中的消息设置 ttl，所以要进行区分

:::

+ 消费者进行消费

```java
@Slf4j
@Component
public class ConsumerTest {

	@RabbitListener(queues = { RabbitMQConfig.DEAD_LETTER_QUEUE })
    public void receiveD(Message message, Channel channel) {
        // 获取消费队列名
        String queueName = message.getMessageProperties().getConsumerQueue();
        log.info("当前时间是：{}，队列 {} 收到消息：{}", new Date(), queueName, new String(message.getBody(), StandardCharsets.UTF_8));
    }
}
```

`@RabbitListener`：监听消息，有消息就进行消费，可以监听多个队列

    @GetMapping("/sendMsg")

2. 消费 `QA` 的消息并拒绝它

```java
@Slf4j
@Component
public class ConsumerTest {

    @SneakyThrows
    @RabbitListener(queues = { RabbitMQConfig.QUEUE_A })
    public void receiveD(Message message, Channel channel) {
        // 获取消费队列名
        String queueName = message.getMessageProperties().getConsumerQueue();
        channel.basicNack(message.getMessageProperties().getDeliveryTag(), false, false);
        log.info("队列 {} 拒绝消息：{}", queueName, new String(message.getBody(), StandardCharsets.UTF_8));
    }

}
```
