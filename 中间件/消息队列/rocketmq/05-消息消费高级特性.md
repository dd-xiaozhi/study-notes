# Chapter 5: 消息消费高级特性

## 5.1 集群消费 vs 广播消费

RocketMQ 支持两种消息消费模式：

### 集群消费（Clustering）
- 消息在消费者组内进行负载均衡，每条消息只会被组内的一个消费者消费
- 消费者组内各消费者共同承担消息处理任务
- 默认消费模式，适用于大多数业务场景

```java
// 设置为集群消费模式（默认）
consumer.setMessageModel(MessageModel.CLUSTERING);
```

### 广播消费（Broadcasting）
- 每条消息会被消费者组内的所有消费者消费
- 每个消费者都能收到全量消息
- 适用于消息通知、缓存同步等场景

```java
// 设置为广播消费模式
consumer.setMessageModel(MessageModel.BROADCASTING);
```

### 适用场景

| 场景 | 推荐模式 | 原因 |
|------|----------|------|
| 订单处理、支付消息 | 集群消费 | 消息只需处理一次，避免重复操作 |
| 系统通知、广告推送 | 广播消费 | 所有消费者都需要收到通知 |
| 缓存同步、日志分发 | 广播消费 | 各节点需要保持数据一致性 |

## 5.2 顺序消费

### 消息有序的前提条件

1. **生产者端**：消息必须按照发送顺序进入同一个 MessageQueue
2. **MessageQueue**：使用单队列或指定队列，确保消息顺序存储
3. **消费者端**：必须单线程顺序消费

### 消费端如何保证有序

```java
// 使用 MessageListenerOrderly 实现顺序消费
consumer.registerMessageListener(new MessageListenerOrderly() {
    @Override
    public ConsumeOrderlyStatus consumeMessage(List<MessageExt> msgs, ConsumeOrderlyContext context) {
        for (MessageExt msg : msgs) {
            // 按顺序处理每条消息
            System.out.println("处理消息: " + new String(msg.getBody()));
        }
        return ConsumeOrderlyStatus.SUCCESS;
    }
});
```

### 注意事项

1. **性能牺牲**：顺序消费通常比并发消费性能低，因为需要串行处理
2. **Broker 故障**：如果 Broker 宕机，可能导致队列重新分配，破坏顺序性
3. **局部有序**：RocketMQ 保证的是队列内有序（Partition Ordered），不是全局有序
4. **异常处理**：抛出异常时消息会重新投递，可能导致短暂乱序

## 5.3 消息重试与死信队列

### 重试机制说明

当消息消费失败时，RocketMQ 会自动进行重试：

1. **立即重试**：消费失败后立即重试
2. **延迟重试**：按照固定时间间隔重试（1s、5s、10s...）
3. **最大重试次数**：超过后进入死信队列

### 最大重试次数

默认最大重试次数为 16 次，可通过配置调整：

```java
//方式1：通过 DefaultMQPushConsumer 配置
consumer.setMaxReconsumeTimes(16);

//方式2：通过 Broker 配置
//broker.conf: maxReconsumeTimes=16
```

重试间隔时间递增：1s、5s、10s、30s、1m、2m、...、2h

### 死信队列（Dead Letter Queue）

当消息超过最大重试次数仍消费失败时，会进入死信队列：

- **死信队列名称**：`%DLQ%{消费者组名}`
- **存储位置**：与普通队列隔离，单独存储
- **保留时间**：默认 72 小时
- **不会自动删除**：需要人工处理或程序消费

```java
// 订阅死信队列
consumer.subscribe(" %DLQ%your-consumer-group", "*");
```

### 重试代码示例

```java
public class RetryConsumer {
    public static void main(String[] args) throws MQClientException {
        DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("my-consumer-group");
        consumer.setNamesrvAddr("localhost:9876");
        consumer.subscribe("TopicTest", "*");

        // 设置最大重试次数
        consumer.setMaxReconsumeTimes(3);

        consumer.registerMessageListener(new MessageListenerConcurrently() {
            @Override
            public ConsumeConcurrentlyStatus consumeMessage(List<MessageExt> msgs,
                                                            ConsumeConcurrentlyContext context) {
                for (MessageExt msg : msgs) {
                    try {
                        // 业务处理逻辑
                        processMessage(msg);
                        return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
                    } catch (Exception e) {
                        // 业务异常，触发重试
                        System.out.println("消费失败，触发重试: " + msg.getMsgId());
                        return ConsumeConcurrentlyStatus.RECONSUME_LATER;
                    }
                }
                return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
            }
        });

        consumer.start();
    }
}
```

## 5.4 消费幂等性

### 幂等性必要性

在分布式系统中，由于网络波动、消费者重启等原因，消息可能被重复投递。如果消费端不具备幂等性，可能导致：

- 重复扣款、重复下单
- 数据重复插入
- 业务状态异常

### 解决方案

#### 1. 唯一消息ID（推荐）

每条消息都有唯一的 MsgId，可用于去重判断：

```java
public class IdempotentConsumer {
    private Set<String> processedMsgIds = new ConcurrentHashSet<>();

    public void consumeMessage(MessageExt msg) {
        String msgId = msg.getMsgId();

        // 幂等判断：检查是否已处理
        if (processedMsgIds.contains(msgId)) {
            System.out.println("消息已处理，跳过: " + msgId);
            return;
        }

        // 业务处理
        doProcess(msg);

        // 记录已处理消息ID
        processedMsgIds.add(msgId);
    }
}
```

#### 2. 业务去重（更可靠）

根据业务唯一键进行去重，如订单号、用户ID等：

```java
public class BusinessIdempotentConsumer {

    @Autowired
    private OrderService orderService;

    public void consumeMessage(MessageExt msg) {
        String body = new String(msg.getBody());
        OrderMessage orderMsg = JSON.parseObject(body, OrderMessage.class);

        // 业务去重：检查订单是否已处理
        if (orderService.isOrderProcessed(orderMsg.getOrderId())) {
            System.out.println("订单已处理，跳过: " + orderMsg.getOrderId());
            return;
        }

        // 业务处理
        orderService.processOrder(orderMsg);

        System.out.println("订单处理成功: " + orderMsg.getOrderId());
    }
}

// OrderMessage 实体
class OrderMessage {
    private String orderId;
    private String userId;
    private BigDecimal amount;
    // getters and setters
}
```

### 幂等性最佳实践

1. **数据库唯一索引**：对关键业务字段建立唯一索引，防止重复数据
2. **分布式锁**：使用 Redis/Zookeeper 实现分布式锁
3. **消息状态表**：记录消息处理状态，定期清理历史数据
4. **至少一次 vs 恰好一次**：在 RocketMQ 层面只能保证"至少一次"，业务层需实现"恰好一次"
