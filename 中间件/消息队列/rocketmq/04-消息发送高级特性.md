# 第4章-消息发送高级特性

## 4.1 顺序消息

### 概念
顺序消息是指消息按照发送的顺序进行消费。在 RocketMQ 中，通过 MessageQueueSelector 可以将消息发送到指定的队列，从而保证消息的顺序性。

### 实现方式
使用 `MessageQueueSelector` 接口实现，有三种实现方式：
- **按队列数量取模**：根据某个 key 取模选择队列
- **使用哈希映射**：对 key 进行哈希后选择队列
- **自定义选择器**：实现 `MessageQueueSelector` 接口自定义逻辑

### 代码示例

```java
import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.client.producer.MessageQueueSelector;
import org.apache.rocketmq.client.producer.SendResult;
import org.apache.rocketmq.common.message.Message;
import org.apache.rocketmq.common.message.MessageQueue;

import java.util.List;

public class OrderMessageProducer {
    public static void main(String[] args) throws Exception {
        // 创建生产者实例
        DefaultMQProducer producer = new DefaultMQProducer("order_producer_group");
        producer.setNamesrvAddr("localhost:9876");
        producer.start();

        // 订单数据列表
        String[] orderIds = {"ORDER001", "ORDER002", "ORDER003"};
        String[] items = {"商品A", "商品B", "商品C"};

        // 发送顺序消息
        for (int i = 0; i < orderIds.length; i++) {
            String orderId = orderIds[i];
            String item = items[i];

            Message msg = new Message("OrderTopic", "OrderTag",
                (orderId + "-" + item).getBytes());

            // 使用 MessageQueueSelector 实现顺序消息
            // 相同 orderId 的消息会发送到同一个队列
            SendResult result = producer.send(msg, new MessageQueueSelector() {
                @Override
                public MessageQueue select(List<MessageQueue> mqs, Message msg, Object arg) {
                    // 按 orderId 取模，确保相同订单的消息顺序发送
                    String orderId = (String) arg;
                    int hash = orderId.hashCode();
                    int index = Math.abs(hash % mqs.size());
                    System.out.println("Order [" + orderId + "] sent to queue: " + index);
                    return mqs.get(index);
                }
            }, orderId);  // arg 参数会传递给 select 方法

            System.out.println("Send Result: " + result.getSendStatus());
        }

        producer.shutdown();
    }
}
```

## 4.2 延迟消息

### 概念
延迟消息是指消息发送到 Broker 后，不会立即被消费者消费，而是等待指定时间后才可投递。RocketMQ 支持多种延迟级别，实现定时任务和延时处理场景。

### RocketMQ 延迟消息级别
RocketMQ 将延迟消息分为 18 个级别：

| 级别 | 延迟时间 | 级别 | 延迟时间 |
|------|---------|------|---------|
| 1 | 1秒 | 10 | 2小时 |
| 2 | 5秒 | 11 | 4小时 |
| 3 | 10秒 | 12 | 8小时 |
| 4 | 30秒 | 13 | 12小时 |
| 5 | 1分钟 | 14 | 1天 |
| 6 | 2分钟 | 15 | 2天 |
| 7 | 3分钟 | 16 | 3天 |
| 8 | 4分钟 | 17 | 4天 |
| 9 | 5分钟 | 18 | 5天 |

### 代码示例

```java
import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.client.producer.SendResult;
import org.apache.rocketmq.common.message.Message;

public class DelayMessageProducer {
    public static void main(String[] args) throws Exception {
        DefaultMQProducer producer = new DefaultMQProducer("delay_producer_group");
        producer.setNamesrvAddr("localhost:9876");
        producer.start();

        // 创建一个延迟消息
        Message msg = new Message("DelayTopic", "DelayTag",
            "延迟消息内容".getBytes());

        // 设置延迟级别为 3，即 10 秒后投递
        // 级别: 1=1s, 2=5s, 3=10s, 4=30s, 5=1m, 6=2m, 7=3m, 8=4m, 9=5m,
        //       10=2h, 11=4h, 12=8h, 13=12h, 14=1d, 15=2d, 16=3d, 17=4d, 18=5d
        msg.setDelayTimeLevel(3);

        SendResult result = producer.send(msg);
        System.out.println("延迟消息发送状态: " + result.getSendStatus());
        System.out.println("延迟级别: 3 (10秒)");

        producer.shutdown();
    }
}
```

## 4.3 事务消息

### 概念
事务消息用于实现本地事务与消息发送的原子性。它确保本地数据库操作和消息发送要么同时成功，要么同时失败，保证系统一致性。

### TransactionListener 使用

事务消息的工作流程：
1. **发送半消息**：将消息发送为 PREPARED 状态（对消费者不可见）
2. **执行本地事务**：在本地数据库执行业务操作
3. **提交/回滚**：根据本地事务结果提交或回滚消息

### 代码示例

```java
import org.apache.rocketmq.client.producer.TransactionListener;
import org.apache.rocketmq.client.producer.TransactionMQProducer;
import org.apache.rocketmq.common.message.Message;
import org.apache.rocketmq.common.message.MessageExt;

import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.atomic.AtomicInteger;

public class TransactionProducer {
    public static void main(String[] args) throws Exception {
        TransactionMQProducer producer = new TransactionMQProducer("transaction_producer_group");
        producer.setNamesrvAddr("localhost:9876");

        // 设置事务监听器
        producer.setTransactionListener(new TransactionListener() {
            // 存储事务状态
            private ConcurrentHashMap<String, AtomicInteger> transactionIndex = new ConcurrentHashMap<>();

            @Override
            public LocalTransactionState executeLocalTransaction(Message msg, Object arg) {
                String transactionId = msg.getTransactionId();
                System.out.println("执行本地事务, transactionId: " + transactionId);

                // 模拟本地业务逻辑
                try {
                    // 假设 arg 中携带了业务标识
                    String status = (String) arg;
                    if ("COMMIT".equals(status)) {
                        // 本地事务成功，提交消息
                        return LocalTransactionState.COMMIT_MESSAGE;
                    } else if ("ROLLBACK".equals(status)) {
                        // 本地事务失败，回滚消息
                        return LocalTransactionState.ROLLBACK_MESSAGE;
                    } else {
                        // 不确定状态，需要回查
                        return LocalTransactionState.UNKNOWN;
                    }
                } catch (Exception e) {
                    System.err.println("本地事务执行异常: " + e.getMessage());
                    return LocalTransactionState.ROLLBACK_MESSAGE;
                }
            }

            @Override
            public LocalTransactionState checkLocalTransaction(MessageExt msg) {
                // 回查本地事务状态
                String transactionId = msg.getTransactionId();
                System.out.println("回查事务状态, transactionId: " + transactionId);

                // 根据本地事务表查询结果
                AtomicInteger state = transactionIndex.get(transactionId);
                if (state != null) {
                    switch (state.get()) {
                        case 1:
                            return LocalTransactionState.COMMIT_MESSAGE;
                        case 2:
                            return LocalTransactionState.ROLLBACK_MESSAGE;
                        default:
                            return LocalTransactionState.UNKNOWN;
                    }
                }
                return LocalTransactionState.UNKNOWN;
            }
        });

        producer.start();

        // 发送事务消息
        Message msg1 = new Message("TransactionTopic", "TagA",
            "事务消息1".getBytes());
        Message msg2 = new Message("TransactionTopic", "TagA",
            "事务消息2".getBytes());

        // 发送时携带业务参数，用于本地事务判断
        producer.sendMessageInTransaction(msg1, "COMMIT");
        producer.sendMessageInTransaction(msg2, "ROLLBACK");

        System.out.println("事务消息发送完成");

        // 注意：实际应用中不应立即关闭
        // Thread.sleep(30000);
        // producer.shutdown();
    }
}
```

### 事务消息使用场景示例：银行转账

```java
/**
 * 转账服务示例：保证余额扣减和消息发送的原子性
 */
public class TransferService {
    private TransactionMQProducer producer;

    public void transfer(String fromAccount, String toAccount, double amount) {
        // 1. 创建消息
        Message transferMsg = new Message("TransferTopic", "Transfer",
            ("从 " + fromAccount + " 转账 " + amount + " 到 " + toAccount).getBytes());

        // 2. 执行转账（本地事务）
        try {
            // 扣除转出账户余额
            accountService.debit(fromAccount, amount);
            // 增加转入账户余额
            accountService.credit(toAccount, amount);

            // 3. 提交事务消息
            producer.sendMessageInTransaction(transferMsg, "COMMIT");
        } catch (Exception e) {
            // 事务失败，回滚消息
            producer.sendMessageInTransaction(transferMsg, "ROLLBACK");
            throw e;
        }
    }
}
```

## 4.4 批量消息

### 概念
批量消息允许将多条消息合并为一次发送，减少网络开销，提高吞吐量。适用于消息量大且可以批量处理的场景。

### ListSplitter 实现
由于消息有大小限制（默认 256KB），需要使用 `ListSplitter` 对大批量消息进行分片。

### 代码示例

```java
import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.client.producer.SendResult;
import org.apache.rocketmq.common.message.Message;

import java.util.ArrayList;
import java.util.List;

/**
 * 批量消息发送示例
 */
public class BatchMessageProducer {
    public static void main(String[] args) throws Exception {
        DefaultMQProducer producer = new DefaultMQProducer("batch_producer_group");
        producer.setNamesrvAddr("localhost:9876");
        producer.start();

        // 批量创建消息
        List<Message> messages = new ArrayList<>();
        for (int i = 0; i < 100; i++) {
            Message msg = new Message("BatchTopic", "BatchTag",
                ("批量消息 " + i).getBytes());
            messages.add(msg);
        }

        // 直接发送批量消息（适用于消息量较小的情况）
        // 注意：如果消息总大小超过 256KB，需要分批发送
        SendResult result = producer.send(messages);
        System.out.println("批量发送结果: " + result.getSendStatus());

        producer.shutdown();
    }
}
```

### 使用 ListSplitter 处理大批量消息

```java
import org.apache.rocketmq.common.message.Message;

import java.util.Iterator;
import java.util.List;
import java.util.Map;

/**
 * 消息分片工具类
 */
public class ListSplitter implements Iterator<List<Message>> {
    private int sizeLimit;  // 单批消息大小限制，默认 256KB
    private List<Message> messages;
    private int currentIndex;

    public ListSplitter(List<Message> messages) {
        this.messages = messages;
        this.sizeLimit = 256 * 1024;  // 256KB
        this.currentIndex = 0;
    }

    @Override
    public boolean hasNext() {
        return currentIndex < messages.size();
    }

    @Override
    public List<Message> next() {
        int startIndex = currentIndex;
        int totalSize = 0;
        List<Message> subList = new ArrayList<>();

        for (int i = currentIndex; i < messages.size(); i++) {
            Message msg = messages.get(i);
            // 估算消息大小（包含消息头）
            int msgSize = estimateMessageSize(msg);

            // 如果加上这条消息会超过限制，且当前批次的消息不为空，则结束当前批次
            if (totalSize + msgSize > sizeLimit && !subList.isEmpty()) {
                break;
            }

            subList.add(msg);
            totalSize += msgSize;
            currentIndex = i + 1;
        }

        return subList;
    }

    /**
     * 估算消息大小
     */
    private int estimateMessageSize(Message msg) {
        // 消息体大小 + 消息头的固定开销（大约 200 字节）
        return msg.getBody() != null ? msg.getBody().length + 200 : 200;
    }
}

/**
 * 使用 ListSplitter 发送大批量消息
 */
public class LargeBatchMessageProducer {
    private static final int SIZE_LIMIT = 256 * 1024;  // 256KB

    public static void main(String[] args) throws Exception {
        DefaultMQProducer producer = new DefaultMQProducer("batch_producer_group");
        producer.setNamesrvAddr("localhost:9876");
        producer.start();

        // 创建大量消息
        List<Message> largeMessageList = new ArrayList<>();
        for (int i = 0; i < 1000; i++) {
            Message msg = new Message("LargeBatchTopic", "Tag",
                ("大批量消息 " + i + " - " + "内容".repeat(100)).getBytes());
            largeMessageList.add(msg);
        }

        // 使用 ListSplitter 分批发送
        ListSplitter splitter = new ListSplitter(largeMessageList);
        int batchCount = 0;

        while (splitter.hasNext()) {
            List<Message> batch = splitter.next();
            SendResult result = producer.send(batch);
            batchCount++;
            System.out.println("第 " + batchCount + " 批消息发送成功，数量: " + batch.size());
        }

        System.out.println("总共发送 " + batchCount + " 批消息");
        producer.shutdown();
    }
}
```

## 4.5 消息过滤

### 概念
消息过滤允许消费者只接收感兴趣的消息，减少无效消息的接收和处理。RocketMQ 支持两种过滤方式：标签过滤（Tag）和 SQL92 过滤。

### 标签过滤（Tag）
- 简单高效，基于精确匹配
- 一个消息只能有一个 Tag
- 适合简单的过滤场景

### SQL92 过滤
- 强大的过滤能力，支持属性表达式
- 可以基于消息属性进行条件过滤
- 适合复杂的过滤需求

### 代码示例

#### 生产者：发送带 Tag 和属性的消息

```java
import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.common.message.Message;

public class FilterMessageProducer {
    public static void main(String[] args) throws Exception {
        DefaultMQProducer producer = new DefaultMQProducer("filter_producer_group");
        producer.setNamesrvAddr("localhost:9876");
        producer.start();

        // 发送不同 Tag 的消息
        String[] tags = {"TagA", "TagB", "TagC"};
        for (int i = 0; i < 10; i++) {
            Message msg = new Message("FilterTopic", tags[i % 3],
                ("消息 " + i).getBytes());
            msg.putUserProperty("price", String.valueOf(100 + i * 10));
            msg.putUserProperty("category", i < 5 ? "electronics" : "furniture");
            producer.send(msg);
            System.out.println("发送消息: " + i + ", Tag: " + tags[i % 3]);
        }

        producer.shutdown();
    }
}
```

#### 使用 MessageSelector 进行 SQL 过滤

```java
import org.apache.rocketmq.client.consumer.DefaultMQPushConsumer;
import org.apache.rocketmq.client.consumer.MessageSelector;
import org.apache.rocketmq.client.consumer.listener.ConsumeConcurrentlyContext;
import org.apache.rocketmq.client.consumer.listener.ConsumeConcurrentlyStatus;
import org.apache.rocketmq.client.consumer.listener.MessageListenerConcurrently;
import org.apache.rocketmq.common.message.MessageExt;

import java.util.List;

public class SQLFilterConsumerWithSelector {
    public static void main(String[] args) throws Exception {
        DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("sql_filter_consumer_group");
        consumer.setNamesrvAddr("localhost:9876");

        // 使用 MessageSelector 指定 SQL92 过滤表达式
        String sqlExpression = "price > 120 AND category = 'electronics'";
        consumer.subscribe("FilterTopic", MessageSelector.bySql(sqlExpression));

        consumer.registerMessageListener(new MessageListenerConcurrently() {
            @Override
            public ConsumeConcurrentlyStatus consume(List<MessageExt> msgs,
                                                      ConsumeConcurrentlyContext context) {
                for (MessageExt msg : msgs) {
                    String price = msg.getUserProperty("price");
                    String category = msg.getUserProperty("category");
                    System.out.println("SQL过滤收到: " + new String(msg.getBody()) +
                        ", Price: " + price +
                        ", Category: " + category);
                }
                return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
            }
        });

        consumer.start();
        System.out.println("SQL92 过滤消费者（使用 Selector）已启动");
    }
}
```

### SQL92 过滤支持的操作符

| 操作符 | 说明 | 示例 |
|--------|------|------|
| `=` | 等于 | `category = 'electronics'` |
| `>` | 大于 | `price > 100` |
| `>=` | 大于等于 | `price >= 100` |
| `<` | 小于 | `price < 100` |
| `<=` | 小于等于 | `price <= 100` |
| `AND` | 逻辑与 | `price > 100 AND category = 'electronics'` |
| `OR` | 逻辑或 | `category = 'electronics' OR category = 'furniture'` |
| `NOT` | 逻辑非 | `NOT category = 'electronics'` |
| `IS NULL` | 为空 | `property IS NULL` |
| `IS NOT NULL` | 不为空 | `property IS NOT NULL` |
| `IN` | 在集合中 | `category IN ('electronics', 'furniture')` |

## 本章小结

本章介绍了 RocketMQ 的五种消息发送高级特性：

| 特性 | 适用场景 | 关键组件 |
|------|---------|---------|
| 顺序消息 | 需要保持消息顺序的业务（如订单处理） | MessageQueueSelector |
| 延迟消息 | 定时任务、延时处理 | delayTimeLevel |
| 事务消息 | 需要保证本地事务和消息发送原子性的场景 | TransactionListener |
| 批量消息 | 高吞吐量、大数据量场景 | ListSplitter |
| 消息过滤 | 只消费感兴趣的消息，减少无效开销 | Tag / SQL92 |

合理使用这些特性可以显著提升系统的可靠性和性能。
