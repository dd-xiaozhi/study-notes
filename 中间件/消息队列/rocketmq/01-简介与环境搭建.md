# 第1章-RocketMQ 简介与环境搭建

## 1.1 消息队列概述

消息队列（Message Queue，简称 MQ）是一种进程间通信或同一进程不同组件之间通信的中间件，它实现了可靠的异步通信机制。消息队列的核心作用包括：

### 核心作用

1. **解耦**：生产者和消费者之间无需直接交互，通过消息队列进行间接通信。当业务逻辑发生变化时，只需要修改消息生产者和消费者的代码，不会影响对方的逻辑。

2. **异步**：发送方将消息写入队列后即可继续执行后续操作，无需等待消费者处理完成。适合耗时较长的操作，如用户注册后发送邮件、短信通知等。

3. **削峰**：在流量高峰期，消息队列可以暂存大量请求，平滑处理压力。系统可以按自身能力从队列中消费消息，避免瞬时高并发压垮系统。

### 主流消息队列产品对比

| 特性 | RocketMQ | Kafka | RabbitMQ | ActiveMQ |
|------|----------|-------|----------|----------|
| 开发语言 | Java | Scala | Erlang | Java |
| 单机吞吐量 | 十万级 | 百万级 | 万级 | 千级 |
| 延迟 | 毫秒级 | 毫秒级 | 微秒级 | 毫秒级 |
| 事务消息 | 支持 | 支持（仅 Kafka Streams） | 不支持 | 支持 |
| 集群规模 | 支持大规模集群 | 支持大规模集群 | 支持中等规模集群 | 支持大规模集群 |
| 消息堆积 | 亿级 | 百万级 | - | - |

## 1.2 RocketMQ 发展历史与特点

### 发展历史

RocketMQ 是阿里巴巴开源的分布式消息中间件，最初服务于阿里集团内部，于 2017 年正式捐赠给 Apache 软件基金会并成为顶级项目。其发展历程：

- **2012 年**：淘宝内部消息系统 Notify 演进为 MetaQ
- **2013 年**：MetaQ 开源版本发布
- **2015 年**：MetaQ 演变为 RocketMQ，捐赠给 Apache
- **2016 年**：RocketMQ 成为 Apache 孵化项目
- **2017 年**：从 Apache 孵化器毕业，成为顶级项目（TLP）

### 核心特点

1. **纯 Java 实现**：核心代码全部使用 Java 开发，便于企业自行定制和二次开发，降低了技术栈复杂度。

2. **高可用架构**：支持主从复制、多副本同步机制，确保消息服务的高可用性。支持灵活的配置以适应不同的可用性需求。

3. **事务消息支持**：提供完整的事务消息功能，通过半消息机制和事务回查确保分布式事务的一致性。

4. **亿级消息堆积能力**：采用高效的存储设计，支持消息的批量刷盘和顺序写，能够存储海量消息而不影响性能。

5. **丰富的消息类型**：支持普通消息、顺序消息、事务消息、延迟消息等多种消息类型。

6. **强大的过滤功能**：支持基于标签（Tag）和 SQL92 表达式的高级消息过滤。

## 1.3 系统要求与环境准备

### 系统要求

- **JDK 版本**：JDK 8 及以上版本（RocketMQ 5.x 需要 JDK 11+）
- **Maven 版本**：3.6.0 及以上
- **磁盘空间**：根据业务量预估，建议至少 20GB 可用空间
- **操作系统**：Linux、Unix、Mac OS、Windows 均支持

### 环境准备

#### 1. 安装 JDK 8

```bash
# 验证 Java 安装
java -version
javac -version
```

#### 2. 安装 Maven

```bash
# 验证 Maven 安装
mvn -version
```

#### 3. 下载 RocketMQ 二进制包

访问 RocketMQ 官方下载页面：https://rocketmq.apache.org/download/

选择稳定版本（如 5.1.4）下载二进制包：

```bash
wget https://archive.apache.org/dist/rocketmq/5.1.4/rocketmq-all-5.1.4-bin-release.zip

# 或使用 curl
curl -O https://archive.apache.org/dist/rocketmq/5.1.4/rocketmq-all-5.1.4-bin-release.zip
```

## 1.4 单机模式部署

### 详细部署步骤

#### 步骤 1：解压二进制包

```bash
# Linux/Mac 系统
unzip rocketmq-all-5.1.4-bin-release.zip
cd rocketmq-all-5.1.4-bin-release

# Windows 系统（使用 7-Zip 或 WinRAR 解压）
# 解压到指定目录，如 D:\rocketmq
```

#### 步骤 2：设置环境变量（可选）

```bash
# Linux/Mac 系统 - 编辑 ~/.bashrc 或 ~/.bash_profile
export ROCKETMQ_HOME=/path/to/rocketmq-all-5.1.4-bin-release
export PATH=$PATH:$ROCKETMQ_HOME/bin

# Windows 系统 - 添加系统环境变量
# ROCKETMQ_HOME = D:\rocketmq\rocketmq-all-5.1.4-bin-release
# PATH 添加 %ROCKETMQ_HOME%\bin
```

#### 步骤 3：启动 NameServer

NameServer 是 RocketMQ 的路由管理服务，所有 Producer 和 Consumer 通过 NameServer 获取主题的路由信息。

```bash
# Linux/Mac 系统
cd rocketmq-all-5.1.4-bin-release
nohup ./bin/mqnamesrv &

# Windows 系统
./bin/mqnamesrv.cmd
```

验证 NameServer 启动成功：

```bash
# 查看日志
tail -f ~/logs/rocketmqlogs/namesrv.log

# 正常输出应包含：
# The Name Server boot success...
```

#### 步骤 4：启动 Broker

Broker 是 RocketMQ 的核心消息服务组件，负责消息的存储、转发和拉取。

```bash
# Linux/Mac 系统
nohup ./bin/mqbroker -n localhost:9876 &

# Windows 系统
./bin/mqbroker.cmd -n localhost:9876
```

验证 Broker 启动成功：

```bash
# 查看日志
tail -f ~/logs/rocketmqlogs/broker.log

# 正常输出应包含：
# The broker[xxx, 192.168.x.x:10911] boot success...
```

#### 步骤 5：验证部署

可以使用 RocketMQ 提供的管理工具验证集群状态：

```bash
# 列出所有主题
./bin/mqadmin topicList -n localhost:9876

# 查看集群状态
./bin/mqadmin clusterList -n localhost:9876
```

### 停止服务

```bash
# 停止 Broker
./bin/mqshutdown broker

# 停止 NameServer
./bin/mqshutdown namesrv
```

## 1.5 快速入门示例

### 环境说明

本示例使用 RocketMQ Java SDK 进行消息发送和消费演示。

### 添加 Maven 依赖

```xml
<dependency>
    <groupId>org.apache.rocketmq</groupId>
    <artifactId>rocketmq-client</artifactId>
    <version>5.1.4</version>
</dependency>
```

### 消息发送者（Producer）示例

```java
import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.client.producer.SendResult;
import org.apache.rocketmq.common.message.Message;
import org.apache.rocketmq.remoting.common.REMotingUtil;

public class ProducerExample {
    public static void main(String[] args) throws Exception {
        // 1. 创建消息生产者，指定生产组名
        DefaultMQProducer producer = new DefaultMQProducer("my-producer-group");

        // 2. 设置 NameServer 地址
        producer.setNamesrvAddr("localhost:9876");

        // 3. 启动生产者实例
        producer.start();

        try {
            // 4. 创建消息对象，指定主题、标签和消息内容
            Message message = new Message(
                "TopicTest",      // 主题
                "TagA",           // 标签，用于消息过滤
                "Hello RocketMQ".getBytes()  // 消息内容
            );

            // 5. 发送消息
            SendResult sendResult = producer.send(message);

            // 6. 输出发送结果
            System.out.printf("发送状态: %s, 消息ID: %s%n",
                sendResult.getSendStatus(),
                sendResult.getMsgId());
        } finally {
            // 7. 关闭生产者
            producer.shutdown();
        }
    }
}
```

### 消息消费者（Consumer）示例

```java
import org.apache.rocketmq.client.consumer.DefaultMQPushConsumer;
import org.apache.rocketmq.client.consumer.listener.ConsumeConcurrentlyStatus;
import org.apache.rocketmq.client.consumer.listener.MessageListenerConcurrently;
import org.apache.rocketmq.common.message.MessageExt;

public class ConsumerExample {
    public static void main(String[] args) throws Exception {
        // 1. 创建消息消费者，指定消费组名
        DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("my-consumer-group");

        // 2. 设置 NameServer 地址
        consumer.setNamesrvAddr("localhost:9876");

        // 3. 订阅主题，指定标签过滤（* 表示接收所有标签）
        consumer.subscribe("TopicTest", "*");

        // 4. 注册消息回调处理函数
        consumer.registerMessageListener(new MessageListenerConcurrently() {
            @Override
            public ConsumeConcurrentlyStatus consumeMessage(
                    java.util.List<MessageExt> msgs,
                    ConsumeConcurrentlyContext context) {

                for (MessageExt msg : msgs) {
                    String topic = msg.getTopic();
                    String tags = msg.getTags();
                    String body = new String(msg.getBody());
                    System.out.printf("收到消息 - 主题: %s, 标签: %s, 内容: %s%n",
                        topic, tags, body);
                }
                // 返回消费成功状态
                return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
            }
        });

        // 5. 启动消费者
        consumer.start();

        System.out.println("消费者启动成功，等待消息...");

        // 保持主线程运行，以便持续消费消息
        // Thread.sleep(Long.MAX_VALUE);

        // 6. 关闭消费者（实际应用中通常不关闭）
        // consumer.shutdown();
    }
}
```

### 顺序消息示例

RocketMQ 支持严格的消息顺序，发送和消费都按 FIFO 顺序进行：

```java
import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.client.producer.MessageQueueSelector;
import org.apache.rocketmq.common.message.Message;
import org.apache.rocketmq.common.message.MessageQueue;

public class OrderedProducerExample {
    public static void main(String[] args) throws Exception {
        DefaultMQProducer producer = new DefaultMQProducer("ordered-producer-group");
        producer.setNamesrvAddr("localhost:9876");
        producer.start();

        String[] tags = {"TagA", "TagB", "TagC"};
        for (int i = 0; i < 10; i++) {
            Message message = new Message(
                "TopicTestOrdered",
                tags[i % tags.length],
                "OrderID-" + i,
                ("订单消息 " + i).getBytes()
            );

            // 使用 MessageQueueSelector 指定消息发送到哪个队列
            // 相同的 OrderID 会被发送到相同的队列，从而保证顺序
            producer.send(message, new MessageQueueSelector() {
                @Override
                public MessageQueue select(java.util.List<MessageQueue> mqs,
                                            Message msg, Object arg) {
                    String orderId = (String) arg;
                    int index = Math.abs(orderId.hashCode()) % mqs.size();
                    return mqs.get(index);
                }
            }, "OrderID-" + (i % 5)); // 5 个订单ID，保证相同订单消息顺序
        }

        producer.shutdown();
        System.out.println("顺序消息发送完成");
    }
}
```

1. 确保 NameServer 和 Broker 已启动

### 常见问题排查

1. **NameServer 连接失败**
   - 确认 NameServer 已启动：`jps` 命令查看是否有 `NamesrvStartup` 进程
   - 检查端口 9876 是否被占用：`netstat -an | grep 9876`

2. **Broker 连接失败**
   - 确认 Broker 已启动并注册到 NameServer
   - 检查 Broker 配置的 NameServer 地址是否正确

3. **消息发送超时**
   - 检查网络连接是否正常
   - 调整 `setSendMsgTimeout()` 超时时间

4. **消费者无法接收消息**
   - 确认消费者订阅的主题与生产者发送的主题一致
   - 检查消费者组是否正确配置
