# Chapter 7: 集群部署与运维

## 7.1 主从架构部署

### 主从架构概念

RocketMQ 的主从架构是为了实现高可用而设计的。主节点（Master）负责处理所有的读写请求，而从节点（Slave）通过同步复制的方式实时备份主节点的数据。当主节点发生故障时，从节点可以接管服务，保证消息的连续性。

**角色说明：**
- **Master**：处理客户端请求，支持读写
- **Slave**：只读，接受 Master 的数据同步
- **同步方式**：同步双写（Sync Master-Slave）和异步复制（Async Master-Slave）

### Broker 配置说明

#### Master Broker 配置

```properties
# broker.conf
brokerClusterName = rocketmq-cluster
brokerName = broker-a
brokerId = 0  # 0 表示 Master，非 0 表示 Slave
listenPort = 10911
namesrvAddr = nameserver1:9876;nameserver2:9876
storePathRootDir = /rocketmq/store-master
storePathCommitLog = /rocketmq/store-master/commitlog
enableAutoCompileIndex = true
```

#### Slave Broker 配置

```properties
# broker.conf
brokerClusterName = rocketmq-cluster
brokerName = broker-a
brokerId = 1  # Slave 的 brokerId 必须大于 0
listenPort = 10912
namesrvAddr = nameserver1:9876;nameserver2:9876
storePathRootDir = /rocketmq/store-slave
storePathCommitLog = /rocketmq/store-slave/commitlog
brokerRole = SLAVE
```

### 部署步骤

**步骤 1：准备 NameServer 集群**

```bash
# 启动第一个 NameServer
nohup sh mqnamesrv -n nameserver1:9876 &

# 启动第二个 NameServer
nohup sh mqnamesrv -n nameserver2:9876 &
```

**步骤 2：启动 Master Broker**

```bash
nohup sh mqbroker -n nameserver1:9876;nameserver2:9876 -c broker-master.conf &
```

**步骤 3：启动 Slave Broker**

```bash
nohup sh mqbroker -n nameserver1:9876;nameserver2:9876 -c broker-slave.conf &
```

**步骤 4：验证部署**

```bash
# 查看集群状态
./mqadmin clusterList -n nameserver1:9876
```

## 7.2 多主多从架构

### Dledger 模式

RocketMQ 4.5 引入了基于 Dledger 的自动主从切换机制。Dledger 使用 Raft 协议实现 Leader 选举和数据同步。

**Dledger 配置示例：**

```properties
# broker-dledger.conf
brokerClusterName = rocketmq-cluster
brokerName = broker-dledger
listenPort = 10911
namesrvAddr = nameserver1:9876;nameserver2:9876;nameserver3:9876

# Dledger 配置
enableDLegerCommitLog = true
dLegerGroup = broker-dledger-group
dLegerPeers = n-0:127.0.0.1:40911;n-1:127.0.0.1:40912;n-2:127.0.0.1:40913
dLegerSelfId = n-0
```

**Dledger 启动命令：**

```bash
nohup sh mqbroker -n nameserver1:9876;nameserver2:9876;nameserver3:9876 -c broker-dledger.conf &
```

### 自动主从切换

当 Master 节点宕机时，Dledger 会在短时间内（通常几秒）通过 Raft 协议选举出新的 Leader，并自动切换。

**故障转移过程：**
1. Dledger 检测到 Leader 不可用
2. 剩余节点发起 Leader 选举
3. 新的 Leader 被选出后，自动对外提供服务
4. 客户端无需任何配置变更

### 配置示例

**三节点 Dledger 集群完整配置：**

```properties
# broker-node1.conf
brokerClusterName = rocketmq-cluster
brokerName = broker-dledger
brokerId = 0
listenPort = 10911
namesrvAddr = nameserver1:9876;nameserver2:9876;nameserver3:9876
enableDLegerCommitLog = true
dLegerGroup = broker-dledger-group
dLegerPeers = n-0:127.0.0.1:40911;n-1:127.0.0.1:40912;n-2:127.0.0.1:40913
dLegerSelfId = n-0
```

```properties
# broker-node2.conf
brokerClusterName = rocketmq-cluster
brokerName = broker-dledger
brokerId = 1
listenPort = 10911
namesrvAddr = nameserver1:9876;nameserver2:9876;nameserver3:9876
enableDLegerCommitLog = true
dLegerGroup = broker-dledger-group
dLegerPeers = n-0:127.0.0.1:40911;n-1:127.0.0.1:40912;n-2:127.0.0.1:40913
dLegerSelfId = n-1
```

```properties
# broker-node3.conf
brokerClusterName = rocketmq-cluster
brokerName = broker-dledger
brokerId = 2
listenPort = 10911
namesrvAddr = nameserver1:9876;nameserver2:9876;nameserver3:9876
enableDLegerCommitLog = true
dLegerGroup = broker-dledger-group
dLegerPeers = n-0:127.0.0.1:40911;n-1:127.0.0.1:40912;n-2:127.0.0.1:40913
```

## 7.3 NameServer 集群

### 多 NameServer 部署

NameServer 是轻量级的服务发现组件，建议部署多个实例以实现高可用。

**部署架构：**
```
┌─────────────────┐
│     Client      │
└────────┬────────┘
         │
    ┌────┴────┬────────────┐
    ▼         ▼            ▼
┌────────┐ ┌────────┐ ┌────────┐
│NameSrv1│ │NameSrv2│ │NameSrv3│
└───┬────┘ └───┬────┘ └───┬────┘
    │          │          │
    └──────────┴──────────┘
           互不影响
```

**启动多个 NameServer：**

```bash
# NameServer 节点 1
nohup sh mqnamesrv -n 192.168.1.101:9876 &

# NameServer 节点 2
nohup sh mqnamesrv -n 192.168.1.102:9876 &

# NameServer 节点 3
nohup sh mqnamesrv -n 192.168.1.103:9876 &
```

### 客户端配置

**Producer 配置：**

```java
public class ClusterProducer {
    public static void main(String[] args) {
        // 配置多个 NameServer 地址
        DefaultMQProducer producer = new DefaultMQProducer("my-producer-group");
        producer.setNamesrvAddr("192.168.1.101:9876;192.168.1.102:9876;192.168.1.103:9876");
        producer.start();

        // 发送消息时无需指定具体的 Broker
        Message msg = new Message("TopicTest", "TagA", "Hello RocketMQ".getBytes());
        producer.send(msg);

        producer.shutdown();
    }
}
```

**Consumer 配置：**

```java
public class ClusterConsumer {
    public static void main(String[] args) {
        // 配置多个 NameServer 地址
        DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("my-consumer-group");
        consumer.setNamesrvAddr("192.168.1.101:9876;192.168.1.102:9876;192.168.1.103:9876");
        consumer.subscribe("TopicTest", "*");
        consumer.registerMessageListener((MessageListenerConcurrently) (msgs, context) -> {
            for (MessageExt msg : msgs) {
                System.out.println(new String(msg.getBody()));
            }
            return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
        });
        consumer.start();
    }
}
```

**Spring Boot 配置：**

```yaml
rocketmq:
  name-server: 192.168.1.101:9876;192.168.1.102:9876;192.168.1.103:9876
  producer:
    group: my-producer-group
```

## 7.4 常用运维命令

### mqadmin 工具介绍

`mqadmin` 是 RocketMQ 提供的命令行管理工具，位于 `bin/mqadmin` 目录下。

**常用命令一览：**

| 命令 | 说明 |
|------|------|
| clusterList | 查看集群信息 |
| topicList | 查看所有 Topic |
| topicRoute | 查看 Topic 的路由信息 |
| statsAll | 查看 Topic 和 Consumer 的状态 |
| consumerProgress | 查看消费者消费进度 |

### 创建 Topic

**命令格式：**

```bash
./mqadmin updateTopic -n nameserver1:9876 -c clusterName -t TopicName
```

**示例：**

```bash
# 创建 Topic
./mqadmin updateTopic -n 192.168.1.101:9876 -c rocketmq-cluster -t my-topic

# 创建读写队列
./mqadmin updateTopic -n 192.168.1.101:9876 -c rocketmq-cluster -t my-topic -r 8 -w 8

# 为特定 Broker 创建 Topic
./mqadmin updateTopic -n 192.168.1.101:9876 -b broker-a -t my-topic
```

**参数说明：**
- `-n`：NameServer 地址
- `-c`：集群名称
- `-t`：Topic 名称
- `-r`：读队列数量
- `-w`：写队列数量
- `-b`：指定的 Broker 名称

### 查看集群状态

```bash
# 查看集群列表
./mqadmin clusterList -n nameserver1:9876

# 输出示例：
# Cluster Name     # Broker Name  # Broker Addr         # Broker Role # Gra # Version
# rocketmq-cluster broker-a      192.168.1.101:10911     # Master      123  V4.x.x
# rocketmq-cluster broker-a      192.168.1.102:10912     # Slave       123  V4.x.x
```

```bash
# 查看 Topic 路由信息
./mqadmin topicRoute -n nameserver1:9876 -t my-topic

# 查看所有 Topic
./mqadmin topicList -n nameserver1:9876

# 查看 Topic 状态
./mqadmin statsAll -n nameserver1:9876
```

### 常见运维操作

**消费者组管理：**

```bash
# 查看消费者组状态
./mqadmin consumerProgress -n nameserver1:9876 -g my-consumer-group

# 查看消费者连接信息
./mqadmin consumerConnection -n nameserver1:9876 -g my-consumer-group
```

**Broker 管理：**

```bash
# 查看 Broker 上的主题
./mqadmin topicStatus -n nameserver1:9876 -t my-topic

# 查看 Broker 配置
./mqadmin brokerStatus -n nameserver1:9876 -b broker-a

# 调整 Broker 权重（权值 Broker）
./mqadmin updateBrokerConfig -n nameserver1:9876 -b broker-a -k brokerPermission -v 6
```

**消息查询：**

```bash
# 根据消息 Key 查询
./mqadmin queryMsgByKey -n nameserver1:9876 -t my-topic -k msgKey

# 根据消息 Offset 查询
./mqadmin queryMsgByOffset -n nameserver1:9876 -b broker-a -t my-topic -i 1234

# 根据消息 ID 查询
./mqadmin queryMsgById -n nameserver1:9876 -i msgId
```

**存储管理：**

```bash
# 查看 CommitLog 文件
./mqadmin examineCommitLog -n nameserver1:9876 -b broker-a

# 查看 ConsumeQueue 文件
./mqadmin examineConsumeQueue -n nameserver1:9876 -b broker-a

# 清理过期消息
./mqadmin cleanExpiredCQ -n nameserver1:9876 -c clusterName
```

**权限管理（ACL）：**

```bash
# 查看 ACL 配置
./mqadmin accessDeploy -n nameserver1:9876 -s

# 更新 ACL 权限
./mqadmin updateAccessConfig -n nameserver1:9876 -b broker-a -a accessKey -s secretKey
```

## 小结

本章介绍了 RocketMQ 集群部署与运维的核心内容：

1. **主从架构**：通过 Master-Slave 模式实现数据备份，支持同步和异步复制
2. **多主多从**：Dledger 模式实现自动主从切换，基于 Raft 协议保证一致性
3. **NameServer 集群**：多节点部署确保服务发现的高可用
4. **运维工具**：mqadmin 提供了丰富的命令支持日常运维操作

在实际生产环境中，建议：
- 至少部署 3 个 NameServer 节点
- 使用 Dledger 模式实现自动故障转移
- 定期监控集群状态和消息积压情况
- 做好数据备份和灾难恢复预案
