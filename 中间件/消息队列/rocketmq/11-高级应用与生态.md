# Chapter 11: 高级应用与生态

## 11.1 消息轨迹追踪

### 消息轨迹概念

消息轨迹（Message Trace）是 RocketMQ 提供的重要功能，用于追踪消息从生产到消费的完整生命周期。通过消息轨迹，开发人员可以清晰地了解每条消息的发送时间、处理耗时、消费状态等关键信息，帮助实现消息可靠性的端到端监控和问题排查。

RocketMQ 的消息轨迹基于其事务消息机制实现，在消息发送和消费的各个关键节点记录轨迹数据。轨迹数据默认存储在 RocketMQ 内置的轨迹 Topic 中，也可以配置存储到独立的集群或第三方存储系统。

### 开启消息轨迹

消息轨迹功能默认关闭，需要通过配置手动开启。在 broker.conf 配置文件中添加以下配置：

```properties
# 开启消息轨迹功能
traceTopicEnable=true

# 轨迹 Topic 的名称，默认值为 SCHEDULE_TOPIC_XXXX
# 可以自定义轨迹Topic名称
traceTopicName=RMQ_SYS_TRACE_TOPIC

# 轨迹消息的可丢弃比例（0-100），用于在轨迹消息积压时选择性丢弃
traceMaxMsgSize=128
```

生产者开启轨迹：

```java
import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.client.trace.TraceBean;
import org.apache.rocketmq.client.trace.TraceContext;
import org.apache.rocketmq.common.message.Message;

DefaultMQProducer producer = new DefaultMQProducer("ProducerGroup");
producer.setNamesrvAddr("namesrv:9876");
// 开启消息轨迹
producer.setEnableMsgTrace(true);
// 自定义轨迹Topic（可选）
producer.setCustomizedTraceTopic("my-trace-topic");
producer.start();

Message msg = new Message("Topic", "tags", "keys", "body".getBytes());
// 发送消息，消息轨迹会被自动采集
producer.send(msg);
```

消费者开启轨迹：

```java
import org.apache.rocketmq.client.consumer.DefaultMQPushConsumer;
import org.apache.rocketmq.client.trace.ConsumeTraceContext;

DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("ConsumerGroup");
consumer.setNamesrvAddr("namesrv:9876");
// 开启消息轨迹
consumer.setEnableMsgTrace(true);
consumer.setCustomizedTraceTopic("my-trace-topic");
consumer.subscribe("Topic", "*");
consumer.registerMessageListener((msgs, context) -> {
    // 消费逻辑
    return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
});
consumer.start();
```

RocketMQ 提供了三种查询消息轨迹的方式：

**1. 使用 RocketMQ Dashboard 查询**

通过 RocketMQ 提供的 Web 控制台，可以图形化地查询消息轨迹：

```bash

```

**2. 使用命令查询**

```bash
# 查询轨迹消息
mqadmin searchMsg -t RMQ_SYS_TRACE_TOPIC -k <msgKey>

# 查看消息轨迹详情
mqadmin queryMsgByUniqueKey -t <topic> -k <msgKey>
```

**3. 程序化查询**

```java
import org.apache.rocketmq.tools.admin.DefaultMQAdminExt;

DefaultMQAdminExt admin = new DefaultMQAdminExt();
admin.start();

// 根据时间范围查询轨迹
List<TraceView> traces = admin.queryMessagesByTimeRange(
    "Topic", startTime, endTime);

for (TraceView trace : traces) {
    System.out.println("MsgId: " + trace.getMsgId());
    System.out.println("ProducerAddr: " + trace.getProducerAddr());
    System.out.println("CostTime: " + trace.getCostTime() + "ms");
    System.out.println("Status: " +ackTrace.getStatus());
```

### 使用示例

完整的消息轨迹使用示例：

```java
public class MessageTraceExample {
    public static void main(String[] args) throws Exception {
        // 1. 创建带轨迹的生产者
        DefaultMQProducer producer = new DefaultMQProducer("PG");
        producer.setNamesrvAddr("localhost:9876");
        producer.setEnableMsgTrace(true);
        producer.start();

        // 2. 发送消息
        Message msg = new Message("DemoTopic", "Hello RocketMQ".getBytes());
        msg.setKeys("trace-demo");
        SendResult result = producer.send(msg);
        System.out.println("消息发送成功: " + result.getMsgId());

        // 3. 创建带轨迹的消费者
        DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("CG");
        consumer.setNamesrvAddr("localhost:9876");
        consumer.setEnableMsgTrace(true);
        consumer.subscribe("DemoTopic", "*");
        consumer.registerMessageListener((msgs, context) -> {
            for (MessageExt msg : msgs) {
                System.out.println("消费消息: " + new String(msg.getBody()));
            }
            return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
        });
        consumer.start();

        // 4. 通过 Admin API 查询轨迹
        DefaultMQAdminExt admin = new DefaultMQAdminExt();
        admin.start();
        TraceView[] traces = admin.queryMessageTraceByMsgId(
            "DemoTopic", result.getMsgId());

        System.out.println("轨迹点数量: " + traces.length);
        for (TraceView trace : traces) {
            System.out.printf("节点类型: %s, 地址: %s, 时间: %d%n",
                trace.getTraceType(), trace.getTime(), trace.getClientHost());
        }

        Thread.sleep(5000);
        producer.shutdown();
        consumer.shutdown();
        admin.shutdown();
    }
}
```

## 11.2 ACL 权限控制

### ACL 概念

ACL（Access Control List，访问控制列表）是 RocketMQ 提供的细粒度权限管理机制。ACL 功能允许管理员为不同的用户或应用分配不同的权限，控制其对消息队列资源的访问和操作能力，从而实现安全的多租户隔离。

RocketMQ 的 ACL 主要包括以下权限类型：

| 权限类型 | 说明 |
|---------|------|
| DENY | 拒绝访问 |
| PUB | 发送消息权限 |
| SUB | 订阅消息权限 |
| CON | 消费消息权限（含订阅） |

### 权限配置

ACL 权限配置采用 YAML 格式，默认配置文件为 `${ROCKETMQ_HOME}/conf/plain_acl.yml`：

```yaml
accounts:
  # 管理员账户，拥有所有权限
  - accessKey: admin
    secretKey: admin123
    whiteRemoteAddress:
    admin: true
    defaultGroupPerms:
      - group: *
        permission: PUB|SUB|CON

  # 生产者账户，只能发送消息
  - accessKey: producer_user
    secretKey: producer123
    whiteRemoteAddress: 192.168.1.*
    permission: PUB

  # 消费者账户，只能消费消息
  - accessKey: consumer_user
    secretKey: consumer123
    whiteRemoteAddress:
    permission: SUB|CON

  # 特定Topic权限配置
  - accessKey: limited_user
    secretKey: limited123
    defaultGroupPerms: []
    topicPerms:
      - topic: ExampleTopic
        permission: PUB|SUB|CON
      - topic: ImportantTopic
        permission: PUB
      - topic: InternalTopic
        permission: DENY
```

### 启用 ACL

**Broker 端配置**

在 broker.conf 中添加 ACL 插件：

```properties
# 开启 ACL 权限控制
aclEnable=true

# 指定 ACL 配置文件路径
aclPlainPairFilterFiles=/path/to/plain_acl.yml

# 或者使用静态配置（5.0版本支持）
# aclEnable=true
```

**依赖配置**

如果使用云服务或需要程序化配置，需要在客户端添加 ACL 依赖：

```xml
<dependency>
    <groupId>org.apache.rocketmq</groupId>
    <artifactId>rocketmq-acl</artifactId>
    <version>5.0.0</version>
</dependency>
```

### 使用示例

**生产者 ACL 配置**

```java
import org.apache.rocketmq.client.producer.DefaultMQProducer;
import org.apache.rocketmq.common.heartbeat.SubscriptionData;

DefaultMQProducer producer = new DefaultMQProducer("ProducerGroup");
// ACL 认证信息
producer.setAccessKey("producer_user");
producer.setSecretKey("producer123");
// 设置允许发送的Topic白名单
producer.setTopicWithNamespaces(Collections.singletonList("ExampleTopic"));
producer.start();
```

**消费者 ACL 配置**

```java
import org.apache.rocketmq.client.consumer.DefaultMQPushConsumer;
import org.apache.rocketmq.client.Impl.*;

DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("ConsumerGroup");
// ACL 认证信息
consumer.setAccessKey("consumer_user");
consumer.setSecretKey("consumer123");
// 设置允许订阅的Topic白名单
consumer.setTopicWithNamespaces(Collections.singletonList("ExampleTopic"));
consumer.subscribe("ExampleTopic", "*");
consumer.start();
```

**动态 ACL 配置更新**

RocketMQ 支持运行时动态更新 ACL 配置，无需重启 Broker：

```java
import org.apache.rocketmq.tools.admin.RMQTools;

RmqSysFlag flag = new RMQTools();
flag.updateAclConfig(new PlainAccessConfig()
    .setAccessKey("new_user")
    .setSecretKey("new_secret")
    .setTopicPerms(Arrays.asList("TopicA:PUB", "TopicB:SUB"))
);
```

## 11.3 RocketMQ 与其他中间件集成

### Spring Cloud Stream 集成

Spring Cloud Stream 是 Spring 官方提供的消息中间件集成框架，RocketMQ 提供 了完整的 Spring Cloud Stream Binder 实现。

**添加依赖**

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-stream</artifactId>
    </dependency>
    <dependency>
        <groupId>org.apache.rocketmq</groupId>
        <artifactId>rocketmq-stream-spring-cloud-starter</artifactId>
        <version>5.0.0</version>
    </dependency>
</dependencies>
```

**配置 application.yml**

```yaml
spring:
  application:
    name: rocketmq-demo
  cloud:
    stream:
      rocketmq:
        binder:
          namesrv-addr: localhost:9876
          # 分组配置
          group: my-group
      bindings:
        output:
          destination: stream-demo-output
          content-type: application/json
        input:
          destination: stream-demo-input
          content-type: application/json
          group: stream-demo-group
```

**生产者代码**

```java
import org.springframework.cloud.stream.annotation.EnableBinding;
import org.springframework.cloud.stream.messaging.Source;

@EnableBinding(Source.class)
public class RocketMQProducer {

    @Autowired
    private Source source;

    public void sendMessage(String message) {
        source.output().send(MessageBuilder
            .withPayload(message)
            .setHeader(MessageHeaders.CONTENT_TYPE, "application/json")
            .build());
    }
}
```

**消费者代码**

```java
import org.springframework.cloud.stream.annotation.EnableBinding;
import org.springframework.cloud.stream.annotation.StreamListener;
import org.springframework.cloud.stream.messaging.Sink;

@EnableBinding(Sink.class)
public class RocketMQConsumer {

    @StreamListener(Sink.INPUT)
    public void receiveMessage(String message) {
        System.out.println("Received message: " + message);
    }
}
```

### Kafka 迁移到 RocketMQ

RocketMQ 提供了 Kafka 协议适配层，允许部分 Kafka 应用零代码修改迁移到 RocketMQ。

**Kafka 协议兼容配置**

在 broker.conf 中开启 Kafka 协议支持：

```properties
# 开启 Kafka 协议兼容
enableKafkaProxy=true
# Kafka 协议监听端口
kafkaProxyPort=9092
# 设置 Kafka 集群的 Broker 数量（用于分区协商）
kafkaClusterMinBrokerSize=3
```

**Kafka 生产者迁移**

原有的 Kafka 生产者代码无需修改，只需更换 bootstrap.servers：

```properties
# 原 Kafka 配置
bootstrap.servers=localhost:9092
security.protocol=PLAINTEXT

# 迁移后 RocketMQ 配置
bootstrap.servers=localhost:9092  # RocketMQ 的 Kafka 兼容端口
security.protocol=PLAINTEXT
```

**Kafka 消费者迁移**

```java
import org.apache.kafka.clients.consumer.KafkaConsumer;

Properties props = new Properties();
props.put("bootstrap.servers", "localhost:9092");  // RocketMQ Kafka兼容端口
props.put("group.id", "kafka-migration-group");
props.put("key.deserializer", "org.apache.kafka.common.serialization.StringDeserializer");
props.put("value.deserializer", "org.apache.kafka.common.serialization.StringDeserializer");
props.put("security.protocol", "PLAINTEXT");

KafkaConsumer<String, String> consumer = new KafkaConsumer<>(props);
consumer.subscribe(Collections.singletonList("original-kafka-topic"));

// 后续消费逻辑保持不变
while (true) {
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
    for (ConsumerRecord<String, String> record : records) {
        System.out.printf("offset=%d, key=%s, value=%s%n",
            record.offset(), record.key(), record.value());
    }
}
```

**迁移注意事项**

1. Kafka 与 RocketMQ 的消息模型存在差异，事务消息、精确一次语义等功能需要额外适配
2. 分区与队列的概念不同，迁移后需要重新评估分区策略
3. 监控指标格式不同，需要配置对应的监控适配器

### 与 Canal 集成实现数据库 CDC

Canal 是阿里巴巴开源的 MySQL binlog 增量订阅和消费组件，可以与 RocketMQ 结合实现数据库变更数据捕获（CDC）。

**架构原理**

```
MySQL -> Canal Server -> Canal Client -> RocketMQ -> 应用消费
```

**Canal 配置**

```properties
# canal.properties
canal.serverMode = rocketmq
canal.rocketmq.namesrvAddr = localhost:9876
canal.rocketmq.topic = canal-mysql-sync
canal.rocketmq.filter = .*\\..*
```

**MySQL 表结构**

```sql
CREATE TABLE products (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(10,2),
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

**RocketMQ 消费者接收 CDC 数据**

```java
import org.apache.rocketmq.client.consumer.DefaultMQPushConsumer;
import org.apache.rocketmq.common.message.MessageExt;
import com.alibaba.otter.canal.protocol.FlatMessage;

DefaultMQPushConsumer consumer = new DefaultMQPushConsumer("canal-cdc-consumer");
consumer.setNamesrvAddr("localhost:9876");
consumer.subscribe("canal-mysql-sync", "*");

consumer.registerMessageListener((msgs, context) -> {
    for (MessageExt msg : msgs) {
        // Canal 消息体为 FlatMessage（JSON 格式）
        FlatMessage flatMessage = JSON.parseObject(
            new String(msg.getBody()), FlatMessage.class);

        String table = flatMessage.getTable();
        List<Map<String, String>> data = flatMessage.getData();

        System.out.println("表: " + table);
        for (Map<String, String> row : data) {
            System.out.println("变更数据: " + row);
        }
    }
    return ConsumeConcurrentlyStatus.CONSUME_SUCCESS;
});
consumer.start();
```

**CDC 数据格式示例**

```json
{
    "id": 1,
    "type": "INSERT",  // INSERT/UPDATE/DELETE
    "database": "shop",
    "table": "products",
    "ts": 1625123456789,
    "data": [
        {"id": "1001", "name": "iPhone", "price": "6999.00"}
    ],
    "old": []  // UPDATE/DELETE 时有旧值
}
```

### 与 Dubbo 微服务集成

Dubbo 是阿里巴巴开源的高性能 RPC 框架，RocketMQ 可作为 Dubbo 的异步通信中间件，实现微服务间的高效异步通信。

**Dubbo 配置**

```xml
<dubbo:reference id="orderService" interface="com.example.OrderService">
    <dubbo:method name="createOrder" timeout="5000"/>
</dubbo:reference>

<!-- RocketMQ 协议配置 -->
<dubbo:protocol name="rocketmq"
    port="20881"
    host="localhost"
    parameters="accessKey:xxx,secretKey:yyy,namesrvAddr:localhost:9876"/>
```

**服务接口定义**

```java
public interface OrderService {
    // 同步调用
    Order createOrder(OrderDTO order);

    // 异步调用，返回 Future
    CompletableFuture<Order> createOrderAsync(OrderDTO order);
}
```

**异步消息发送示例**

```java
import org.apache.rocketmq.spring.core.RocketMQTemplate;
import org.springframework.beans.factory.annotation.Autowired;

@Service
public class OrderServiceImpl implements OrderService {

    @Autowired
    private RocketMQTemplate rocketMQTemplate;

    @Override
    public CompletableFuture<Order> createOrderAsync(OrderDTO orderDTO) {
        return CompletableFuture.supplyAsync(() -> {
            // 构造消息
            Message<OrderDTO> message = MessageBuilder
                .withPayload(orderDTO)
                .setHeader("orderType", "ASYNC")
                .build();

            // 发送消息到延迟队列（模拟异步处理）
            rocketMQTemplate.asyncSend("order-topic", message,
                new SendCallback() {
                    @Override
                    public void onSuccess(SendResult sendResult) {
                        System.out.println("订单消息发送成功: "
                            + sendResult.getMsgId());
                    }

                    @Override
                    public void onException(Throwable e) {
                        System.err.println("订单消息发送失败: " + e.getMessage());
                    }
                });

            // 返回处理中的订单
            return new Order()
                .setStatus(OrderStatus.PROCESSING)
                .setOrderId(generateOrderId());
        });
    }
}
```

**Dubbo 消费者使用 RocketMQ 事件驱动**

```java
@DubboService
public class PaymentServiceImpl implements PaymentService {

    @Autowired
    private RocketMQTemplate rocketMQTemplate;

    @RocketMQMessageListener(
        topic = "order-topic",
        consumerGroup = "payment-consumer-group",
        selectorExpression = "*"
    )
    public void onOrderMessage(Message msg) {
        OrderDTO order = (OrderDTO) msg.getPayload();
        // 处理支付逻辑
        processPayment(order);
    }
}
```

## 本章小结

本章介绍了 RocketMQ 的高级应用与生态系统的几个重要方面：

1. **消息轨迹追踪**：通过开启 traceTopicEnable 配置，可以完整追踪消息从生产到消费的全过程，帮助快速定位消息丢失或延迟问题。

2. **ACL 权限控制**：RocketMQ 提供基于 YAML 的细粒度权限管理，支持对不同用户配置 Topic 和 ConsumerGroup 级别的访问权限，实现多租户安全隔离。

3. **生态集成**：
   - Spring Cloud Stream 提供了标准化的消息抽象，RocketMQ Binder 实现让 Spring 应用可以轻松接入
   - Kafka 协议兼容层允许部分 Kafka 应用零代码迁移
   - Canal 集成实现数据库 CDC，配合 RocketMQ 可构建完整的数据变更同步管道
   - Dubbo 微服务集成通过 RocketMQ 实现高效的异步通信

掌握这些高级特性，能够帮助开发者更好地将 RocketMQ 融入到企业现有的技术架构中，发挥消息队列在分布式系统中的核心枢纽作用。
