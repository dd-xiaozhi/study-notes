# Chapter 10: 分布式事务实战

## 10.1 事务消息实现原理

### 两阶段提交

事务消息采用两阶段提交协议来保证分布式事务的一致性：

**第一阶段（Prepare 阶段）**：
- 生产者发送半消息（Half Message）到 RocketMQ 服务端
- 此时消息被标记为"暂不可投递"状态，消费者无法看到
- 服务端持久化该消息，返回 prepare 成功确认

**第二阶段（Commit/Rollback 阶段）**：
- 生产者执行本地事务逻辑
- 根据本地事务执行结果，调用 commit 或 rollback
- commit：消息变为可投递状态，消费者可见
- rollback：消息被删除，不可见

```
生产端                        RocketMQ服务端                    消费端
   │                              │                              │
   │---发送Half Message----------->│                              │
   │<-返回 Prepare OK ------------│                              │
   │                              │                              │
   │（执行本地事务）               │                              │
   │                              │                              │
   │---提交/回滚------------------>│                              │
   │                              │---投递消息------------------->│
   │                              │                              │
```

### 本地事务执行

生产者在发送事务消息前，需要先绑定一个本地事务监听器（TransactionListener）：

```java
TransactionListener transactionListener = new TransactionListener() {
    @Override
    public LocalTransactionState executeLocalTransaction(Message msg, Object arg) {
        // 执行本地业务逻辑
        // 例如：创建订单、扣减库存等
        try {
            // 业务处理
            orderService.createOrder(msg);
            return LocalTransactionState.COMMIT_MESSAGE;
        } catch (Exception e) {
            return LocalTransactionState.ROLLBACK_MESSAGE;
        }
    }

    @Override
    public LocalTransactionState checkLocalTransaction(MessageExt msg) {
        // 回查接口，用于解决一阶段后生产者宕机的情况
        // 查询本地事务是否执行成功
        String transactionId = msg.getTransactionId();
        boolean committed = transactionLogService.isCommitted(transactionId);
        return committed ? LocalTransactionState.COMMIT_MESSAGE
                         : LocalTransactionState.ROLLBACK_MESSAGE;
    }
};
```

### 回查机制

回查机制是解决生产者发送 Prepare 消息后宕机的关键机制：

**触发场景**：
- 生产者发送 Prepare 消息后宕机
- 本地事务执行成功但提交/回滚指令未送达 RocketMQ

**回查流程**：
1. RocketMQ 服务端等待超时（默认 60 秒）
2. 向生产者查询事务状态
3. 生产者根据本地事务日志判断事务最终状态
4. 根据查询结果提交或回滚消息

**配置回查**：
```java
// 事务消息回查间隔，默认 1000ms
transactionCheckInterval = 3000
// 事务消息回查最大次数，默认 15 次
transactionCheckMax = 10
// 事务消息回查时间间隔，默认 60 秒
transactionTimeout = 60000
```

### 事务状态

RocketMQ 定义了三种事务状态：

| 状态 | 说明 | 消息处理 |
|------|------|----------|
| `COMMIT_MESSAGE` | 本地事务执行成功 | 提交消息，消费者可见 |
| `ROLLBACK_MESSAGE` | 本地事务执行失败 | 回滚消息，删除 |
| `UNKNOWN` | 状态未知，需要回查 | 等待回查或超时 |

**状态转换**：

```
                    发送 Half Message
                         │
                         ▼
                    ┌─────────┐
                 ──►│ PREPARE │◄──
                    └─────────┘
                         │
              ┌──────────┼──────────┐
              │          │          │
              ▼          ▼          ▼
        ┌─────────┐ ┌─────────┐ ┌─────────┐
        │ COMMIT  │ │ ROLLBACK│ │ UNKNOWN │
        └─────────┘ └─────────┘ └─────────┘
              │          │          │
              │          │          ▼
              │          │    ┌───────────┐
              │          └───►│ 回查机制   │
              │               └───────────┘
              │                     │
              ▼                     ▼
        消息可消费              等待最终状态
```

## 10.2 实战案例

### 场景：电商下单

**业务背景**：
用户在电商平台下单购买商品，需要保证：
1. 订单创建成功
2. 库存扣减成功
3. 库存不足时订单不创建
4. 任意环节失败时数据一致

**核心流程**：

```
┌─────────┐    ┌─────────────┐    ┌───────────┐    ┌────────────┐
│  用户   │───►│ 创建订单    │───►│ 扣减库存  │───►│ 发送消息   │
│  下单   │    │ (本地事务)  │    │ (远程调用) │    │ (事务消息) │
└─────────┘    └─────────────┘    └───────────┘    └────────────┘
                     │                                      │
                     │         ┌──────────────────────┐      │
                     └────────►│   订单服务            │◄─────┘
                               │   (TransactionListener)│
                               └──────────────────────┘
```

### 创建订单（本地事务）

```java
@Service
public class OrderServiceImpl implements OrderService {

    @Autowired
    private OrderMapper orderMapper;

    @Autowired
    private InventoryService inventoryService;

    @Autowired
    private TransactionLogMapper transactionLogMapper;

    /**
     * 创建订单 - 作为本地事务的一部分
     */
    public void createOrder(OrderDTO orderDTO, String transactionId) {
        // 1. 创建订单记录
        Order order = new Order();
        order.setOrderId(orderDTO.getOrderId());
        order.setUserId(orderDTO.getUserId());
        order.setTotalAmount(orderDTO.getTotalAmount());
        order.setStatus(OrderStatus.CREATED);
        order.setTransactionId(transactionId);
        orderMapper.insert(order);

        // 2. 扣减库存
        boolean inventoryDeducted = inventoryService.deductInventory(
            orderDTO.getProductId(),
            orderDTO.getQuantity()
        );

        if (!inventoryDeducted) {
            throw new BusinessException("库存不足");
        }

        // 3. 记录事务日志（用于回查）
        TransactionLog log = new TransactionLog();
        log.setTransactionId(transactionId);
        log.setStatus("COMMITTED");
        log.setCreateTime(new Date());
        transactionLogMapper.insert(log);
    }
}
```

### 扣减库存（远程调用）

```java
@Service
public class InventoryServiceImpl implements InventoryService {

    @Autowired
    private InventoryMapper inventoryMapper;

    @Autowired
    private InventoryFeignClient inventoryFeignClient;

    /**
     * 扣减库存
     */
    public boolean deductInventory(String productId, Integer quantity) {
        // 先本地扣减
        int rows = inventoryMapper.deductStock(productId, quantity);
        if (rows > 0) {
            return true;
        }

        // 库存不足，尝试远程服务降级处理
        try {
            return inventoryFeignClient.deduct(productId, quantity);
        } catch (Exception e) {
            log.error("远程库存服务调用失败", e);
            return false;
        }
    }
}
```

### 发送事务消息

```java
@Service
public class OrderTransactionService {

    @Autowired
    private RocketMQTemplate rocketMQTemplate;

    @Autowired
    private OrderService orderService;

    /**
     * 创建订单并发送事务消息
     */
    public void createOrderWithTransaction(OrderDTO orderDTO) {
        String transactionId = UUID.randomUUID().toString();

        // 构建消息
        OrderMessage message = new OrderMessage();
        message.setOrderId(orderDTO.getOrderId());
        message.setUserId(orderDTO.getUserId());
        message.setProductId(orderDTO.getProductId());
        message.setQuantity(orderDTO.getQuantity());
        message.setTransactionId(transactionId);

        // 发送事务消息
        // executeLocalTransaction 会在本地执行
        // checkLocalTransaction 用于回查
        rocketMQTemplate.sendMessageInTransaction(
            "order_topic:create_order",  // Topic:Tag
            MessageBuilder.withPayload(JSON.toJSONString(message))
                         .setHeader("transactionId", transactionId)
                         .build(),
            orderDTO  // arg 参数传递给 executeLocalTransaction
        );
    }
}
```

### 完整代码实现

#### 1. 事务监听器实现

```java
@Component
@RocketMQTransactionListener(corePoolSize = 5, maximumPoolSize = 10)
public class OrderTransactionListener implements RocketMQLocalTransactionListener {

    @Autowired
    private OrderService orderService;

    @Autowired
    private OrderMapper orderMapper;

    @Autowired
    private TransactionLogMapper transactionLogMapper;

    @Override
    public RocketMQLocalTransactionState executeLocalTransaction(Message msg, Object arg) {
        String transactionId = msg.getTransactionId();
        OrderDTO orderDTO = (OrderDTO) arg;

        try {
            // 执行本地事务：创建订单 + 扣减库存
            orderService.createOrder(orderDTO, transactionId);
            return RocketMQLocalTransactionState.COMMIT;
        } catch (BusinessException e) {
            // 业务异常，回滚
            log.warn("订单创建失败: {}", e.getMessage());
            return RocketMQLocalTransactionState.ROLLBACK;
        } catch (Exception e) {
            // 系统异常，未知状态，等待回查
            log.error("订单创建异常: {}", e.getMessage(), e);
            return RocketMQLocalTransactionState.UNKNOWN;
        }
    }

    @Override
    public RocketMQLocalTransactionState checkLocalTransaction(MessageExt msg) {
        String transactionId = msg.getTransactionId();

        // 查询事务日志，判断实际状态
        TransactionLog log = transactionLogMapper.findByTransactionId(transactionId);

        if (log == null) {
            // 事务日志不存在，可能本地事务未执行
            return RocketMQLocalTransactionState.ROLLBACK;
        }

        if ("COMMITTED".equals(log.getStatus())) {
            return RocketMQLocalTransactionState.COMMIT;
        } else if ("FAILED".equals(log.getStatus())) {
            return RocketMQLocalTransactionState.ROLLBACK;
        }

        // 状态不明确，可能是超时，继续等待
        return RocketMQLocalTransactionState.UNKNOWN;
    }
}
```

#### 2. 消息消费者

```java
@Component
@RocketMQMessageListener(
    topic = "order_topic",
    selectorExpression = "create_order",
    consumerGroup = "order_consumer_group"
)
public class OrderMessageConsumer implements RocketMQListener<OrderMessage> {

    @Autowired
    private OrderService orderService;

    @Override
    public void onMessage(OrderMessage message) {
        log.info("收到订单创建消息: {}", message);

        try {
            // 1. 幂等检查
            if (orderService.isMessageProcessed(message.getTransactionId())) {
                log.warn("消息已处理，跳过: {}", message.getTransactionId());
                return;
            }

            // 2. 处理订单后续流程（发送通知、更新统计数据等）
            orderService.processOrderPostCreation(message);

            // 3. 标记消息已处理
            orderService.markMessageProcessed(message.getTransactionId());

            log.info("订单消息处理成功: {}", message.getOrderId());

        } catch (Exception e) {
            log.error("订单消息处理失败: {}", e.getMessage(), e);
            // 抛出异常，触发重试
            throw e;
        }
    }
}
```

#### 3. 配置类

```java

    @Bean
    public TransactionListener transactionListener() {
        return new OrderTransactionListener();
    }
}
```

## 10.3 常见问题处理

### 问题一：本地事务成功，消息发送失败

**场景描述**：
本地事务已提交成功，但在发送事务消息时网络中断或 RocketMQ 服务端异常。

**解决方案**：

```java
@Override
public RocketMQLocalTransactionState executeLocalTransaction(Message msg, Object arg) {
    try {
        // 执行本地事务
        orderService.createOrder(orderDTO, transactionId);

        // 尝试发送消息，设置重试机制
        int maxRetries = 3;
        for (int i = 0; i < maxRetries; i++) {
            try {
                SendResult result = rocketMQTemplate.sendMessageInTransaction(
                    "order_topic:create_order",
                    msg,
                    arg
                );
                if (result.getSendStatus() == SendStatus.SEND_OK) {
                    return RocketMQLocalTransactionState.COMMIT;
                }
            } catch (Exception e) {
                log.warn("消息发送失败，第 {} 次重试", i + 1);
                if (i == maxRetries - 1) {
                    // 记录失败日志，用于人工干预
                    transactionFailLogService.record(transactionId, "消息发送失败");
                    return RocketMQLocalTransactionState.UNKNOWN;
                }
            }
        }
        return RocketMQLocalTransactionState.UNKNOWN;

    } catch (Exception e) {
        return RocketMQLocalTransactionState.ROLLBACK;
    }
}
```

**预防措施**：
1. 本地事务和消息发送不要紧耦合
2. 使用事务日志表记录状态，便于回查
3. 监控事务消息发送失败情况，及时告警

### 问题二：消息超时未响应

**场景描述**：
事务消息长时间处于 UNKNOWN 状态，未被提交也未被回滚。

**原因分析**：
1. 生产者执行本地事务时间过长
2. checkLocalTransaction 接口响应慢或超时
3. 网络问题导致回查失败

**解决方案**：

```java
// 1. 配置合理的超时时间
@Bean
public TransactionListener transactionListener(RocketMQProperties properties) {
    TransactionListener listener = new OrderTransactionListener();
    // 事务超时时间，默认 60 秒
    properties.getTransaction().setTransactionTimeout(60);
    // 回查次数
    properties.getTransaction().setTransactionCheckMax(15);
    // 回查间隔
    properties.getTransaction().setTransactionCheckInterval(3000);
    return listener;
}

// 2. checkLocalTransaction 中实现超时处理
@Override
public RocketMQLocalTransactionState checkLocalTransaction(MessageExt msg) {
    String transactionId = msg.getTransactionId();

    TransactionLog log = transactionLogMapper.findByTransactionId(transactionId);

    if (log == null) {
        // 超时未查到日志，默认回滚
        return RocketMQLocalTransactionState.ROLLBACK;
    }

    // 检查事务执行时间
    long elapsed = System.currentTimeMillis() - log.getCreateTime().getTime();
    if (elapsed > 120000) { // 超过 2 分钟
        // 长时间未确认，标记并回滚
        transactionLogMapper.updateStatus(transactionId, "TIMEOUT_ROLLBACK");
        return RocketMQLocalTransactionState.ROLLBACK;
    }

    return "COMMITTED".equals(log.getStatus())
        ? RocketMQLocalTransactionState.COMMIT
        : RocketMQLocalTransactionState.ROLLBACK;
}
```

### 问题三：事务消息限制

**RocketMQ 事务消息的限制**：

| 限制项 | 说明 | 建议 |
|--------|------|------|
| 不支持顺序消息 | 事务消息目前不支持顺序消费 | 业务层面保证幂等 |
| 单消息大小 | 建议消息体不超过 64KB | 较大数据使用压缩或外部存储 |
| 事务超时 | 默认 60 秒 | 根据业务处理时间调整 |
| 回查次数 | 默认 15 次 | 防止无限回查 |
| 不支持批量 | 无法使用批量发送接口 | 单条发送 |

**最佳实践**：

### 问题四：幂等性处理

**场景描述**：
网络异常或消费超时导致消息重复投递，业务需要保证幂等。

**解决方案**：

```java
@Component
public class IdempotentProcessor {

    @Autowired
    private RedisTemplate redisTemplate;

    /**
     * 尝试获取幂等锁
     */
    public boolean tryLock(String transactionId, long expireSeconds) {
        Boolean result = redisTemplate.opsForValue()
            .setIfAbsent("idempotent:" + transactionId, "1",
                Duration.ofSeconds(expireSeconds));
        return Boolean.TRUE.equals(result);
    }

    /**
     * 检查是否已处理
     */
    public boolean isProcessed(String transactionId) {
        return Boolean.TRUE.equals(
            redisTemplate.hasKey("processed:" + transactionId)
        );
    }

    /**
     * 标记已处理
     */
    public void markProcessed(String transactionId) {
        redisTemplate.opsForValue().set("processed:" + transactionId, "1",
            Duration.ofDays(7));
    }
}

// 消费端使用
@RocketMQMessageListener(topic = "order_topic", consumerGroup = "order_consumer_group")
public class OrderConsumer implements RocketMQListener<OrderMessage> {

    @Autowired
    private IdempotentProcessor idempotentProcessor;

    @Override
    public void onMessage(OrderMessage message) {
        String transactionId = message.getTransactionId();

        // 1. 尝试获取幂等锁
        if (!idempotentProcessor.tryLock(transactionId, 30)) {
            log.warn("获取幂等锁失败，可能正在处理: {}", transactionId);
            return;
        }

        try {
            // 2. 检查是否已处理
            if (idempotentProcessor.isProcessed(transactionId)) {
                log.info("消息已处理，跳过: {}", transactionId);
                return;
            }

            // 3. 执行业务逻辑
            processOrder(message);

            // 4. 标记已处理
            idempotentProcessor.markProcessed(transactionId);

        } finally {
            idempotentProcessor.unlock(transactionId);
        }
    }
}
```

### 最佳实践建议

**1. 事务消息使用原则**：
- 只在必要时使用事务消息，避免过度设计
- 核心交易流程（如支付、订单）使用事务消息
- 非核心流程使用普通消息异步处理

**2. 本地事务设计**：
- 保持本地事务简短，避免长事务
- 本地事务只处理核心业务，衍生操作异步化
- 使用事务日志表记录状态，支持回查

**3. 回查机制优化**：
- 回查接口需要快速响应，避免复杂查询
- 使用缓存减少数据库压力
- 设置合理的回查间隔和最大次数

**4. 监控与告警**：
- 监控 UNKNOWN 状态消息数量
- 监控事务消息回查次数
- 设置超时告警，及时处理

**5. 异常处理**：
```java
// 统一异常处理策略
public class TransactionExceptionHandler {

    public RocketMQLocalTransactionState handle(Exception e, String transactionId) {
        if (e instanceof BusinessException) {
            // 业务异常，明确回滚
            return RocketMQLocalTransactionState.ROLLBACK;
        } else if (e instanceof TimeoutException) {
            // 超时异常，返回 UNKNOWN 等待回查
            return RocketMQLocalTransactionState.UNKNOWN;
        } else {
            // 系统异常，记录并回滚
            log.error("系统异常: transactionId={}", transactionId, e);
            alertService.send("事务执行异常", transactionId);
            return RocketMQLocalTransactionState.ROLLBACK;
        }
    }
}
```
