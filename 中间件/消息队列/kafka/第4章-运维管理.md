# 第四章：运维管理

## 4.1 主题管理

### 4.1.1 创建主题

使用 `kafka-topics` 脚本创建主题是日常运维中最基本的操作之一。

#### 基本创建语法

```bash
# 语法格式
kafka-topics.sh --create \
  --bootstrap-server <broker地址> \
  --topic <主题名> \
  --partitions <分区数> \
  --replication-factor <副本数>
```

#### 实际示例

```bash
# 创建单副本主题
kafka-topics.sh --create \
  --bootstrap-server localhost:9092 \
  --topic my-topic \
  --partitions 3 \
  --replication-factor 1

# 创建多副本主题（推荐生产环境使用）
kafka-topics.sh --create \
  --bootstrap-server localhost:9092 \
  --topic production-topic \
  --partitions 6 \
  --replication-factor 3
```

#### 创建时指定配置

```bash
# 创建主题并设置保留策略
kafka-topics.sh --create \
  --bootstrap-server localhost:9092 \
  --topic config-demo \
  --partitions 3 \
  --replication-factor 1 \
  --config retention.ms=604800000 \
  --config max.message.bytes=1048576
```

### 4.1.2 查看主题

#### 查看所有主题列表

```bash
# 列出所有主题
kafka-topics.sh --list --bootstrap-server localhost:9092

# 列出包含特定前缀的主题
kafka-topics.sh --list --bootstrap-server localhost:9092 | grep "^order-"
```

#### 查看主题详细信息

```bash
# 查看单个主题详情
kafka-topics.sh --describe \
  --bootstrap-server localhost:9092 \
  --topic my-topic

# 查看所有主题详情
kafka-topics.sh --describe --bootstrap-server localhost:9092
```

输出示例：

```
Topic: my-topic    PartitionCount: 3    ReplicationFactor: 1    Configs: ...
    Topic: my-topic    Partition: 0    Leader: 0    Replicas: 0    Isr: 0
    Topic: my-topic    Partition: 1    Leader: 0    Replicas: 0    Isr: 0
    Topic: my-topic    Partition: 2    Leader: 0    Replicas: 0    Isr: 0
```

#### 字段说明

| 字段 | 含义 |
|------|------|
| Leader | 负责该分区读写的broker节点ID |
| Replicas | 该分区的所有副本所在的broker节点列表 |
| Isr | in-sync replicas，与leader保持同步的副本集合 |

### 4.1.3 修改主题

#### 增加分区（只能增加，不能减少）

```bash
# 将分区数从3增加到6
kafka-topics.sh --alter \
  --bootstrap-server localhost:9092 \
  --topic my-topic \
  --partitions 6
```

::: warning 注意
分区数只能增加，不能减少。减少分区会导致数据丢失或不一致。
:::

#### 修改主题配置

```bash
# 修改消息保留时间（7天改为3天）
kafka-topics.sh --alter \
  --bootstrap-server localhost:9092 \
  --topic my-topic \
  --add-config retention.ms=259200000

# 关闭主题的压缩功能
kafka-topics.sh --alter \
  --bootstrap-server localhost:9092 \
  --topic my-topic \
  --remove-config cleanup.policy
```

#### 常用主题配置参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| retention.ms | 消息保留时间（毫秒） | 604800000（7天） |
| max.message.bytes | 单条消息最大字节数 | 1048576（1MB） |
| cleanup.policy | 清理策略（delete/compact） | delete |
| min.insync.replicas | 最小同步副本数 | 1 |
| segment.bytes | segment文件大小 | 1073741824（1GB） |

### 4.1.4 删除主题

```bash
# 删除主题（需要enable.auto.delete=true）
kafka-topics.sh --delete \
  --bootstrap-server localhost:9092 \
  --topic my-topic
```

::: danger 注意
删除主题会永久删除所有数据，请谨慎操作。
:::

### 4.1.5 分区管理

#### 分区副本分配

```bash
# 查看当前副本分配情况
kafka-topics.sh --describe \
  --bootstrap-server localhost:9092 \
  --topic my-topic
```

#### 手动指定分区副本分配

```bash
# 创建主题时手动指定副本分配
kafka-topics.sh --create \
  --bootstrap-server localhost:9092,localhost:9093,localhost:9094 \
  --topic manual-topic \
  --partitions 4 \
  --replication-factor 2 \
  --replica-assignment "0:1,1:2,2:3,3:0"
```

#### 副本重新均衡

当broker宕机或新broker加入时，需要进行副本重新分配：

```bash
# 生成推荐的重分配方案（先创建JSON文件）
cat > reassign.json << 'EOF'
{
  "topics": [
    {
      "topic": "my-topic",
      "partitions": [
        {"partition": 0, "replicas": [0, 1]},
        {"partition": 1, "replicas": [1, 2]},
        {"partition": 2, "replicas": [2, 0]}
      ]
    }
  ],
  "version": 1
}
EOF

# 执行副本重分配
kafka-reassign-partitions.sh --bootstrap-server localhost:9092 \
  --generate \
  --topics-to-move-json-file reassign.json \
  --broker-list "0,1,2" \
  | kafka-reassign-partitions.sh --bootstrap-server localhost:9092 \
  --execute \
  --reassignment-json-file <(cat << 'REASSIGN_EOF'
{"version":1,"partitions":[{"topic":"my-topic","partition":0,"replicas":[0,1],"log_dirs":["any","any"]},{"topic":"my-topic","partition":1,"replicas":[1,2],"log_dirs":["any","any"]},{"topic":"my-topic","partition":2,"replicas":[2,0],"log_dirs":["any","any"]}]}
REASSIGN_EOF
)

# 检查重分配状态
kafka-reassign-partitions.sh --bootstrap-server localhost:9092 \
  --verify \
  --reassignment-json-file reassign.json
```

## 4.2 配置调优

### 4.2.1 Broker级别配置

Broker配置文件位于 `config/server.properties`。以下是生产环境推荐的关键配置：

#### 基础配置

```properties
# broker唯一标识（必须唯一）
broker.id=0

# 监听地址
listeners=PLAINTEXT://localhost:9092

# 日志目录（建议使用独立磁盘）
log.dirs=/var/lib/kafka/logs

# 数据保留时间（7天）
log.retention.hours=168

# 每个分区的segment文件大小
log.segment.bytes=1073741824

# 段文件检查间隔
log.retention.check.interval.ms=300000
```

#### 网络与连接配置

```properties
# 最大连接数
max.connections.max=2147483647

# 连接最大空闲时间
connections.max.idle.ms=600000

# socket发送缓冲区大小
socket.send.buffer.bytes=102400

# socket接收缓冲区大小
socket.receive.buffer.bytes=102400

# 最大请求大小
message.max.bytes=1048576
```

#### 副本与一致性配置

```properties
# 默认副本因子
default.replication.factor=3

# 分区内最大消息数
num.replica.fetchers=4

# 副本滞后检测阈值
replica.lag.time.max.ms=30000

# 最小同步副本数（推荐设置）
min.insync.replicas=2

# leader选举惩罚时间
uncaught.exception.handler=log
```

#### Zookeeper配置

```properties
# Zookeeper连接字符串
zookeeper.connect=localhost:2181/kafka

# Zookeeper连接超时
zookeeper.connection.timeout.ms=18000

# Zookeeper session超时
zookeeper.session.timeout.ms=6000
```

### 4.2.3 JVM调优

Kafka使用JVM运行，推荐的JVM配置：

#### Heap内存设置

```bash
# 推荐使用G1垃圾收集器，Heap大小根据服务器内存调整
# 通常设置为服务器物理内存的1/4到1/2，最大不超过31GB

export KAFKA_HEAP_OPTS="-Xms4g -Xmx4g -XX:+UseG1GC -XX:MaxGCPauseMillis=20 -XX:InitiatingHeapOccupancyPercent=35"

# 或者使用JDK 11+的ZGC（适合大内存）
export KAFKA_HEAP_OPTS="-Xms8g -Xmx8g -XX:+UseZGC -XX:MaxHeapFreeRatio=70 -XX:MinHeapFreeRatio=40"
```

#### Kafka启动脚本JVM配置示例

修改 `bin/kafka-server-start.sh` 或通过环境变量设置：

```bash
# 设置环境变量
export KAFKA_HEAP_OPTS="-Xmx6g -Xms6g -XX:+UseG1GC -XX:G1ReservePercent=25 -XX:InitiatingHeapOccupancyPercent=30"

# Kafka 2.11+ 推荐配置
export KAFKA_JVM_PERFORMANCE_OPTS="-XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=256m -XX:G1HeapRegionSize=16m"
```

#### GC调优参数说明

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| -Xms/-Xmx | 堆最小/最大内存 | 4g-8g |
| -XX:+UseG1GC | 使用G1垃圾收集器 | 推荐 |
| -XX:MaxGCPauseMillis | 最大GC停顿时间 | 20ms |
| -XX:InitiatingHeapOccupancyPercent | 触发GC的堆使用率 | 35% |

## 4.4 故障排查

### 4.4.1 消息丢失

#### 常见原因

1. **acks设置不当**：producer的acks参数设置过低
2. **副本同步失败**：min.insync.replicas设置过高，部分副本无法同步
3. **刷盘策略不当**：log.flush.interval.messages设置过大
4. **Broker宕机**：数据未完全刷盘就发生宕机

#### 排查步骤

```bash
# 1. 检查是否有欠副本分区
kafka-topics.sh --describe --bootstrap-server localhost:9092 --under-replicated-partitions

# 2. 检查ISR情况
kafka-topics.sh --describe --bootstrap-server localhost:9092 | grep -E "ISR|Replicas"

# 3. 检查Broker日志
grep -i "error\|exception\|fail" /var/log/kafka/server.log

# 4. 检查网络连接
netstat -an | grep 9092 | grep ESTABLISHED

# 5. 检查磁盘空间
df -h /var/lib/kafka/logs
```

#### 解决方案

**1. 调整Producer配置**

```java
// 不推荐：acks=0，可能丢失消息
properties.put("acks", "0");

// 推荐：acks=all，保证消息不丢失
properties.put("acks", "all");

// 推荐：使用重试机制
properties.put("retries", 3);
properties.put("retry.backoff.ms", 1000);

// 推荐：启用幂等性
properties.put("enable.idempotence", true);
```

**2. 调整Broker副本配置**

```properties
# server.properties
# 确保最小同步副本数
min.insync.replicas=2

# 禁用不安全leader选举
unclean.leader.election.enable=false

# 合理设置副本滞后阈值
replica.lag.time.max.ms=30000
replica.socket.timeout.ms=30000
```

**3. 确保数据刷盘**

```properties
# 适当减小刷盘间隔（会影响性能）
log.flush.interval.messages=10000
log.flush.interval.ms=1000

# 推荐使用默认配置，依靠OS刷盘
```

### 4.4.2 消息重复消费

#### 常见原因

1. **消费者手动提交offset**：在消息处理完成前就提交了offset
2. **消费者重启**：重启后从头消费，导致重复
3. **Producer重试**：网络超时导致消息被重试发送
4. **事务失败**：使用事务时，事务回滚导致重复

#### 排查步骤

```bash
# 1. 检查消费者组的消费进度
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --group <consumer-group> \
  --describe

# 2. 查看消费者的lag
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --group <consumer-group> \
  --describe | grep LAG

# 3. 检查是否有消费者离线
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --all-groups \
  --describe

# 4. 查看生产者重试日志
grep -i "retry\|resend" producer.log
```

#### 解决方案

**1. 使用幂等消费者**

```java
// 消息处理时做幂等性处理
public void processMessage(String messageId, String content) {
    // 方案1：数据库唯一键
    try {
        insertIntoDatabase(messageId, content);
    } catch (DuplicateKeyException e) {
        // 消息已处理，忽略
        log.info("Duplicate message ignored: {}", messageId);
        return;
    }

    // 方案2：Redis去重
    String key = "processed:" + messageId;
    if (redis.set(key, "1", "NX", "EX", 86400)) {
        // 首次处理
        doProcess(content);
    } else {
        // 重复消息
        log.info("Duplicate message from Redis: {}", messageId);
    }
}
```

**2. 正确处理offset提交**

```java
// 推荐：手动提交offset时，先处理消息，再提交
public class SafeConsumer {
    private static final int MAX_POLL_RECORDS = 100;

    public void consume() {
        ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(1000));

        for (ConsumerRecord<String, String> record : records) {
            try {
                // 处理消息
                processMessage(record);

                // 在消息处理成功后再提交offset
                if (isLastRecordForPartition(record)) {
                    consumer.commitSync(Collections.singletonMap(
                        new TopicPartition(record.topic(), record.partition()),
                        new OffsetAndMetadata(record.offset() + 1)
                    ));
                }
            } catch (Exception e) {
                log.error("Failed to process message", e);
                // 记录失败，不提交offset，下次重新消费
                handleFailure(record);
            }
        }
    }
}
```

**3. 生产者幂等性配置**

```java
// 启用幂等性，避免重复发送
properties.put("enable.idempotence", true);
properties.put("acks", "all");
properties.put("retries", 3);

// 生产者配置
properties.put("max.in.flight.requests.per.connection", 5);
```

### 4.4.3 消费延迟

#### 常见原因

1. **消费者处理能力不足**：处理逻辑太慢，或消费者数量太少
2. **分区不均匀**：消息分布不均，导致部分消费者负载过高
3. **消费者频繁Rebalance**：分区分配频繁变动
4. **网络瓶颈**：带宽不足
5. **磁盘IO瓶颈**：日志读写速度跟不上

#### 排查步骤

```bash
# 1. 查看消费者lag
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --group <consumer-group> \
  --describe

# 2. 检查分区分布
kafka-topics.sh --describe --bootstrap-server localhost:9092 --topic <topic>

# 3. 监控网络带宽
sar -n DEV 1 10

# 4. 检查磁盘IO
iostat -x 1 5

# 5. 检查消费者处理时间
# 在消费者日志中添加处理耗时统计
```

#### 解决方案

**1. 增加消费者数量**

```bash
# 查看当前消费者组
kafka-consumer-groups.sh --bootstrap-server localhost:9092 \
  --describe --group <consumer-group>

# 确保消费者数量 <= 分区数
# 如果分区数为6，消费者数应该 <= 6
```

**2. 优化消费者处理逻辑**

```java
// 使用批处理提高吞吐量
public class BatchConsumer {
    private final int batchSize = 100;
    private final List<ConsumerRecord<String, String>> buffer = new ArrayList<>();

    public void consume() {
        ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(1000));

        for (ConsumerRecord<String, String> record : records) {
            buffer.add(record);

            if (buffer.size() >= batchSize) {
                // 批量处理
                processBatch(buffer);
                buffer.clear();
            }
        }

        // 处理剩余的记录
        if (!buffer.isEmpty()) {
            processBatch(buffer);
            buffer.clear();
        }
    }

    private void processBatch(List<ConsumerRecord<String, String>> batch) {
        // 批量插入数据库
        jdbcTemplate.batchUpdate(
            "INSERT INTO messages (id, content) VALUES (?, ?)",
            batch,
            batch.size(),
            (ps, record) -> {
                ps.setString(1, record.key());
                ps.setString(2, record.value());
            }
        );
    }
}
```
