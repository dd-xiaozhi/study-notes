# 第1章：Jenkins 简介与核心概念

## 1.1 Jenkins 简介

### 1.1.1 什么是 Jenkins

Jenkins 是一个开源的自动化服务器，最初由 Sun Microsystems 的开发者 Kohsuke Kawaguchi 于 2004 年创建，原名为 "Hudson"。它主要用于持续集成（Continuous Integration, CI）和持续交付（Continuous Delivery, CD），能够帮助开发团队自动化构建、测试和部署软件的过程。

Jenkins 通过插件化的架构提供了极高的灵活性，用户可以根据项目需求选择和配置不同的插件来实现各种功能。截至目前，Jenkins 插件生态拥有超过 1800 个插件，涵盖了从源代码管理、构建工具、测试框架到部署平台的方方面面。

### 1.1.2 Jenkins 的核心特性

**1. 开源免费**
Jenkins 采用 MIT 开源许可证，完全免费使用，社区活跃，文档丰富。

**2. 插件化架构**
- 核心功能精简，通过插件扩展
- 插件仓库包含 1800+ 插件
- 支持自定义插件开发（基于 Java）

**3. 分布式构建**
- Master-Agent 架构支持分布式任务执行
- Agent 可以是物理机、虚拟机或容器
- 负载均衡和故障转移能力

**4. Pipeline as Code**
- 使用 Groovy DSL 定义构建流程
- 版本控制化的流水线配置
- 支持复杂的条件、循环、并行逻辑

**5. 易于扩展**
- REST API 支持外部系统集成
- Webhook 机制实现事件驱动
- 插件开发文档完善

## 1.2 Jenkins 发展历史

### 1.2.1 时间线

| 年份 | 版本/事件 | 说明 |
|------|-----------|------|
| 2004 | Hudson 诞生 | Kohsuke Kawaguchi 在 Sun Microsystems 创建 |
| 2005 | 开源发布 | 采用 MIT 许可证开源 |
| 2007 | Jenkins 更名 | Oracle 收购 Sun 后，社区分支创建 Jenkins |
| 2011 | Jenkins 1.x | 首个 LTS 版本，长期支持模式确立 |
| 2016 | Jenkins 2.x | Pipeline as Code 成为核心功能 |
| 2019 | Jenkins X | 面向云原生的 Kubernetes-native 版本 |
| 2023 | Jenkins 2.426+ | Java 17 支持，现代 UI 改进 |

### 1.2.2 从 Hudson 到 Jenkins 的分支故事

2011 年，Oracle 收购 Sun Microsystems 后，Hudson 项目归属 Oracle 管理。由于社区对项目发展方向存在分歧，约 70% 的核心开发者决定创建分支项目，并将其命名为 "Jenkins"。这一事件反而促进了 Jenkins 的快速发展，使其成为最受欢迎的 CI/CD 工具之一。

## 1.3 Jenkins 核心概念

### 1.3.1 Master 和 Agent

Jenkins 采用经典的 Master-Agent（也称为 Master-Slave）分布式架构。

#### Master（主节点）

Master 是 Jenkins 的核心组件，负责：
- 管理所有配置和元数据
- 调度和分配构建任务
- 提供 Web UI 和 REST API
- 存储构建历史和产物
- 管理用户权限和认证

```
┌─────────────────────────────────────────────────────────────┐
│                      Jenkins Master                         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │  Job 配置   │  │  调度引擎  │  │   Web Server        │  │
│  │  (Config)   │  │ (Scheduler)│  │   (UI/API)          │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │  安全模块  │  │  插件管理   │  │   构建记录          │  │
│  │  (Security) │  │ (Plugin Mgr)│  │   (Build History)   │  │
│  └─────────────┘  └─────────────┘  └─────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

#### Agent（从节点）

Agent 是执行构建任务的工作节点，可以是：
- 物理服务器
- 虚拟机
- Docker 容器
- Kubernetes Pod
- 云主机（AWS EC2, Azure VM 等）

Agent 的配置示例：

```groovy
// 在 Jenkinsfile 中指定 agent
pipeline {
    agent {
        // 使用任意可用的 agent
        any
    }
    stages {
        stage('Build') {
            steps {
                echo 'Building...'
            }
        }
    }
}
```

```groovy
// 指定特定的 agent label
pipeline {
    agent {
        label 'linux && docker'
    }
    stages {
        stage('Build') {
            steps {
                echo 'Building on Linux with Docker...'
            }
        }
    }
}
```

```groovy
// 使用 Docker 容器作为 agent
pipeline {
    agent {
        docker {
            image 'maven:3.8-openjdk-17'
            label 'docker'
        }
    }
    stages {
        stage('Build') {
            steps {
                sh 'mvn --version'
            }
        }
    }
}
```

#### Master-Agent 通信机制

Agent 与 Master 之间通过 JNLP（Java Web Start）或 SSH 协议建立连接：

**JNLP 方式（适用于防火墙内的 Agent）**
```xml
<!-- agent launch.xml 示例 -->
<jnlp spec="1.0+" codebase="http://master:8080/jenkins">
    <information>
        <title>Jenkins Agent</title>
    </information>
    <resources>
        <jar href="agent.jar"/>
    </resources>
    <application-desc>
        <argument>http://master:8080</argument>
    </application-desc>
</jnlp>
```

**SSH 方式（适用于有 SSH 访问权限的机器）**
```bash
# 在 Agent 机器上手动启动
java -jar agent.jar -jnlpUrl http://master:8080/computer/agent1/slave-agent.jnlp -workDir "/home/jenkins/agent"
```

### 1.3.2 Job、Build 和 Artifact

#### Job（任务）

Job 是 Jenkins 中的基本工作单元，代表一个完整的构建流程。常见的 Job 类型包括：

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| Freestyle Project | 自由式项目，配置灵活 | 简单构建任务 |
| Pipeline | 流水线项目，代码化流程 | 复杂构建和部署 |
| Multi-configuration Project | 多配置项目 | 矩阵式构建（多平台、多编译器） |
| Folder | 文件夹，用于组织任务 | 项目分组管理 |
| Organization Folder | 组织文件夹 | 扫描 GitHub/GitLab 组织 |

**Freestyle Job 配置示例**

```groovy
// 这是一个 Freestyle Job 的配置结构（pipeline 语法）
job('my-freestyle-job') {
    displayName('My First Freestyle Job')
    description('这是一个示例自由式任务')

    // 源码管理
    scm {
        git {
            remote {
                url('https://github.com/example/repo.git')
                credentials('github-ssh-key')
            }
            branch('*/main')
        }
    }

    // 构建触发器
    triggers {
        cron('H H * * *')  // 每天午夜执行
    }

    // 构建步骤
    steps {
        shell('echo "Hello Jenkins"')
    }

    // 构建后操作
    post {
        always {
            cleanWs()
        }
    }
}
```

#### Build（构建）

Build 是 Job 的一次执行实例。每次触发 Job 都会创建一个新的 Build，并分配一个递增的编号（如 #1, #2, #3）。

Build 的生命周期：

```
触发（Trigger）
    │
    ▼
排队（Queued） ────► 执行器（Executor）可用时
    │                   │
    ▼                   ▼
开始（Started）      执行 Stage
    │                   │
    ▼                   ▼
完成（Completed）   上传 Artifact
    │                   │
    ▼                   ▼
后处理（Post-build） 通知
```

**Build 状态说明**

| 状态 | 颜色 | 说明 |
|------|------|------|
| SUCCESS | 蓝色 | 构建成功 |
| FAILURE | 红色 | 构建失败 |
| UNSTABLE | 黄色 | 构建成功但有测试失败 |
| ABORTED | 灰色 | 构建被手动终止 |
| NOT_BUILT | 白色 | 构建未执行（如条件跳过） |

#### Artifact（产物）

Artifact 是构建过程产生的输出文件，如编译后的二进制文件、Docker 镜像、安装包等。

**Artifact 配置示例**

```groovy
pipeline {
    agent any
    stages {
        stage('Build') {
            steps {
                sh '''
                    mvn clean package -DskipTests=false
                '''
            }
        }
    }
    post {
        success {
            archiveArtifacts artifacts: 'target/*.jar', fingerprint: true
        }
    }
}
```

**Artifact 访问**
- 通过 Jenkins Web UI 下载
- 通过 REST API 下载：`GET http://master:8080/job/<job-name>/<build-number>/artifact/<path>`
- 通过 CLI 下载：`jenkins-cli.jar get-job <job-name>`

### 1.3.3 Trigger（触发器）

Trigger 定义了何时触发构建。以下是常见的触发方式：

#### 1. 轮询 SCM（Poll SCM）

定期检查源码仓库是否有新提交：

```groovy
pipeline {
    triggers {
        pollSCM('H/5 * * * *')  // 每5分钟检查一次
    }
    stages {
        stage('Build') {
            steps {
                echo 'Building...'
            }
        }
    }
}
```

#### 2. 定时触发（Build Periodically）

按 CRON 表达式定时触发：

```groovy
pipeline {
    triggers {
        // 每周一到周五早上9点执行
        cron('0 9 * * 1-5')
    }
    stages {
        stage('Build') {
            steps {
                echo 'Morning build triggered'
            }
        }
    }
}
```

#### 3. Webhook 触发

代码提交时自动触发：

```groovy
pipeline {
    triggers {
        // GitHub Push 事件触发
        githubPush()
    }
    stages {
        stage('Build') {
            steps {
                echo 'Triggered by GitHub push'
            }
        }
    }
}
```

#### 4. 上游触发（Upstream）

其他 Job 构建成功后触发：

```groovy
pipeline {
    triggers {
        // 当 job1 或 job2 构建成功时触发
        upstream('job1,job2', threshold: 'SUCCESS')
    }
    stages {
        stage('Deploy') {
            steps {
                echo 'Triggered by upstream job'
            }
        }
    }
}
```

#### 5. 手动触发（Build with Parameters）

用户手动触发，支持参数化构建：

```groovy
pipeline {
    parameters {
        string(name: 'BRANCH', defaultValue: 'main', description: '分支名称')
        choice(name: 'ENVIRONMENT', choices: ['dev', 'staging', 'prod'], description: '部署环境')
        booleanParam(name: 'RUN_TESTS', defaultValue: true, description: '是否运行测试')
    }
    stages {
        stage('Build') {
            steps {
                echo "Building branch: ${params.BRANCH}"
                echo "Environment: ${params.ENVIRONMENT}"
                echo "Run tests: ${params.RUN_TESTS}"
            }
        }
    }
}
```

### 1.3.4 Pipeline（流水线）

Pipeline 是 Jenkins 2.x 引入的核心功能，将构建过程定义为代码。

#### Pipeline 语法结构

```groovy
// 声明式 Pipeline
pipeline {
    // agent 定义在哪里执行
    agent any

    // 环境变量
    environment {
        JAVA_HOME = '/usr/lib/jvm/java-17'
    }

    // 参数定义
    parameters {
        string(name: 'VERSION', defaultValue: '1.0.0')
    }

    // 触发器
    triggers {
        githubPush()
    }

    // 阶段定义
    stages {
        stage('Checkout') {
            steps {
                echo 'Checking out source code...'
                git 'https://github.com/example/repo.git'
            }
        }

        stage('Build') {
            steps {
                echo 'Building application...'
                sh 'mvn clean package'
            }
        }

        stage('Test') {
            steps {
                echo 'Running tests...'
                sh 'mvn test'
            }
        }

        stage('Deploy') {
            when {
                branch 'main'
            }
            steps {
                echo 'Deploying to production...'
            }
        }
    }

    // 后处理
    post {
        always {
            echo 'Cleaning up...'
        }
        success {
            echo 'Build succeeded!'
        }
        failure {
            echo 'Build failed!'
        }
    }
}
```

#### 脚本式 Pipeline

```groovy
// 脚本式 Pipeline（更灵活但语法复杂）
node('agent-label') {
    try {
        stage('Checkout') {
            echo 'Checking out...'
        }

        stage('Build') {
            echo 'Building...'
        }

        stage('Test') {
            echo 'Testing...'
        }
    } catch (Exception e) {
        echo "Error: ${e.message}"
        currentBuild.result = 'FAILURE'
    } finally {
        echo 'Finally block'
    }
}
```

### 1.3.5 Stage（阶段）

Stage 是 Pipeline 中的主要逻辑分组，通常代表构建流程中的一个主要步骤。

#### Stage 最佳实践

```groovy
pipeline {
    agent any
    stages {
        // 第一阶段：代码检出
        stage('Checkout') {
            steps {
                echo 'Checking out source code'
                git url: 'https://github.com/example/repo.git'
            }
        }

        // 第二阶段：安装依赖
        stage('Install Dependencies') {
            steps {
                echo 'Installing dependencies'
                sh 'npm install'
            }
        }

        // 第三阶段：代码质量检查
        stage('Code Quality') {
            steps {
                echo 'Running lint and static analysis'
                sh 'npm run lint'
                sh 'npm run static-analysis'
            }
        }

        // 第四阶段：构建
        stage('Build') {
            steps {
                echo 'Building application'
                sh 'npm run build'
            }
        }

        // 第五阶段：测试
        stage('Test') {
            steps {
                echo 'Running unit tests'
                sh 'npm run unit-test'
            }

            // 第六阶段：集成测试（在 Test stage 内部）
            stage('Integration Test') {
                steps {
                    echo 'Running integration tests'
                    sh 'npm run integration-test'
                }
            }
        }

        // 第七阶段：打包
        stage('Package') {
            steps {
                echo 'Creating distribution package'
                sh 'npm run package'
                archiveArtifacts artifacts: 'dist/**/*', fingerprint: true
            }
        }

        // 第八阶段：部署
        stage('Deploy') {
            when {
                branch 'main'
            }
            steps {
                echo 'Deploying to server'
            }
        }
    }
    post {
        always {
            junit testResults: '**/test-results/*.xml'
        }
    }
}
```

### 1.3.6 Step（步骤）

Step 是 Pipeline 中最基本的执行单元，代表一个具体的命令或操作。

#### 常用 Steps

**Shell 命令执行**

```groovy
steps {
    sh 'echo "Hello World"'
    sh '''
        cd /path/to/project
        npm install
        npm run build
    '''
}
```

**Windows 批处理**

```groovy
steps {
    bat 'dir'
    bat '''
        call npm install
        call npm run build
    '''
}
```

**条件执行**

```groovy
steps {
    script {
        if (env.BRANCH_NAME == 'main') {
            echo 'Running deployment steps'
        } else {
            echo 'Skipping deployment for feature branch'
        }
    }
}
```

**超时重试**

```groovy
steps {
    timeout(time: 30, unit: 'MINUTES') {
        retry(3) {
            sh 'curl -s http://api.example.com/health'
        }
    }
}
```

**邮件通知**

```groovy
steps {
    emailext(
        subject: "Jenkins Build ${currentBuild.result}",
        body: """
            Build: ${currentBuild.fullDisplayName}
            Status: ${currentBuild.result}
            URL: ${env.BUILD_URL}
        """,
        to: 'team@example.com'
    )
}
```

### 1.4.2 典型 Pipeline 完整示例

```groovy
// 完整的 CI/CD Pipeline 示例
pipeline {
    agent {
        docker {
            image 'maven:3.8-openjdk-17'
            args '-v /root/.m2:/root/.m2'
        }
    }

    environment {
        APP_NAME = 'my-app'
        REGISTRY = 'registry.example.com'
    }

    parameters {
        choice(name: 'BRANCH', choices: ['main', 'develop'], description: '选择分支')
        booleanParam(name: 'SKIP_TESTS', defaultValue: false, description: '跳过测试')
    }

    triggers {
        githubPush()
    }

    stages {
        // 阶段1：代码检出
        stage('Checkout') {
            steps {
                echo "Checking out ${params.BRANCH} branch"
                script {
                    def gitUtils = new com.example.GitUtils()
                    env.COMMIT_SHA = gitUtils.getCommitSha()
                }
            }
        }

        // 阶段2：安装依赖
        stage('Dependencies') {
            steps {
                echo 'Installing dependencies...'
                sh 'mvn dependency:go-offline'
            }
        }

        // 阶段3：代码检查
        stage('Code Analysis') {
            parallel {
                stage('Lint') {
                    steps {
                        echo 'Running linter...'
                        sh 'mvn checkstyle:check'
                    }
                }
                stage('SonarQube') {
                    steps {
                        echo 'Running SonarQube analysis...'
                        sh 'mvn sonar:sonar'
                    }
                }
            }
        }

        // 阶段4：构建
        stage('Build') {
            steps {
                echo 'Building application...'
                sh 'mvn clean package -DskipTests=${params.SKIP_TESTS}'
            }
        }

        // 阶段5：测试
        stage('Test') {
            when {
                expression { params.SKIP_TESTS == false }
            }
            steps {
                echo 'Running tests...'
                sh 'mvn test'
            }
            post {
                always {
                    junit '**/target/surefire-reports/*.xml'
                }
            }
        }

        // 阶段6：打包 Docker 镜像
        stage('Docker Build') {
            steps {
                echo 'Building Docker image...'
                sh '''
                    docker build -t ${REGISTRY}/${APP_NAME}:${BRANCH_NAME}-${BUILD_NUMBER} .
                    docker build -t ${REGISTRY}/${APP_NAME}:latest .
                '''
            }
        }

        // 阶段7：推送镜像
        stage('Push to Registry') {
            steps {
                echo 'Pushing Docker image...'
                sh '''
                    docker push ${REGISTRY}/${APP_NAME}:${BRANCH_NAME}-${BUILD_NUMBER}
                    docker push ${REGISTRY}/${APP_NAME}:latest
                '''
            }
        }

        // 阶段8：部署
        stage('Deploy') {
            when {
                branch 'main'
            }
            steps {
                echo 'Deploying to production...'
                sh '''
                    kubectl apply -f k8s/deployment.yaml
                    kubectl set image deployment/${APP_NAME} app=${REGISTRY}/${APP_NAME}:latest
                '''
            }
        }

        // 阶段9：健康检查
        stage('Health Check') {
            when {
                branch 'main'
            }
            steps {
                echo 'Running health checks...'
                sh 'kubectl rollout status deployment/${APP_NAME}'
            }
        }
    }

    // 后处理
    post {
        always {
            echo 'Cleaning workspace...'
            cleanWs()
        }
        success {
            echo 'Pipeline succeeded!'
            slackSend(
                channel: '#ci-cd',
                message: "Build ${currentBuild.number} succeeded: ${env.BUILD_URL}"
            )
        }
        failure {
            echo 'Pipeline failed!'
            slackSend(
                channel: '#ci-cd',
                message: "Build ${currentBuild.number} FAILED: ${env.BUILD_URL}"
            )
            emailext(
                subject: "Jenkins Build Failed: ${currentBuild.fullDisplayName}",
                body: "Check console output at: ${env.BUILD_URL}",
                recipientProviders: [culprits(), developers()]
            )
        }
    }
}
```

## 1.5 Jenkins 与其他 CI/CD 工具对比

### 1.5.1 主流 CI/CD 工具概览

| 工具 | 开发方 | 类型 | 特点 |
|------|--------|------|------|
| Jenkins | 开源社区 | 通用型 | 插件丰富，灵活性高 |
| GitLab CI/CD | GitLab | 集成型 | 与 GitLab 深度集成 |
| GitHub Actions | GitHub | 集成型 | 与 GitHub 深度集成 |
| CircleCI | CircleCI | 云原生 | 配置简单，速度快 |

### 1.5.3 Jenkins 的优势

**1. 极高的灵活性**
- 几乎所有功能都可以通过插件扩展
- 可以与任何工具集成
- 不绑定特定平台或语言

**2. 成熟的生态系统**
- 15+ 年的发展和社区积累
- 文档丰富，社区活跃
- 大量企业实践经验

**3. 强大的分布式构建能力**
- 支持任意数量的 Agent
- 可以运行在不同平台（Windows, Linux, macOS）
- 负载均衡和故障转移完善

**4. 完全控制**
- 完全自托管，数据不出本地
- 可以运行在私有数据中心
- 适合对数据安全要求高的企业

### 1.5.4 Jenkins 的劣势

**1. 配置相对复杂**
- 相比 GitHub Actions 等工具，学习曲线较陡
- 大量配置需要手动完成
- UI 设计较为陈旧

**2. 维护成本**
- 需要专人维护 Master 和 Agent
- 插件版本兼容性有时是个问题
- 升级需要谨慎测试

**3. 插件质量参差不齐**
- 部分插件缺乏维护
- 插件安全漏洞需要关注
- 插件依赖管理复杂

### 1.5.5 选型建议

| 场景 | 推荐工具 | 原因 |
|------|----------|------|

| 中型企业，多项目 | Jenkins / GitLab CI | 灵活可控，插件丰富 |
| 大型企业，复杂需求 | Jenkins / TeamCity | 功能强大，支持复杂工作流 |
| 安全敏感行业 | Jenkins | 完全自托管，数据安全 |
| 开源项目 | GitHub Actions / CircleCI | 免费额度充足，集成好 |
| 多语言混合项目 | Jenkins | 不绑定特定语言和工具链 |

## 1.6 Jenkins 适用场景

### 1.6.1 持续集成（CI）

Jenkins 最典型的应用场景是持续集成：

```groovy
// 标准的 CI Pipeline
pipeline {
    agent any
    stages {
        stage('Build') {
            steps {
                echo 'Compiling source code...'
                // 编译步骤
            }
        }
        stage('Unit Test') {
            steps {
                echo 'Running unit tests...'
                // 运行单元测试
            }
        }
        stage('Integration Test') {
            steps {
                echo 'Running integration tests...'
                // 运行集成测试
            }
        }
    }
    post {
        always {
            junit '**/test-results/**/*.xml'
        }
    }
}
```

### 1.6.2 持续交付/持续部署（CD）

Jenkins 可以实现完整的 CD 流程：

```groovy
// CD Pipeline 示例
pipeline {
    agent any
    stages {
        stage('Build') {
            steps {
                echo 'Building application...'
            }
        }
        stage('Test') {
            steps {
                echo 'Running all tests...'
            }
        }
        stage('Deploy to Staging') {
            steps {
                echo 'Deploying to staging environment...'
                sh 'kubectl apply -f k8s/staging/'
            }
        }
        stage('Smoke Test') {
            steps {
                echo 'Running smoke tests...'
                sh 'curl -f http://staging.example.com/health'
            }
        }
        stage('Deploy to Production') {
            when {
                branch 'main'
            }
            steps {
                echo 'Deploying to production...'
                sh 'kubectl apply -f k8s/production/'
            }
        }
    }
}
```

### 1.6.3 自动化测试

Jenkins 支持各种自动化测试：

```groovy
// 多层测试 Pipeline
pipeline {
    agent {
        docker {
            image 'maven:3.8-openjdk-17'
        }
    }
    stages {
        stage('Unit Tests') {
            steps {
                echo 'Running unit tests...'
                sh 'mvn test -Dtest=*Test'
            }
            post {
                always {
                    junit 'target/surefire-reports/*.xml'
                }
            }
        }

        stage('Integration Tests') {
            steps {
                echo 'Running integration tests...'
                sh 'mvn verify -Dintegration-tests'
            }
            post {
                always {
                    junit 'target/failsafe-reports/*.xml'
                }
            }
        }

        stage('UI Tests') {
            steps {
                echo 'Running UI tests with Selenium...'
                sh 'mvn test -Dtest=*UITest -Dselenium.grid.url=http://selenium:4444'
            }
        }

        stage('Performance Tests') {
            steps {
                echo 'Running performance tests...'
                sh 'k6 run tests/performance.js'
            }
            post {
                always {
                    publishHTML([
                        target: [
                            allowMissing: false,
                            alwaysLinkToLastBuild: true,
                            keepAll: true,
                            reportDir: 'target/reports',
                            reportFiles: 'performance-report.html',
                            reportName: 'Performance Report'
                        ]
                    ])
                }
            }
        }

        stage('Security Scan') {
            steps {
                echo 'Running security scans...'
                sh 'mvn dependency-check:check'
                sh 'npx zap-baseline.py -t http://localhost:3000'
            }
        }
    }
}
```

### 1.6.4 基础设施即代码（IaC）

Jenkins 可以用于自动化基础设施管理：

```groovy
// Terraform 基础设施部署 Pipeline
pipeline {
    agent {
        docker {
            image 'hashicorp/terraform:1.5'
        }
    }
    environment {
        TF_VAR_aws_access_key = credentials('aws-access-key')
        TF_VAR_aws_secret_key = credentials('aws-secret-key')
    }
    stages {
        stage('Init') {
            steps {
                echo 'Initializing Terraform...'
                sh 'terraform init -backend=s3 -backend-config=bucket=tf-state-123456'
            }
        }

        stage('Plan') {
            steps {
                echo 'Creating execution plan...'
                sh 'terraform plan -out=tfplan'
                archiveArtifacts artifacts: 'tfplan', fingerprint: true
            }
        }

        stage('Approval') {
            when {
                branch 'main'
            }
            steps {
                echo 'Waiting for approval...'
                script {
                    def approve = input message: 'Approve Terraform deployment?',
                        parameters: [
                            choice(name: 'APPROVE', choices: ['yes', 'no'], description: 'Approve deployment')
                        ]
                    if (approve == 'no') {
                        error 'Deployment rejected by user'
                    }
                }
            }
        }

        stage('Apply') {
            steps {
                echo 'Applying Terraform changes...'
                sh 'terraform apply -auto-approve tfplan'
            }
        }

        stage('Verify') {
            steps {
                echo 'Verifying infrastructure...'
                sh 'terraform show'
            }
        }
    }
}
```

### 1.6.5 多平台构建

Jenkins 支持在多个平台上构建和测试：

```groovy
// 多平台构建 Pipeline
pipeline {
    agent none
    stages {
        stage('Build on Linux') {
            agent {
                label 'linux'
            }
            steps {
                echo 'Building on Linux...'
                sh 'make build-linux'
            }
        }

        stage('Build on Windows') {
            agent {
                label 'windows'
            }
            steps {
                echo 'Building on Windows...'
                bat 'make build-windows'
            }
        }

        stage('Build on macOS') {
            agent {
                label 'macos'
            }
            steps {
                echo 'Building on macOS...'
                sh 'make build-macos'
            }
        }

        stage('Cross-platform Tests') {
            parallel {
                stage('Test on Linux') {
                    agent { label 'linux' }
                    steps {
                        echo 'Testing on Linux...'
                        sh 'make test'
                    }
                }
                stage('Test on Windows') {
                    agent { label 'windows' }
                    steps {
                        echo 'Testing on Windows...'
                        bat 'make test'
                    }
                }
            }
        }
    }
}
```
