# 第3章 Jenkins 基础配置

> 本章介绍 Jenkins 安装完成后的基础配置工作，包括系统配置、全局工具配置、安全策略、通知集成以及配置即代码（JCasC）。掌握这些内容是熟练使用 Jenkins 的前提。

---

## 3.1 系统配置（Manage Jenkins）

### 3.1.1 进入系统配置

通过浏览器访问 Jenkins 控制台（默认为 `http://localhost:8080`），点击左侧菜单 **"Manage Jenkins"** 进入管理页面。

主要入口包括：

| 路径 | 功能 |
|------|------|
| Manage Jenkins | 主管理页面 |
| System Log | 日志查看 |
| Load Statistics | 负载统计 |
| Manage Plugins | 插件管理 |
| Configure System | 全局系统配置 |
| Global Tool Configuration | 全局工具配置 |
| Manage Users | 用户管理 |

### 3.1.2 系统日志（System Log）

Jenkins 会记录所有内部日志，出问题时这里是排查的第一线。

**查看日志：**

1. 进入 **Manage Jenkins** → **System Log**
2. 选择 **All Jenkins Logs** 或 **Java Memory Logs**
3. 日志可以实时刷新（Live Updates）

**日志级别配置：**

在 `jenkins.xml` 中可以添加系统属性调整日志级别：

```xml
<!-- D:\Work\cicd\jenkins\jenkins.xml (Windows) -->
<service>
  <id>jenkins</id>
  <name>Jenkins</name>
  <description>Jenkins CI Server</description>
  <executable>%BASE%\jre\bin\java.exe</executable>
  <arguments>-Xrs -Xmx2048m -Dhudson.lifecycle.HudsonLifecycle生命周期类 -Djenkins.model.Jenkins.logStartupPerformance=true -verbose:gc -logger:ALL=800</arguments>
</service>
```

通过系统属性覆盖日志级别。在脚本控制台（Manage Jenkins → Script Console）执行：

```groovy
// 动态修改日志级别（临时生效，重启后失效）
import java.util.logging.Level
import java.util.logging.Logger

// 获取所有日志记录器并设置级别
Logger.getLogger("org.jenkinsci.plugins").setLevel(Level.FINE)
Logger.getLogger("hudson").setLevel(Level.FINE)

// 输出验证
println "日志级别已修改"
```

### 3.1.3 Jenkins Location 配置

**配置 Jenkins URL（重要）：**

进入 **Manage Jenkins** → **Configure System** → **Jenkins Location**：

- **Jenkins URL**：Jenkins 的访问地址，用于邮件、钉钉通知中生成链接。必须使用外网可访问的真实地址。
- **System Admin e-mail address**：系统管理员邮箱

> **常见错误**：如果 Jenkins URL 配置为 `localhost:8080`，则 Pipeline 发送的通知链接在团队成员打开时会是无效链接。

```groovy
// 在 Pipeline 中获取 Jenkins URL
def jenkinsUrl = JenkinsLocationConfiguration.get().getUrl()
echo "Jenkins URL: ${jenkinsUrl}"
```

### 3.1.4 构建行为限制（Build Configure）

在 **Configure System** 页面中，还可以设置：

| 配置项 | 说明 | 推荐值 |
|--------|------|--------|
| # of executors | Master 同时运行的最大构建数 | CPU 核心数 |
| Mode | 执行器运行模式 | Normal（允许在 Master 运行 job）|
| Host黑名单 | 禁止某些节点执行构建 | 按需配置 |
| Quiet Period | 等待多长时间收集 SCM 变更 | 默认5秒 |
| Pipeline скорость（Slow Build Config） | 超时阈值 | 按需配置 |

## 3.2 全局工具配置（Global Tool Configuration）

**进入路径：** **Manage Jenkins** → **Global Tool Configuration**

全局工具用于所有 Job 和 Pipeline 中引用，是标准化 CI/CD 环境的关键。

### 3.2.1 JDK 配置

**自动安装 JDK：**

1. 点击 **Add JDK** → 勾选 **Install automatically**
2. 选择版本或输入自定义版本号
3. Jenkins 会从指定渠道下载并安装

**Oracle JDK 需要认证：**

在 **Manage Jenkins** → **Configure Credentials** 中添加 Oracle 账号token，或者配置自建的 JDK 镜像源。

**手动配置（推荐生产环境使用）：**

1. 不勾选自动安装
2. 指定 `JAVA_HOME` 路径

```groovy
// Pipeline 中引用全局工具配置的 JDK
pipeline {
    agent any
    tools {
        jdk "jdk-17"  // 对应 Global Tool Configuration 中配置的名称
    }
    stages {
        stage('Build') {
            steps {
                sh 'java -version'
                sh 'mvn -version'
            }
        }
    }
}
```

**Windows 节点上的 JDK 配置：**

如果使用 Windows 节点，需要在节点配置中单独设置 JDK 路径：

```groovy
// 在 Windows 节点上使用指定的 JDK
node('windows-agent') {
    stage('Build') {
        bat '"C:\Program Files\Java\jdk-17\bin\java.exe" -version'
    }
}
```

### 3.2.2 Maven 配置

**自动安装 Maven：**

1. 点击 **Add Maven** → 勾选 **Install automatically**
2. 选择版本或自定义版本

**配置文件和 settings.xml：**

Maven 行为可以通过 `settings.xml` 配置，包括：
- 镜像仓库
- 私有仓库认证
- 本地仓库路径
- JVM 参数

```xml
<!-- ~/.m2/settings.xml -->
<?xml version="1.0" encoding="UTF-8"?>
<settings xmlns="http://maven.apache.org/SETTINGS/1.0.0"
          xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
          xsi:schemaLocation="http://maven.apache.org/SETTINGS/1.0.0
                              http://maven.apache.org/xsd/settings-1.0.0.xsd">
    <localRepository>D:\maven-repo</localRepository>

    <mirrors>
        <mirror>
            <id>aliyun-maven</id>
            <name>Aliyun Maven Mirror</name>
            <url>https://maven.aliyun.com/repository/public</url>
            <mirrorOf>central</mirrorOf>
        </mirror>
    </mirrors>

    <servers>
        <server>
            <id>nexus-releases</id>
            <username>admin</username>
            <password>admin123</password>
        </server>
        <server>
            <id>nexus-snapshots</id>
            <username>admin</username>
            <password>admin123</password>
        </server>
    </servers>

    <profiles>
        <profile>
            <id>nexus-profile</id>
            <repositories>
                <repository>
                    <id>nexus-releases</id>
                    <url>http://nexus.example.com/repository/maven-releases/</url>
                    <releases><enabled>true</enabled></releases>
                    <snapshots><enabled>false</enabled></snapshots>
                </repository>
                <repository>
                    <id>nexus-snapshots</id>
                    <url>http://nexus.example.com/repository/maven-snapshots/</url>
                    <releases><enabled>false</releases>
                    <snapshots><enabled>true</enabled></snapshots>
                </repository>
            </repositories>
        </profile>
    </profiles>

    <activeProfiles>
        <activeProfile>nexus-profile</activeProfile>
    </activeProfiles>
</settings>
```

**在 Pipeline 中使用自定义 settings.xml：**

```groovy
pipeline {
    agent any
    tools {
        maven 'maven-3.9.6'
    }
    stages {
        stage('Build') {
            steps {
                sh '''
                    mvn -s ~/.m2/settings.xml clean deploy \
                        -DskipTests=false \
                        -Dmaven.test.failure.ignore=false
                '''
            }
        }
    }
    post {
        always {
            archiveArtifacts artifacts: '**/target/*.jar', fingerprint: true
        }
    }
}
```


### 3.2.4 Node.js 配置

**安装 Node.js 工具：**

1. 进入 **Manage Jenkins** → **Manage Plugins** → **Available**
2. 安装 **NodeJS** 插件
3. 进入 **Global Tool Configuration** → **Add NodeJS**
4. 勾选 **Install automatically**，选择版本或输入版本号

**配置 NPM 镜像（加速国内下载）：**

```groovy
// Pipeline 中配置 NPM 镜像
pipeline {
    agent any
    environment {
        NPM_CONFIG_REGISTRY = 'https://registry.npmmirror.com'
    }
    tools {
        nodejs 'node-20'
    }
    stages {
        stage('Install') {
            steps {
                sh '''
                    npm config set registry https://registry.npmmirror.com
                    npm install --legacy-peer-deps
                '''
            }
        }
        stage('Build') {
            steps {
                sh 'npm run build'
            }
        }
    }
}
```

**多版本 Node.js 项目：**

```groovy
// 同时使用多个 Node.js 版本进行测试
pipeline {
    agent any
    stages {
        stage('Test on Node 18') {
            steps {
                script {
                    def node18 = tool name: 'node-18', type: 'nodejs'
                    env.PATH = "${node18}/bin:${env.PATH}"
                }
                sh 'node --version && npm test'
            }
        }
        stage('Test on Node 20') {
            steps {
                script {
                    def node20 = tool name: 'node-20', type: 'nodejs'
                    env.PATH = "${node20}/bin:${env.PATH}"
                }
                sh 'node --version && npm test'
            }
        }
    }
}
```

## 3.3 安全配置

> 安全是 Jenkins 配置中最重要也最复杂的部分。本节详细介绍用户注册、权限模型和两种主要授权策略。

### 3.3.1 启用安全控制

**初始设置：** Jenkins 默认是**不启用安全控制**的（安装后第一次访问会有引导）。生产环境**必须启用**。

**进入配置：** **Manage Jenkins** → **Configure Global Security**

### 3.3.2 安全realm（认证方式）

#### 1. Jenkins 内置用户数据库（默认）

```groovy
// 通过脚本创建用户（Script Console）
import hudson.model.User
import jenkins.security.HudsonPrivateSecurityRealm
import jenkins.security.SecurityRealm

def realm = Jenkins.getInstance().getSecurityRealm()
if (realm.class == HudsonPrivateSecurityRealm) {
    // 创建用户
    def user = User.getById('developer1', true)
    user.addProperty(hudson.security.HudsonPrivateSecurityRealm.class)
    
    // 设置密码（通过 API 或手动在 UI 中设置）
    println "User developer1 created"
}
```

通过 UI 管理用户：进入 **Manage Jenkins** → **Manage Users** → **Create User**

#### 2. LDAP 集成（企业常用）

```groovy
// LDAP 配置示例（通过 JCasC 配置）
// 见 3.6 JCasC 节
```

### 3.3.3 授权策略

#### 1. 矩阵授权策略（Matrix Authorization Strategy）

**进入：** **Manage Jenkins** → **Configure Global Security** → **Authorization** → **Matrix-based Security**

**权限矩阵说明：**

| 权限类别 | 权限项 | 说明 |
|----------|--------|------|
| **Overall** | Administer | 完整管理员权限 |
| | Configure | 配置系统设置 |
| | Read | 读取视图和Job |
| | RunScripts | 运行脚本 |
| **Credentials** | Manage | 管理凭证 |
| | Update | 更新凭证 |
| | Delete | 删除凭证 |
| | View | 查看凭证 |
| **Agent** | Connect | 连接节点 |
| | Disconnect | 断开节点 |
| **Job** | Create | 创建Job |
| | Delete | 删除Job |
| | Configure | 配置Job |
| | Read | 查看Job |
| | Build | 执行构建 |
| | Workspace | 访问工作区 |
| **View** | Create | 创建视图 |
| | Configure | 配置视图 |
| | Delete | 删除视图 |
| | Read | 查看视图 |
| **SCM** | Tag | SCM 标签操作 |

**典型配置场景：**

```groovy
// 典型权限矩阵配置（JCasC YAML）
security:
  matrix:
    entries:
      - user: admin
        permissions:
          - Overall/Administer
          - Overall/Configure
          - Overall/Read
          - Credentials/Manage
          - Credentials/Update
          - Credentials/Delete
          - Credentials/View
          - Agent/Connect
          - Agent/Disconnect
          - Job/Create
          - Job/Delete
          - Job/Configure
          - Job/Read
          - Job/Build
          - Job/Workspace
          - Job/Extensions
          - View/Create
          - View/Configure
          - View/Delete
          - View/Read
          - SCM/Tag
      - user: developer
        permissions:
          - Overall/Read
          - Credentials/View
          - Job/Configure
          - Job/Read
          - Job/Build
          - Job/Workspace
          - View/Read
      - user: viewer
        permissions:
          - Overall/Read
          - Job/Read
          - View/Read
```

#### 2. 基于角色的授权策略（Role-Based Authorization Strategy）

**安装插件：** Role-based Authorization Strategy

**启用：** **Manage Jenkins** → **Configure Global Security** → **Authorization** → **Role-Based Strategy**

**配置路径：** **Manage Jenkins** → **Manage and Assign Roles**

**角色类型：**

| 角色类型 | 说明 |
|----------|------|
| Global roles | 全局角色，影响整个 Jenkins |
| Project roles | 项目角色，匹配特定 Job 模式 |
| Agent roles | 节点角色，管理 Agent 权限 |

**角色创建示例：**

```groovy
// 通过 Script Console 创建角色
import jenkins.model.Jenkins
import org.jenkinsci.plugins.rolestrategy.model.Role
import org.jenkinsci.plugins.rolestrategy.model.RoleType
import org.jenkinsci.plugins.rolestrategy.RoleStrategy
import org.jenkinsci.plugins.rolestrategy.permissions.PermissionHelper

def strategy = Jenkins.getInstance().getAuthorizationStrategy()
if (strategy instanceof RoleStrategy) {
    // 添加全局角色
    def adminRole = new Role("admin", Collections.emptySet()) // 权限在 UI 中设置
    def developerRole = new Role("developer", Collections.emptySet())
    def viewerRole = new Role("viewer", Collections.emptySet())
    
    println "Role strategy configured"
}
```

**通过 UI 管理角色：**

1. **Manage Jenkins** → **Manage and Assign Roles** → **Manage Roles**
2. 添加全局角色：
   - **admin**：授予所有权限
   - **developer**：Job 构建和配置权限
   - **viewer**：只读权限
3. 添加项目角色（Project roles）：
   - **frontend-dev**：匹配 `frontend-*` 模式的 Job
   - **backend-dev**：匹配 `backend-*` 模式的 Job

**分配角色给用户：**

1. 进入 **Manage and Assign Roles** → **Assign Roles**
2. 在 **Global roles** 部分添加用户
3. 在 **Project roles** 部分添加用户并指定匹配模式

```groovy
// 项目角色匹配模式示例
// Pattern: backend-.*  → 匹配 backend-api, backend-service 等 Job
// Pattern: frontend-.*  → 匹配 frontend-web, frontend-app 等 Job
// Pattern: .*-deploy    → 匹配所有以 -deploy 结尾的 Job
```

**权限速查表：**

| 角色 | Overall | Credentials | Job | Agent | View |
|------|---------|-------------|-----|-------|------|
| admin | Administer | Manage | 所有 | 所有 | 所有 |
| developer | Read | View | Build, Configure, Read | Connect | Read |
| viewer | Read | - | Read | - | Read |
| deployer | Read | - | Read, Build, Workspace | - | Read |

### 3.3.4 安全配置检查清单

> 生产环境 Jenkins 安全配置检查清单：

```markdown
□ 启用安全控制（Configure Global Security）
□ 选择合适的认证方式（内置用户 / LDAP / SSO）
□ 配置授权策略（矩阵 / Role-based）
□ 禁用注册功能（如果不需要用户自助注册）
□ 配置 CSRF 保护（默认启用，勿关闭）
□ 启用 CLI 远程认证（如果使用 Jenkins CLI）
□ 配置会话超时时间
□ 审计日志记录（Audit Log Plugin）
□ 限制节点访问权限
□ 敏感信息使用凭证而非明文配置
□ 定期审查用户和权限
□ 禁用不安全的插件和功能
□ 配置 IP 白名单（如果你使用的是 Jenkins Enterprise）
```

### 3.4.2 Pipeline 中发送邮件

**使用 mail 步骤：**

```groovy
pipeline {
    agent any
    stages {
        stage('Build') {
            steps {
                sh 'mvn clean package -DskipTests'
            }
        }
    }
    post {
        success {
            mail to: 'team@example.com',
                 subject: "Jenkins Build Success: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                 body: """
                    构建成功！
                    项目: ${env.JOB_NAME}
                    构建号: #${env.BUILD_NUMBER}
                    构建URL: ${env.BUILD_URL}
                    触发人: ${currentBuild.buildCauses shortDescription}
                 """
        }
        failure {
            mail to: 'team@example.com',
                 subject: "Jenkins Build FAILED: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                 body: """
                    构建失败！
                    项目: ${env.JOB_NAME}
                    构建号: #${env.BUILD_NUMBER}
                    构建URL: ${env.BUILD_URL}
                    失败阶段: ${currentBuild.phase}
                    失败原因: ${currentBuild.result}
                 """
        }
        always {
            mail to: 'team@example.com',
                 subject: "Jenkins Build Result: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                 body: """
                    构建状态: ${currentBuild.result ?: 'SUCCESS'}
                    项目: ${env.JOB_NAME}
                    构建号: #${env.BUILD_NUMBER}
                    构建URL: ${env.BUILD_URL}
                    持续时间: ${currentBuild.durationString}
                 """
        }
    }
}
```

```groovy
def sign(String secret) {
    def algorithm = 'HmacSHA256'
    def signature = javax.crypto.Mac.getInstance(algorithm).with {
        init(secret.getBytes('UTF-8'))
        doFinal(Base64.getDecoder().decode(secret))

    return URLEncoder.encode(signature, 'UTF-8')
```

### 3.6.1 安装 JCasC 插件

## 3.7 本章小结

本章详细介绍了 Jenkins 的基础配置，核心要点如下：

1. **系统配置**：Jenkins Location 的 URL 必须配置为外网可访问的真实地址，否则通知链接会失效
2. **全局工具配置**：通过统一管理 JDK、Maven、Gradle、Node.js 等工具，实现 CI/CD 环境标准化
3. **安全配置**：生产环境必须启用安全控制，推荐使用 LDAP 或 SSO 实现统一认证；授权策略根据团队规模选择矩阵授权或基于角色的授权
4. **邮件通知**：使用 Extended E-mail Plugin 实现灵活的邮件通知配置，支持 HTML 格式和构建日志附件
5. **即时通讯集成**：Slack、钉钉、企业微信各有优劣，根据团队情况选择；优先使用官方插件，其次使用 Webhook 原生方式
6. **JCasC**：通过声明式 YAML 管理 Jenkins 配置，实现配置的版本化和可复现，是 DevOps 最佳实践

下一章将介绍 **Pipeline 语法与实践**，学习如何使用 Jenkinsfile 实现自动化构建流程。
