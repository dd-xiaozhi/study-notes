## 12.1 Jenkins 日志体系

Jenkins 的日志系统是排查问题的重要依据。理解不同日志的作用和位置，是进行有效监控和故障排除的基础。

### 12.1.1 系统日志

Jenkins 系统日志记录了 Controller 的运行状态、插件行为、内存使用情况等核心信息。

#### 日志位置

```
# Linux/macOS
/var/log/jenkins/jenkins.log

# Windows
%JENKINS_HOME%\jenkins.out
%JENKINS_HOME%\jenkins.err

# Docker 容器
docker logs <container_name>
```

#### 查看系统日志的方法

**方法一：通过 Jenkins Web 界面**

1. 登录 Jenkins
2. 进入 **Manage Jenkins** → **System Log**
3. 选择 **All Jenkins Logs** 查看完整日志

**方法二：通过脚本控制台**

访问 `<JENKINS_URL>/script` 执行日志查询：

```groovy
// 查看最近的系统日志
println Jenkins.LocationConfiguration.get().getUrl()
println hudson.model.Hudson.getInstance().getLogRecords()
```

#### 系统日志主要内容

```
# 日志格式示例
May 20, 2024 10:15:32 AM org.jenkinsci.main.modules.systems.SystemConfigurationMonitor lambda$getConfigPage$0
INFO: System configuration monitor initialized

May 20, 2024 10:15:33 AM hudson.model.Run run
INFO: Job test-job #123 started at 2024-05-20T10:15:33Z

May 20, 2024 10:15:45 AM hudson.model.AsyncAperiodicWork$1 lambda$doAperiodicRun$0
WARNING: Slow async operation: took 45s for 'Workspace cleanup'
```

#### 日志轮转配置

在 `jenkins.yaml` 或 `JENKINS_HOME` 目录配置日志轮转：

```yaml
# /etc/jenkins/jenkins.yaml
logrotate:
  days: 7
  count: 10
  compress: true
```

或在 Log4j 配置中（`$JENKINS_HOME/jenkins.logging.properties`）：

```properties
# 日志轮转配置
log4j.appender.file.File=/var/log/jenkins/jenkins.log
log4j.appender.file.MaxFileSize=100MB
log4j.appender.file.MaxBackupIndex=10

# 按时间轮转（每日）
log4j.appender.fileByDay=org.apache.log4j.DailyRollingFileAppender
log4j.appender.fileByDay.DatePattern='.'yyyy-MM-dd
```

### 12.1.2 Job 日志

每个 Job 的构建日志独立存储，是排查构建失败的核心依据。

#### 日志存储位置

```
$JENKINS_HOME/jobs/<job_name>/builds/<build_number>/log
```

#### 日志查看方式

**方式一：Web 界面**

- 控制台输出：`Job 页面 → Build History → 点击构建编号 → Console Output`
- 完整日志文件：`Job 页面 → Build History → 点击构建编号 → Log`

**方式二：REST API**

```bash
# 获取构建日志
curl -s http://localhost:8080/job/my-job/123/logText/progressiveText

# 获取最后 100 行
curl -s "http://localhost:8080/job/my-job/123/logText/progressiveText?start=0" | tail -100

# 获取带过滤的日志（只显示错误）
curl -s "http://localhost:8080/job/my-job/123/logText/progressiveText?type=error"
```

**方式三：Jenkins CLI**

```bash
java -jar jenkins-cli.jar -s http://localhost:8080 build-log my-job -b 123
```

#### Pipeline 日志的特别处理

```groovy
// Jenkinsfile - Pipeline 脚本中控制日志输出

pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                script {
                    echo "当前工作目录: ${pwd()}"
                    sh '''
                        echo "开始构建..."
                        ./gradlew build
                    '''
                }
            }
        }
        stage('Test') {
            steps {
                script {
                    // 使用 catchError 捕获错误但不立即失败
                    catchError(buildResult: 'FAILURE', stageResult: 'FAILURE') {
                        sh './gradlew test'
                    }
                }
            }
        }
    }

    post {
        always {
            echo "构建状态: ${currentBuild.result}"
            archiveArtifacts artifacts: 'build/**/*.jar', fingerprint: true
            junit testResults: 'build/test-results/**/*.xml'
        }
        failure {
            echo "构建失败！查看日志获取详情"
        }
    }
}
```

#### 日志持久化策略

建议在 Job 配置中启用日志保留策略：

```groovy
// 在 Jenkinsfile 中配置日志保留
properties([
    buildDiscarder(
        logRotator(
            daysToKeepStr: '30',           // 保留30天
            numToKeepStr: '100',            // 保留最近100个构建
            artifactDaysToKeepStr: '14',    // 构件保留14天
            artifactNumToKeepStr: '50'      // 构件保留最近50个
        )
    )
])
```

### 12.1.3 Agent 日志

Agent 日志记录了分布式构建中远程节点的活动情况。

#### Agent 日志位置

```
# Linux Agent
/var/log/jenkins-agent/jenkins-agent.log

# Windows Agent
%AGENT_HOME%\logs\jenkins-agent.log

# Kubernetes Agent (Jenkins Agent 容器内)
/var/log/jenkins-agent.log
```

#### Agent 日志内容详解

```
# Agent 启动日志示例
May 20, 2024 09:00:15 AM hudson.remoting.jnlp.Main lambda$main$4
INFO: Running as user: jenkins-agent
May 20, 2024 09:00:16 AM org.jenkinsci.remoting.engine.WorkDirManager lambda$getWorkDirFile$0
INFO: Work directory: /home/jenkins/agent
May 20, 2024 09:00:17 AM hudson.remoting.jnlp.Main lambda$main$5
INFO: Connected to master

# Agent 执行任务日志
May 20, 2024 09:05:22 AM hudson.remoting.Channel lambda$buildTask$0
INFO: Executing job: deploy-job on agent-01
May 20, 2024 09:05:25 AM hudson.FilePath lambda$installMandatory Software$0
INFO: Installing tools: gradle 8.5
```

#### Agent 连接问题排查

当 Agent 连接断开时，查看以下日志：

```bash
# 查找 Agent 断开连接的时间点
grep "Connection closed" /var/log/jenkins-agent/jenkins-agent.log

# 查找网络超时
grep "SocketTimeout" /var/log/jenkins-agent/jenkins-agent.log

# 查找认证失败
grep "Authentication failed" /var/log/jenkins-agent/jenkins-agent.log
```

## 12.2 日志级别配置与调试

### 12.2.1 日志级别详解

Jenkins 使用 Java Util Logging (JUL) 和 Log4j 两种日志框架。日志级别从低到高：

| 级别 | 说明 | 使用场景 |
|------|------|----------|
| FINEST | 最详细 | 跟踪代码执行流程 |
| FINER | 很详细 | 调试插件行为 |
| FINE | 详细 | 一般调试 |
| CONFIG | 配置信息 | 查看配置加载 |
| INFO | 一般信息 | 正常运行日志 |
| WARNING | 警告 | 潜在问题提示 |
| SEVERE | 错误 | 严重错误需要处理 |
| ALL | 全部日志 | 最大详细程度 |
| OFF | 关闭日志 | 禁用该类别日志 |

### 12.2.2 日志配置界面

#### 通过 Web 界面配置

1. 进入 **Manage Jenkins** → **System Log** → **Log recorder**
2. 创建新的 Log Recorder（例如 `PluginDebug`）
3. 添加感兴趣的日志类

```
# 常用日志类
org.jenkinsci.plugins                 # 插件相关
hudson.model.Hudson                   # Hudson 模型
hudson.PluginManager                  # 插件管理器
org.jenkinsci.main.modules.systems   # 系统模块
hudson.slaves.SlaveComputer           # Agent 连接
```

#### 配置文件方式

在 `$JENKINS_HOME/logging.properties` 中配置：

```properties
# 根日志级别
handlers=java.util.logging.ConsoleHandler, java.util.logging.FileHandler
.level=INFO

# Jenkins 核心日志
hudson.level=INFO
hudson.model.Hudson.level=FINE
hudson.model.Job.level=FINE

# 插件日志
org.jenkinsci.plugins.pipeline.level=FINE
org.jenkinsci.plugins.workflow.level=FINEST

# Agent 相关
hudson.slaves.SlaveComputer.level=ALL
hudson.remoting.level=ALL

# 控制台输出格式
java.util.logging.ConsoleHandler.formatter=java.util.logging.SimpleFormatter
java.util.logging.SimpleFormatter.format=[%1$tF %1$tT] %4$s %3$s %2$s %5$s%6$s%n
```

### 12.2.3 调试技巧

#### 启用特定组件的调试日志

```groovy
// 在脚本控制台启用特定插件的调试日志
import java.util.logging.*
import jenkins.model.Jenkins

// 获取日志管理器
def logger = Logger.getLogger("org.jenkinsci.plugins.docker")
logger.setLevel(Level.ALL)

// 添加文件处理器
def handler = new FileHandler("/var/log/jenkins/plugin-debug.log", true)
handler.setFormatter(new SimpleFormatter())
logger.addHandler(handler)
```

#### Pipeline 调试技巧

```groovy
// Jenkinsfile - 启用 Pipeline 调试

@Library('custom-library@v1.0') _

pipeline {
    agent { label 'docker' }

    options {
        // 启用详细的步骤日志
        timestamps()
        timeout(time: 1, unit: 'HOURS')
    }

    environment {
        // 启用详细输出
        MAVEN_OPTS = "-Xmx1024m -Xdebug -Xrunjdwp:transport=dt_socket,server=y,suspend=n,address=5005"
    }

    stages {
        stage('Debug Environment') {
            steps {
                script {
                    echo "=== 环境变量 ==="
                    sh 'printenv | sort'

                    echo "=== Java 版本 ==="
                    sh 'java -version'

                    echo "=== 工作目录 ==="
                    sh 'pwd && ls -la'
                }
            }
        }

        stage('Build with Debug') {
            steps {
                script {
                    // 使用 -x 标志显示执行的命令
                    // 或者使用 sh returnStdout
                    def buildOutput = sh(script: './gradlew build --info', returnStdout: true)
                    echo "构建输出: ${buildOutput}"
                }
            }
        }
    }

    post {
        always {
            echo "=== 最终状态 ==="
            echo "构建结果: ${currentBuild.result}"
            echo "持续时间: ${currentBuild.durationString}"
        }
    }
}
```

#### 获取堆栈跟踪

当遇到异常时，获取详细的堆栈跟踪：

```groovy
// 在脚本控制台
import java.io.StringWriter
import java.io.PrintWriter

try {
    // 执行可能失败的代码
    jenkins.model.Jenkins.instance.getExtensionList(hudson.model.Descriptor)
} catch (Exception e) {
    StringWriter sw = new StringWriter()
    PrintWriter pw = new PrintWriter(sw)
    e.printStackTrace(pw)
    println "堆栈跟踪: ${sw.toString()}"
}
```

## 12.3 Prometheus 监控集成

Prometheus 是 CNCF 的毕业项目，是云原生监控的事实标准。通过 Prometheus 可以采集 Jenkins 的各种指标，实现可视化监控和告警。

### 12.3.1 安装 Prometheus Plugin

#### 安装步骤

1. 进入 **Manage Jenkins** → **Manage Plugins**
2. 在 **Available** 标签搜索 `Prometheus`
3. 安装 `Prometheus Metrics Plugin`
4. 重启 Jenkins

#### 验证安装

```
# 检查 Prometheus endpoint 是否可用
curl http://localhost:8080/prometheus/
```

成功时会返回类似以下内容：

```
# HELP jenkins_node_builds_total Number of builds on node
# TYPE jenkins_node_builds_total counter
jenkins_node_builds_total{job="test-job",node="built-in"} 123

# HELP jenkins_job_duration_seconds Duration of job build in seconds
# TYPE jenkins_job_duration_seconds summary
jenkins_job_duration_seconds{job="deploy",quantile="0.5"} 45.2

# HELP jenkins_memory_used_bytes Jenkins memory usage in bytes
# TYPE jenkins_memory_used_bytes gauge
jenkins_memory_used_bytes{type="heap"} 524288000
```

### 12.3.2 Prometheus 配置

#### prometheus.yml 配置

```yaml
# /etc/prometheus/prometheus.yml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

scrape_configs:
  - job_name: 'jenkins'
    metrics_path: '/prometheus/'
    static_configs:
      - targets: ['localhost:8080']
        labels:
          instance: 'jenkins-master'
          environment: 'production'

  - job_name: 'jenkins-agent'
    metrics_path: '/prometheus/'
    static_configs:
      - targets:
          - 'agent-01:8080'
          - 'agent-02:8080'
        labels:
          instance: 'jenkins-agents'
```

#### Prometheus 关键指标

| 指标名称 | 类型 | 说明 |
|----------|------|------|
| jenkins_job_count_total | Counter | 总构建次数 |
| jenkins_job_duration_seconds | Summary | 构建持续时间 |
| jenkins_job_result_total | Counter | 构建结果（按状态分类） |
| jenkins_node_free_space_bytes | Gauge | 节点可用空间 |
| jenkins_node_executor_count | Gauge | 节点执行器数量 |
| jenkins_queue_size | Gauge | 队列大小 |
| jenkins_memory_used_bytes | Gauge | 内存使用 |
| jenkins_thread_count | Gauge | 线程数 |

#### 服务发现配置

对于 Kubernetes 环境，使用服务发现：

```yaml
# kubernetes-sd-config 示例
- job_name: 'jenkins-k8s'
  kubernetes_sd_configs:
    - role: pod
      namespaces:
        names:
          - jenkins
  relabel_configs:
    - source_labels: [__meta_kubernetes_pod_label_jenkins]
      action: keep
      regex: true
    - source_labels: [__meta_kubernetes_pod_container_port_number]
      action: replace
      target_label: __metrics_path__
      replacement: '/prometheus/'
```

### 12.3.3 关键指标解读

#### 构建相关指标

```bash
# 查看构建频率趋势
promtool query instant \
  'rate(jenkins_job_count_total[5m])'

# 查看构建成功率
promtool query instant \
  'sum(jenkins_job_result_total{result="success"}) / sum(jenkins_job_count_total)'

# 查看平均构建时间
promtool query instant \
  'jenkins_job_duration_seconds_mean'
```

#### 队列指标

```bash
# 当前队列大小
promtool query instant 'jenkins_queue_size_value'

# 队列等待时间过长的构建
promtool query instant \
  'jenkins_queue_age_seconds > 300'
```

#### 资源使用指标

```bash
# CPU 使用率
promtool query instant \
  'rate(process_cpu_seconds_total{job="jenkins"}[5m]) * 100'

# 内存使用趋势
promtool query instant \
  'jenkins_memory_used_bytes / jenkins_memory_max_bytes * 100'

# GC 频率
promtool query instant \
  'rate(jvm_gc_pause_seconds_count{job="jenkins"}[5m])'
```

## 12.4 Grafana 集成

Grafana 是开源的度量分析和可视化平台，支持从 Prometheus、Elasticsearch 等多种数据源读取数据。

### 12.4.1 Grafana 安装与配置

#### Docker 部署 Grafana

```bash
# 创建 Grafana 数据卷
docker volume create grafana-data

# 启动 Grafana
docker run -d \
  --name grafana \
  -p 3000:3000 \
  -v grafana-data:/var/lib/grafana \
  -e GF_SECURITY_ADMIN_PASSWORD=admin123 \
  -e GF_USERS_ALLOW_SIGN_UP=false \
  grafana/grafana:latest
```

#### 配置数据源

1. 访问 `http://localhost:3000`
2. 登录（默认 admin/admin）
3. 进入 **Configuration** → **Data Sources**
4. 添加 **Prometheus** 数据源：
   - URL: `http://localhost:9090`
   - Access: Server
   - 按需设置认证信息

```conf
    codec => json
  }

    path => "/var/log/jenkins/jenkins.log"

filter {
  # 解析 Jenkins 日志格式
  if [message] =~ /jenkins\.log/ {
    grok {
      match => {
        "message" => "%{TIMESTAMP_ISO8601:timestamp}\s+%{LOGLEVEL:level}\s+%{JAVACLASS:class}\s+-\s+%{GREEDYDATA:log_message}"
      }
    }
  }

  # 解析构建日志
  if [fields] and [fields][job_name] {
    mutate {
      add_field => {
        "job_name" => "%{[fields][job_name]}"
        "build_number" => "%{[fields][build_number]}"
      }
    }
  }

  # 时间戳处理
  date {
    match => [ "timestamp", "ISO8601" ]
    target => "@timestamp"
  }

  # 添加环境标签
  mutate {
    add_tag => ["jenkins", "production"]
  }
}

output {
  elasticsearch {
    hosts => ["http://elasticsearch:9200"]
    index => "jenkins-logs-%{+YYYY.MM.dd}"
    document_type => "_doc"
  }

}
```

#### 健康检查脚本

```groovy
// health-check.groovy - Jenkins 健康检查脚本

import jenkins.model.*
import hudson.model.*
import hudson.Functions

def checkJenkins() {
    def results = [:]

    // 检查1: Jenkins 是否可访问
    try {
        def jenkins = Jenkins.getInstance()
        results['jenkins_accessible'] = true
        results['jenkins_version'] = jenkins.version
        results['jenkins_mode'] = jenkins.mode
    } catch (Exception e) {
        results['jenkins_accessible'] = false
        results['jenkins_error'] = e.message
    }

    // 检查2: 磁盘空间
    try {
        def home = new File(Jenkins.getInstance().getRootDir.getAbsolutePath())
        def usableSpace = home.getUsableSpace()
        def totalSpace = home.getTotalSpace()
        def usedPercent = ((totalSpace - usableSpace) / totalSpace) * 100

        results['disk_used_percent'] = usedPercent
        results['disk_free_gb'] = usableSpace / (1024 * 1024 * 1024)

        if (usedPercent > 90) {
            results['disk_warning'] = "磁盘空间不足，超过 90% 已使用"
        }
    } catch (Exception e) {
        results['disk_error'] = e.message
    }

    // 检查3: 内存使用
    try {
        def runtime = Runtime.getRuntime()
        def totalMem = runtime.maxMemory()
        def freeMem = runtime.freeMemory()
        def usedMem = totalMem - freeMem

        results['memory_total_mb'] = totalMem / (1024 * 1024)
        results['memory_used_mb'] = usedMem / (1024 * 1024)
        results['memory_used_percent'] = (usedMem / totalMem) * 100
    } catch (Exception e) {
        results['memory_error'] = e.message
    }

    // 检查4: 队列状态
    try {
        def queue = Jenkins.getInstance().getQueue()
        results['queue_size'] = queue.items.size()

        if (queue.items.size() > 100) {
            results['queue_warning'] = "队列积压过多"
        }
    } catch (Exception e) {
        results['queue_error'] = e.message
    }

    // 检查5: Agent 状态
    try {
        def computers = Jenkins.getInstance().getComputers()
        def onlineAgents = computers.findAll { !it.isOffline() && !it.isTemporarilyOffline() }
        def offlineAgents = computers.findAll { it.isOffline() }

        results['total_agents'] = computers.size()
        results['online_agents'] = onlineAgents.size()
        results['offline_agents'] = offlineAgents.size()

        if (offlineAgents.size() > 0) {
            results['offline_agent_names'] = offlineAgents.collect { it.name }
        }
    } catch (Exception e) {
        results['agents_error'] = e.message
    }

    // 检查6: 最近构建统计
    try {
        def jobs = Jenkins.getInstance().getAllItems(Job.class)
        def recentBuilds = [:]

        jobs.each { job ->
            def lastBuild = job.getLastBuild()
            if (lastBuild) {
                recentBuilds[job.name] = [
                    number: lastBuild.number,
                    result: lastBuild.result?.toString() ?: "SUCCESS",
                    duration: lastBuild.duration
                ]
            }
        }

        results['recent_builds'] = recentBuilds
    } catch (Exception e) {
        results['builds_error'] = e.message
    }

    return results
}

println "=== Jenkins 健康检查报告 ==="
println new groovy.json.JsonOutput().toJson(checkJenkins())
```

## 12.7 常见问题排查

### 12.7.1 构建失败排查

#### 排查流程

```
1. 查看控制台输出
   └─ 识别错误类型（编译错误、测试失败、部署问题等）

2. 分析错误信息
   ├─ 编译错误 → 检查代码语法、依赖
   ├─ 测试失败 → 查看测试报告、覆盖率
   ├─ 部署失败 → 检查目标环境、网络连接
   └─ 权限错误 → 检查凭证、访问控制

3. 确认构建步骤
   └─ 回溯最近的变更

4. 检查 Agent 状态
   └─ 确认构建执行的节点
```

#### 常见错误及解决方案

**错误类型 1: 依赖下载失败**

```
# 控制台输出示例
[ERROR] Could not resolve dependencies:
Could not transfer artifact com.example:library:jar:1.0.0
from/to central (https://repo.maven.apache.org/maven2):
Connection timed out
```

解决方案：

```groovy
// 在 Jenkinsfile 中配置 Maven 镜像
pipeline {
    agent any
    options {
        timeout(time: 30, unit: 'MINUTES')
    }
    stages {
        stage('Build') {
            steps {
                script {
                    // 使用国内镜像
                    def mavenSettings = '''
                    <settings>
                      <mirrors>
                        <mirror>
                          <id>aliyun</id>
                          <url>https://maven.aliyun.com/repository/public</url>
                          <mirrorOf>central</mirrorOf>
                        </mirror>
                      </mirrors>
                    </settings>
                    '''

                    // 保存自定义 settings
                    writeFile file: 'custom-settings.xml', text: mavenSettings

                    sh './gradlew build -s -Dorg.gradle.configure.onDemand=true'
                }
            }
        }
    }
}
```

**错误类型 2: 权限问题**

```
# 控制台输出
[ERROR] Permission denied: /var/jenkins/workspace/deploy
```

解决方案：

```bash
# 检查目录权限
ls -la /var/jenkins/workspace/

chown -R jenkins:jenkins /var/jenkins/workspace/
```


解决方案：

```bash
# 清理工作空间

find /var/jenkins/workspace -type d -name "node_modules" -exec rm -rf {} +

# 清理旧的构建记录
jenkins-cli build-discarder --days 7
```

### 12.7.2 性能问题排查

#### 性能问题诊断流程

```
1. 识别瓶颈
   ├─ CPU 密集型 → 编译、打包
   ├─ IO 密集型 → 文件操作、网络
   └─ 内存密集型 → 大型构建、缓存

2. 检查资源使用
   ├─ top/htop → CPU、内存
   ├─ iostat → 磁盘 IO
   └─ netstat → 网络连接

3. 分析 Jenkins 线程
   └─ 线程 dump 分析
```

#### 性能分析工具脚本

```groovy
// performance-analysis.groovy

import jenkins.model.*
import hudson.model.*
import java.lang.management.*

// 收集性能数据
def collectPerformanceData() {
    def data = [:]

    // 操作系统信息
    def os = ManagementFactory.getOperatingSystemMXBean()
    data['os'] = [
        name: os.name,
        version: os.version,
        arch: os.arch,
        systemLoad: os.systemLoadAverage
    ]

    // 内存信息
    def runtime = Runtime.getRuntime()
    data['memory'] = [
        maxMemory: runtime.maxMemory() / (1024*1024),
        totalMemory: runtime.totalMemory() / (1024*1024),
        freeMemory: runtime.freeMemory() / (1024*1024),
        usedMemory: (runtime.totalMemory() - runtime.freeMemory()) / (1024*1024)
    ]

    // GC 信息
    def gcMxBeans = ManagementFactory.getGarbageCollectorMXBeans()
    data['gc'] = gcMxBeans.collect { gc ->
        [
            name: gc.name,
            collectionCount: gc.collectionCount,
            collectionTime: gc.collectionTime,
            memoryPools: gc.memoryPoolNames
        ]
    }

    // 线程信息
    def threadMx = ManagementFactory.getThreadMXBean()
    data['threads'] = [
        peakThreadCount: threadMx.peakThreadCount,
        currentThreadCount: threadMx.threadCount,
        daemonThreadCount: threadMx.daemonThreadCount
    ]

    // 类加载信息
    def classMx = ManagementFactory.getClassLoadingMXBean()
    data['classes'] = [
        loadedClassCount: classMx.loadedClassCount,
        totalLoadedClassCount: classMx.totalLoadedClassCount,
        unloadedClassCount: classMx.unloadedClassCount
    ]

    // Compilation
    def compileMx = ManagementFactory.getCompilationMXBean()
    if (compileMx) {
        data['compilation'] = [
            name: compileMx.name,
            totalCompilationTime: compileMx.totalCompilationTime
        ]
    }

    // Jenkins 特定信息
    def jenkins = Jenkins.getInstance()
    data['jenkins'] = [
        version: jenkins.version,
        mode: jenkins.mode.toString(),
        queueSize: jenkins.queue.items.size(),
        executors: [
            total: jenkins.getTotalExecutors(),
            busy: jenkins.busyExecutors
        ],
        nodes: jenkins.computers.collect { computer ->
            [
                name: computer.name,
                displayName: computer.displayName,
                isOnline: computer.isOnline(),
                executors: computer.executors.size(),
                isTemporarilyOffline: computer.isTemporarilyOffline()
            ]
        },
        jobs: jenkins.allItems.collect { item ->
            if (item instanceof Job) {
                def lastBuild = item.lastBuild
                [
                    name: item.fullName,
                    buildCount: item.builds.size(),
                    lastBuild: lastBuild ? [
                        number: lastBuild.number,
                        result: lastBuild.result?.toString(),
                        duration: lastBuild.duration
                    ] : null
                ]
            }
        }
    ]

    // 耗时最长的构建
    data['slowest_builds'] = jenkins.allItems
        .findAll { it instanceof Job }
        .collect { job -> job.builds }
        .flatten()
        .findAll { it != null }
        .collect { build ->
            [
                jobName: build.parent.fullName,
                buildNumber: build.number,
                duration: build.duration,
                timestamp: build.timestamp.time
            ]
        }
        .sort { -it.duration }
        .take(10)
```

### 12.7.3 内存泄漏检测

#### 内存泄漏典型症状

```
1. Jenkins UI 响应变慢
2. 构建执行时间逐渐增加
3. 频繁 GC 导致停顿
4. 内存使用持续增长
```

#### 内存泄漏排查脚本

```groovy
// memory-leak-check.groovy

import jenkins.model.*
import hudson.model.*
import java.lang.management.*

def analyzeMemoryLeaks() {
    def report = [:]

    // JVM 内存概览
    def runtime = Runtime.getRuntime()
    report['memory'] = [
        heapMax: runtime.maxMemory() / (1024*1024),
        heapUsed: (runtime.totalMemory() - runtime.freeMemory()) / (1024*1024),
        heapCommitted: runtime.totalMemory() / (1024*1024),
        nonHeapUsed: ManagementFactory.getMemoryMXBean().getNonHeapMemoryUsage().getUsed() / (1024*1024)
    ]

    // 内存池信息
    def memoryPools = ManagementFactory.getMemoryPoolMXBeans()
    report['memoryPools'] = memoryPools.collect { pool ->
        def usage = pool.getUsage()
        [
            name: pool.name,
            type: pool.type.toString(),
            used: usage?.getUsed() / (1024*1024),
            max: usage?.getMax() / (1024*1024),
            usagePercent: usage ? (usage.getUsed() * 100 / usage.getMax()) : 0
        ]
    }

    // GC 分析
    def gcPools = ManagementFactory.getGarbageCollectorMXBeans()
    report['gc'] = gcPools.collect { gc ->
        [
            name: gc.name,
            collectionCount: gc.collectionCount,
            collectionTime: gc.collectionTime,
            memoryPools: gc.memoryPoolNames
        ]
    }

    // 计算 GC 频率
    def runtimeMx = ManagementFactory.getRuntimeMXBean()
    def uptime = runtimeMx.getUptime()
    def totalGcCount = gcPools.sum { it.collectionCount } ?: 0
    def totalGcTime = gcPools.sum { it.collectionTime } ?: 0

    report['gcStats'] = [
        uptime: uptime,
        totalGcCount: totalGcCount,
        totalGcTime: totalGcTime,
        gcFrequency: totalGcCount / (uptime / 60000), // 次/分钟
        gcTimeRatio: totalGcTime / uptime // GC 时间占比
    ]

    // 检查可能的内存泄漏源

    // 1. 检查 Job 构建历史
    def jobs = Jenkins.getInstance().getAllItems(Job.class)
    report['jobsWithManyBuilds'] = jobs.collect { job ->
        def builds = job.builds
        [
            name: job.fullName,
            buildCount: builds.size(),
            oldestBuildAge: builds.size() > 0 ?
                (System.currentTimeMillis() - builds[0].timestamp.time) / (24*60*60*1000) + " days" :
                "N/A"
        ]
    ].findAll { it.buildCount > 500 }

    // 2. 检查 Queue
    def queue = Jenkins.getInstance().getQueue()
    report['queueSize'] = queue.items.size()
    report['queueWaitingItems'] = queue.items.collect { item ->
        [
            id: item.id,
            task: item.task.fullName,
            inQueueSince: item.inQueueSince,
            waitTime: System.currentTimeMillis() - item.inQueueSince
        ]
    }

    // 3. 检查 Computer 资源
    def computers = Jenkins.getInstance().getComputers()
    report['computers'] = computers.collect { computer ->
        [
            name: computer.name,
            isOnline: computer.isOnline(),
            executors: computer.executors.size(),
            builds: computer.builds.collect { it.number }
        ]
    }

    return report
}

println new groovy.json.JsonOutput().prettyPrint(
    new groovy.json.JsonOutput().toJson(analyzeMemoryLeaks())
)
```

```groovy
// cleanup.groovy - 磁盘空间清理

import jenkins.model.*
import hudson.model.*
import java.io.File

def cleanOldBuilds() {
    def jenkins = Jenkins.getInstance()
    def cleaned = [:]

    jenkins.allItems(Job.class).each { job ->
        def buildsToKeep = 50 // 默认保留最近50个构建
        def builds = job.builds

        if (builds.size() > buildsToKeep) {
            def buildsToDelete = builds.limit(builds.size() - buildsToKeep)
            def count = 0

            buildsToDelete.each { build ->
                try {
                    build.delete()
                    count++
                } catch (Exception e) {
                    println "Failed to delete build ${build.number}: ${e.message}"
                }
            }

            if (count > 0) {
                cleaned[job.fullName] = count
            }
        }
    }

    return cleaned
}

def cleanWorkspaces() {
    def jenkins = Jenkins.getInstance()
    def cleaned = []

    jenkins.allItems(Job.class).each { job ->
        def ws = job.workspace
        if (ws.exists()) {
            def size = ws.size()
            if (size > 1024 * 1024 * 1024) { // 超过 1GB
                cleaned << [
                    job: job.fullName,
                    size: "${size / (1024*1024)} MB"
                ]
            }
        }
    }

    return cleaned
}

def cleanOldLogs() {
    def logDir = new File(Jenkins.getInstance().rootDir, "logs")
    def now = System.currentTimeMillis()
    def maxAge = 7 * 24 * 60 * 60 * 1000 // 7 天

    if (logDir.exists()) {
        logDir.eachFile { file ->
            if (now - file.lastModified() > maxAge) {
                file.delete()
                println "Deleted old log: ${file.name}"
            }
        }
    }
}

def report = [
    deletedBuilds: cleanOldBuilds(),
    largeWorkspaces: cleanWorkspaces(),
    timestamp: new Date()
]

println new groovy.json.JsonOutput().toJson(report)
```

## 12.9 性能调优建议

### 9.1 JVM 调优

#### 推荐 JVM 参数

```bash
# /etc/jenkins/jenkins.conf (Debian/Ubuntu)
JAVA_ARGS="-Xms2g -Xmx4g -XX:+UseG1GC -XX:+UseStringDeduplication \
  -XX:+ParallelRefProcEnabled -XX:MaxGCPauseMillis=200 \
  -Djava.awt.headless=true"

# /etc/sysconfig/jenkins (RHEL/CentOS)
JENKINS_JAVA_OPTIONS="-Xms2g -Xmx4g -XX:+UseG1GC \
  -XX:G1ReservePercent=15 -XX:MaxGCPauseMillis=200 \
  -Dhudson.slaves.PingStrategy=com.jcraft.jenkins.SilentPingStrategy"
```

#### G1GC 调优参数详解

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| -Xms | 2g-4g | 初始堆大小 |
| -Xmx | 4g-8g | 最大堆大小 |
| -XX:+UseG1GC | - | 使用 G1 垃圾收集器 |
| -XX:MaxGCPauseMillis | 200 | 最大 GC 暂停时间目标 |
| -XX:G1ReservePercent | 10-15 | 预留内存百分比 |
| -XX:InitiatingHeapOccupancyPercent | 45 | 触发 Mixed GC 的堆使用率 |
