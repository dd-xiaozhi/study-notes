# 第10章：权限管理与安全配置

> 本章深入讲解 Jenkins 的权限管理与安全配置体系，包括用户认证、授权策略、凭证管理、API Token、安全审计等核心主题。通过本章的学习，你将掌握如何构建一个安全可靠的 Jenkins CI/CD 平台。

---

## 10.1 安全配置概述

### 10.1.1 Jenkins 安全架构

Jenkins 的安全体系主要包含两大核心概念：

- **Security Realm（安全域）**：负责验证用户身份，即"你是谁"
- **Authorization Strategy（授权策略）**：决定已认证用户的权限，即"你能做什么"

```
┌─────────────────────────────────────────────────────────────────┐
│                      Jenkins 安全架构                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌───────────────┐      ┌──────────────────┐                   │
│  │ Security Realm │ ──── │ Authorization     │                   │
│  │ (认证 - Who)   │      │ Strategy (授权)  │                   │
│  └───────────────┘      └──────────────────┘                   │
│         │                        │                              │
│         ▼                        ▼                              │
│  ┌───────────────┐      ┌──────────────────┐                   │
│  │ • 内置用户数据库 │      │ • 任何用户可以做任何事│                │
│  │ • LDAP         │      │ • 矩阵授权策略    │                   │
│  │ • Active Dir.  │      │ • Role-Based策略  │                   │
│  │ • OAuth/SSO    │      │ • 项目矩阵授权    │                   │
│  └───────────────┘      └──────────────────┘                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 10.1.2 启用安全配置

**默认情况下**：

- Jenkins 安装完成后**安全功能是禁用的**
- 任何人可以直接访问并执行任意操作
- **强烈建议在生产环境中立即启用安全配置**

**启用安全配置步骤**：

1. 进入 **Manage Jenkins** → **Security**
2. 在 **Security Realm** 部分选择用户认证方式
3. 在 **Authorization** 部分选择授权策略
4. 点击 **Save** 保存配置

### 10.1.3 安全配置页面详解

访问路径：**Manage Jenkins** → **Security**

```
安全配置页面结构
├── Security Realm（安全域）
│   ├── Jenkins' own user database（内置用户数据库）
│   ├── LDAP
│   ├── Active Directory
│   ├── Unix user/group database
│   └── SAML 2.0
│
├── Authorization（授权策略）
│   ├── Anyone can do anything（任何人都可以做任何事）
│   ├── Legacy mode（遗留模式）
│   ├── Logged-in users can do anything（已登录用户可以做任何事）
│   ├── Matrix-based security（矩阵授权策略）
│   └── Role-Based strategy（基于角色的授权策略）
│
├── Markup Formatter（标记格式化器）
│   ├── Safe HTML
│   ├── ESCAPE_NEWLINES
│   └── Raw HTML
│
└── CSRF Protection（CSRF 保护）
    └── Enable proxy compatibility
```

## 10.2 用户认证（Security Realm）

### 10.2.1 内置用户数据库

Jenkins 内置了一个简单的用户数据库，适合小型团队或测试环境。

**启用内置用户数据库**：

1. 进入 **Manage Jenkins** → **Security**
2. 选择 **Security Realm** → **Jenkins' own user database**
3. 勾选 **Allow users to sign up**（允许用户注册）

**创建用户**：

1. 进入 **Manage Jenkins** → **Manage Users**
2. 点击 **Create User**
3. 填写用户名、密码、确认密码、邮箱
4. 点击 **Create User** 完成创建

**用户配置文件**（`$JENKINS_HOME/users/`）：

```
$JENKINS_HOME/users/
├── users.xml              # 用户索引文件
├── admin_123456789/       # 每个用户一个目录
│   ├── config.xml         # 用户配置文件
│   └── fingerprints/      # 指纹数据
└── developer_987654321/
    └── config.xml
```

**用户 config.xml 示例**：

```xml
<!-- $JENKINS_HOME/users/admin_123456789/config.xml -->
<user>
  <version>1</version>
  <id>admin</id>
  <fullName>系统管理员</fullName>
  <email>admin@example.com</email>
  <passwordHash>#jbcrypt:$2a$10$xxx...</passwordHash>
  <properties>
    <jenkins.security.ApiTokenProperty>
      <apiToken>xxxxx</apiToken>
    </jenkins.security.ApiTokenProperty>
    <hudson.model.UserProperty>
      <address>admin@example.com</address>
    </hudson.model.UserProperty>
  </properties>
</user>
```

### 10.2.2 LDAP 认证

LDAP（Lightweight Directory Access Protocol）适合企业环境，实现集中式用户管理。

**配置 LDAP**：

1. 进入 **Manage Jenkins** → **Security**
2. 选择 **Security Realm** → **LDAP**
3. 填写 LDAP 服务器信息

**LDAP 配置详解**：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| Server | LDAP 服务器地址 | `ldap://ldap.example.com` 或 `ldaps://ldap.example.com`（SSL） |
| Port | LDAP 端口 | 389（标准）或 636（SSL） |
| root DN | 基础 DN | `dc=example,dc=com` |
| User search base | 用户搜索基础 | `ou=people` |
| User search filter | 用户搜索过滤器 | `(uid={0})` |
| Group search base | 组搜索基础 | `ou=groups` |
| Group search filter | 组搜索过滤器 | `(member={0})` |
| Manager DN | 绑定 DN | `cn=admin,dc=example,dc=com` |
| Manager Password | 绑定密码 | `********` |

**Advanced LDAP Configuration**：

```yaml
# LDAP 高级配置示例
server: ldap://ldap.example.com:389
rootDN: dc=example,dc=com

# 用户搜索配置
userSearchBase: ou=people,dc=example,dc=com
userSearchFilter: (uid={0})
userUsernameAttribute: uid
userDisplayNameAttribute: cn
userEmailAttribute: mail

# 组搜索配置
groupSearchBase: ou=groups,dc=example,dc=com
groupSearchFilter: (member={0})
groupMembershipAttribute: memberOf

# 绑定配置
managerDN: cn=jenkins,ou=services,dc=example,dc=com
managerPassword: ${LDAP_MANAGER_PASSWORD}

# TLS/SSL 配置
ssl: false
startTLS: true
```

**使用环境变量存储敏感信息**：

```groovy
// Pipeline 中使用 LDAP 密码（通过环境变量）
environment {
    LDAP_MANAGER_PASSWORD = credentials('ldap-manager-password')
}
```

### 10.2.3 Active Directory 认证

Active Directory 是 Windows 企业环境的目录服务，Jenkins 提供了专门的 AD 认证支持。

**安装 Active Directory 插件**：

```
Manage Jenkins → Manage Plugins → Available
→ 搜索 "Active Directory" → 安装
```

**配置 Active Directory**：

1. 进入 **Manage Jenkins** → **Security**
2. 选择 **Security Realm** → **Active Directory`
3. 填写 AD 域名和服务信息

**AD 配置详解**：

| 配置项 | 说明 | 示例 |
|--------|------|------|
| Domain | AD 域名 | `example.com` |
| Domain controller | 域控制器 | `dc01.example.com:3268` |
| Site | AD 站点名称（可选） | `Default-First-Site-Name` |
| Bind DN | 绑定 DN | `jenkins@EXAMPLE.COM` |
| Bind Password | 绑定密码 | `********` |

**多域控制器配置**：

```yaml
# 多域控制器配置
Domain: example.com

# 主域控制器
Domain controller: dc01.example.com:3268

# 备用域控制器
Additional domain controllers:
  - dc02.example.com:3268
  - dc03.example.com:3268

# 如果使用 Jenkins 域缓存
Use Jenkins Domain Cache: true
Cache size: 500
Cache TTL: 300
```

**使用 AD 进行认证的 Pipeline 示例**：

```groovy
// Jenkinsfile - AD 认证环境中的 Pipeline
pipeline {
    agent any

    environment {
        // AD 认证会自动应用，不需要在 Pipeline 中额外配置
        AD_DOMAIN = 'EXAMPLE.COM'
    }

    stages {
        stage('Checkout') {
            steps {
                echo "当前用户: ${env.USER_NAME}"
                echo "正在使用 AD 认证..."
            }
        }

        stage('Build') {
            steps {
                echo "构建中..."
            }
        }
    }

    post {
        always {
            echo "构建完成，用户: ${currentBuild.rawBuild.getCauses()[0]}"
        }
    }
}
```

### 10.2.4 SSO/OAuth 2.0 认证

对于需要单点登录（SSO）的环境，可以使用 OAuth 2.0 认证，如 GitHub、GitLab、Google、Microsoft 等。

#### 10.2.4.1 GitHub OAuth 认证

**步骤1：创建 GitHub OAuth App**：

1. 登录 GitHub，进入 **Settings** → **Developer settings** → **OAuth Apps**
2. 点击 **New OAuth App**
3. 填写应用信息：
   - Application name: `Jenkins CI`
   - Homepage URL: `https://jenkins.example.com`
   - Authorization callback URL: `https://jenkins.example.com/securityRealm/finishLogin`

**步骤2：在 Jenkins 中配置 GitHub OAuth**：

1. 安装 **GitHub Authentication Plugin**
2. 进入 **Manage Jenkins** → **Security**
3. 选择 **Security Realm** → **GitHub Authentication Plugin`
4. 填写配置：
   - GitHub Web URI: `https://github.com`
   - GitHub API URI: `https://api.github.com`
   - Client ID: `your-github-client-id`
   - Client Secret: `your-github-client-secret`
5. 可选：配置组织成员自动授权

```yaml
# GitHub OAuth 配置
GitHub Web URI: https://github.com
GitHub API URI: https://api.github.com
Client ID: Ov21xxxxxxxxxxxxx
Client Secret: ${GITHUB_OAUTH_CLIENT_SECRET}

# 可选：授权特定 GitHub 组织的成员
Enable auto-managed client secret: true
Scopes: read:user,user:email

# 组织成员权限配置
-oauth-access-token-validity: 3600
```

#### 10.2.4.2 GitLab OAuth 认证

**安装插件**：GitLab Authentication Plugin

**配置 GitLab OAuth**：

1. 在 GitLab 中创建 Application：
   - Name: `Jenkins`
   - Redirect URI: `https://jenkins.example.com/securityRealm/finishLogin`
   - Scopes: `openid`, `profile`, `email`
2. 获取 Application ID 和 Secret
3. 在 Jenkins 中配置：
   - GitLab Web URI: `https://gitlab.com`
   - GitLab API URI: `https://gitlab.com/api/v4`
   - Client ID: `your-gitlab-client-id`
   - Client Secret: `your-gitlab-client-secret`

#### 10.2.4.3 通用 OAuth 2.0 配置

对于其他 OAuth 提供者，可以使用 **OAuth Token** 或 **OIDC** 插件。

**OAuth 通用参数配置**：

```groovy
// Pipeline 中使用 OAuth 认证获取的用户信息
pipeline {
    agent any

    stages {
        stage('Get User Info') {
            steps {
                script {
                    def user = User.current()
                    echo "当前用户: ${user.fullName}"
                    echo "用户 ID: ${user.id}"
                    echo "用户邮箱: ${user.email}"
                }
            }
        }
    }
}
```

## 10.3 权限授权（Authorization Strategy）

### 10.3.1 授权策略概述

Jenkins 提供了多种授权策略，从简单的"任何人可以做任何事"到细粒度的矩阵授权。

```
授权策略选择指南
├── 测试/开发环境
│   └── Anyone can do anything（不推荐生产环境）
│
├── 简单团队
│   └── Logged-in users can do anything（已登录用户可以做任何事）
│
├── 中型企业
│   ├── Matrix-based security（矩阵授权策略）
│   └── Project-based Matrix Authorization Strategy（项目矩阵授权）
│
└── 大型企业/复杂权限需求
    └── Role-Based strategy（基于角色的授权策略）
```

### 10.3.2 矩阵授权策略（Matrix-based Security）

矩阵授权是最灵活的授权方式，可以为每个用户或组单独设置权限。

**启用矩阵授权**：

1. 进入 **Manage Jenkins** → **Security**
2. 选择 **Authorization** → **Matrix-based security`
3. 添加用户/组，设置权限

**权限列表详解**：

| 权限类别 | 权限名称 | 说明 |
|----------|----------|------|
| **Overall** | Administer | 管理系统配置（最高权限） |
| | Read | 读取 Jenkins 配置和构建历史 |
| | RunScripts | 运行 Groovy 脚本 |
| | UploadPlugins | 上传插件 |
| | ConfigureUpdateCenter | 配置更新中心 |
| **Credentials** | Create | 创建凭证 |
| | Delete | 删除凭证 |
| | Manage | 管理凭证 |
| | Update | 更新凭证 |
| | View | 查看凭证 |
| **Agent** | Build | 在节点上执行构建 |
| | Configure | 配置节点 |
| | Connect | 连接节点 |
| | Create | 创建节点 |
| | Delete | 删除节点 |
| | Disconnect | 断开节点 |
| | Move | 移动节点 |
| | Provision | 为节点提供构建环境 |
| **Job** | Build | 触发构建 |
| | Cancel | 取消构建 |
| | Configure | 配置 Job |
| | Create | 创建 Job |
| | Delete | 删除 Job |
| | Discover | 发现 Job（通过 API） |
| | Move | 移动 Job |
| | Read | 读取 Job 配置 |
| | Workspace | 访问 Job 工作区 |
| **Run** | Delete | 删除构建记录 |
| | Log | 查看构建日志 |
| | Replay | 重放构建 |
| | Update | 更新构建参数 |
| **View** | Configure | 配置视图 |
| | Create | 创建视图 |
| | Delete | 删除视图 |
| | Read | 读取视图 |
| **SCM** | Tag | 创建 SCM 标签 |

**矩阵授权配置示例**：

```
┌─────────────────────────────────────────────────────────────────┐
│                    矩阵授权配置示例                               │
├─────────────┬────────┬────────┬────────┬────────┬────────┬─────┤
│ 用户/组     │ Admin  │ Read   │ Build  │ Config │ Delete │ ... │
├─────────────┼────────┼────────┼────────┼────────┼────────┼─────┤
│ admin       │   ✓    │   ✓    │   ✓    │   ✓    │   ✓    │     │
│ developer   │        │   ✓    │   ✓    │   ✓    │        │     │
│ tester      │        │   ✓    │   ✓    │        │        │     │
│ ci-bot      │        │   ✓    │   ✓    │        │        │     │
│ qa-team     │        │   ✓    │   ✓    │        │        │     │
└─────────────┴────────┴────────┴────────┴────────┴────────┴─────┘
```

**通过 Jenkins CLI 配置矩阵授权**：

```bash
# 设置全局矩阵授权
java -jar jenkins-cli.jar -s https://jenkins.example.com/jenkins \
    -auth admin:api-token \
    set-matrix-auth \
    --user developer \
    --permission hudson.model.Item.Build \
    --permission hudson.model.Item.Read

# 移除权限
java -jar jenkins-cli.jar -s https://jenkins.example.com/jenkins \
    -auth admin:api-token \
    unset-matrix-auth \
    --user developer \
    --permission hudson.model.Item.Configure
```

### 10.3.3 Role-Based 授权策略（Role Strategy 插件）

Role Strategy 插件是最强大的授权管理工具，适合大型团队和复杂权限场景。

**安装 Role Strategy 插件**：

```
Manage Jenkins → Manage Plugins → Available
→ 搜索 "Role-based Authorization Strategy" → 安装
```

**Role Strategy 的核心概念**：

```
┌─────────────────────────────────────────────────────────────────┐
│                    Role Strategy 授权模型                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────┐     ┌─────────┐     ┌─────────┐                   │
│  │ Global  │     │ Agent   │     │  Job    │                   │
│  │ Roles   │     │ Roles   │     │  Roles  │                   │
│  └────┬────┘     └────┬────┘     └────┬────┘                   │
│       │               │               │                          │
│       ▼               ▼               ▼                          │
│  ┌─────────┐     ┌─────────┐     ┌─────────┐                   │
│  │  Admin  │     │  Build  │     │  Build  │                   │
│  │  Ops    │     │  Config │     │  Deploy │                   │
│  │  DevOps │     │         │     │  Read   │                   │
│  └─────────┘     └─────────┘     └─────────┘                   │
│                                                                 │
│  ┌─────────────────────────────────────────┐                   │
│  │  Role Assignment（角色分配）              │                   │
│  │  ─────────────────────────────────────  │                   │
│  │  alice   → Admin, DevOps                 │                   │
│  │  bob     → Developer                    │                   │
│  │  charlie → QA                           │                   │
│  │  jenkins-ci → Agent                     │                   │
│  └─────────────────────────────────────────┘                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**配置 Role Strategy**：

1. 进入 **Manage Jenkins** → **Security**
2. 选择 **Authorization** → **Role-Based Strategy`
3. 点击 **Manage Roles** 配置角色

**Global Roles（全局角色）**：

| 角色名称 | 权限说明 | 适用用户 |
|----------|----------|----------|
| Admin | 完全控制权限 | 系统管理员 |
| Developer | 创建/配置/运行 Job | 开发人员 |
| Viewer | 只读权限 | 审计人员、PM |
| Build | 运行构建权限 | CI/CD 机器人 |

**Agent Roles（节点角色）**：

| 角色名称 | 权限说明 | 适用节点 |
|----------|----------|----------|
| Builder | 可以在节点上构建 | 所有构建节点 |
| Provisioner | 供应新节点 | 动态云节点 |
| Connect Only | 仅连接权限 | 临时节点 |

**Project Roles（项目角色）**：

| 角色名称 | Pattern | 权限说明 |
|----------|---------|----------|
| frontend-dev | `frontend-.*` | 前端项目开发权限 |
| backend-dev | `backend-.*` | 后端项目开发权限 |
| qa-tester | `.*-qa` | QA 测试权限 |
| release-manager | `release-.*` | 发布管理权限 |

**创建角色的完整示例**：

```
步骤1：创建 Global Roles
─────────────────────────
Role Name: developer
Permissions:
  ✓ Overall/Read
  ✓ Overall/Runs/Read
  ✓ Job/Build
  ✓ Job/Cancel
  ✓ Job/Configure
  ✓ Job/Create
  ✓ Job/Delete
  ✓ Job/Move
  ✓ Job/Read
  ✓ Job/Workspace
  ✓ Run/Update

步骤2：创建 Project Roles
─────────────────────────
Role Name: frontend-developer
Pattern: frontend-.*
Permissions:
  ✓ Job/Build
  ✓ Job/Cancel
  ✓ Job/Configure
  ✓ Job/Read
  ✓ Job/Workspace
  ✓ Run/Delete
  ✓ Run/Log
  ✓ Run/Replay
  ✓ Run/Update

步骤3：分配角色
─────────────────────────
User: alice
  → Global Roles: developer
  → Project Roles: frontend-developer

User: bob
  → Global Roles: developer
  → Project Roles: backend-developer
```

**通过 Jenkins CLI 管理角色**：

```bash
# 安装角色策略插件后，使用 CLI 管理角色

# 创建全局角色
java -jar jenkins-cli.jar -s https://jenkins.example.com/jenkins \
    -auth admin:api-token \
    create-global-role "developer" "hudson.model.Item.Build,hudson.model.Item.Read"

# 创建项目角色
java -jar jenkins-cli.jar -s https://jenkins.example.com/jenkins \
    -auth admin:api-token \
    create-project-role "frontend-dev" "frontend-.*" "hudson.model.Item.Build,hudson.model.Item.Read"

# 分配全局角色
java -jar jenkins-cli.jar -s https://jenkins.example.com/jenkins \
    -auth admin:api-token \
    assign-role "developer" "alice"

# 分配项目角色
java -jar jenkins-cli.jar -s https://jenkins.example.com/jenkins \
    -auth admin:api-token \
    assign-project-role "frontend-dev" "alice"

# 列出所有角色
java -jar jenkins-cli.jar -s https://jenkins.example.com/jenkins \
    -auth admin:api-token \
    list-roles

# 删除角色
java -jar jenkins-cli.jar -s https://jenkins.example.com/jenkins \
    -auth admin:api-token \
    delete-role "developer"
```

**Role Strategy REST API**：

```bash
# 获取所有角色
curl -X GET \
  "https://jenkins.example.com/jenkins/role-strategy/role/roles" \
  -H "Authorization: Bearer ${JENKINS_API_TOKEN}"

# 创建角色
curl -X POST \
  "https://jenkins.example.com/jenkins/role-strategy/role/create" \
  -H "Authorization: Bearer ${JENKINS_API_TOKEN}" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "roleName=developer&type=global&permissions=hudson.model.Item.Build,hudson.model.Item.Read"

# 分配角色
curl -X POST \
  "https://jenkins.example.com/jenkins/role-strategy/role/assign" \
  -H "Authorization: Bearer ${JENKINS_API_TOKEN}" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "role=developer&type=global&sid=alice"
```

## 10.5 API Token 管理

### 10.5.1 API Token 概述

API Token 是用户身份的另一形式，用于程序化访问 Jenkins API。

**Token 的用途**：

- Jenkins CLI 身份认证
- REST API 调用认证
- 第三方集成（如 GitHub Webhook、GitLab CI）
- 自动化脚本认证

### 10.5.2 创建 API Token

**方法1：通过 Web 界面创建**

1. 点击右上角用户名 → **Configure**
2. 在 **API Token** 部分点击 **Add new Token**
3. 输入 Token 名称（如 "github-webhook"）
4. 点击 **Generate**
5. 复制生成的 Token（只显示一次）

**方法2：通过脚本创建**

```groovy
// 在 Script Console 中创建 API Token
import hudson.model.User
import jenkins.security.ApiTokenProperty

def user = User.get('developer')
def apiTokenProperty = user.getProperty(ApiTokenProperty.class)

// 生成新 Token
def token = apiTokenProperty.tokenStore.generateToken("自动化脚本使用")
println "Token 名称: ${token.name}"
println "Token 值: ${token.plainValue}"
println "请妥善保存，值只会显示一次"

// 列出用户所有 Token
println "\n用户 ${user.id} 的现有 Token:"
apiTokenProperty.tokenStore.tokens.each { t ->
    println "  - ${t.name} (创建于: ${t.creationDate})"
}
```

### 10.5.3 使用 API Token

**Jenkins CLI 使用 Token**：

```bash
# 格式: -auth user:token
java -jar jenkins-cli.jar -s https://jenkins.example.com/jenkins \
    -auth admin:11xxxxxxxxxxxxxxxxxx \
    list-jobs

# 使用 API Token 文件（更安全）
echo "11xxxxxxxxxxxxxxxxxx" > /path/to/token.file
java -jar jenkins-cli.jar -s https://jenkins.example.com/jenkins \
    -auth admin@token.file \
    list-jobs
```

**REST API 使用 Token**：

```bash
# Basic Auth 方式：用户名:Token 作为凭据
curl -X GET \
  "https://jenkins.example.com/jenkins/api/json" \
  -u "admin:11xxxxxxxxxxxxxxxxxx"

# 或者使用 -H Authorization Header
curl -X GET \
  "https://jenkins.example.com/jenkins/api/json" \
  -H "Authorization: Basic $(echo -n 'admin:11xxxxxxxxxxxxxxxxxx' | base64)"
```

**Pipeline 中使用 Token**：

```groovy
// Pipeline 中调用 Jenkins API
pipeline {
    agent any

    environment {
        JENKINS_URL = 'https://jenkins.example.com/jenkins'

                script {
                    def response = httpRequest(
                        url: "${env.JENKINS_URL}/job/my-job/build",

                        ],
                        httpMode: 'POST'

                }
            }
        }
    }
```

### 10.5.4 Token 安全管理

**Token 轮换最佳实践**：

```groovy
// 定期检查未使用的 Token（可作为定时 Job）
import hudson.model.User
import jenkins.security.ApiTokenProperty
import java.time.LocalDateTime
import java.time.temporal.ChronoUnit

def daysThreshold = 90 // 90 天未使用

User.getAll().each { user ->
    def prop = user.getProperty(ApiTokenProperty.class)
    prop.tokenStore.tokens.each { token ->
        def lastUsed = token.lastUseDate
        if (lastUsed) {
            def daysSinceUsed = ChronoUnit.DAYS.between(lastUsed.toInstant(), LocalDateTime.now())
            if (daysSinceUsed > daysThreshold) {
                println "警告: 用户 ${user.id} 的 Token '${token.name}' 已 ${daysSinceUsed} 天未使用"
            }
        } else {
            println "警告: 用户 ${user.id} 的 Token '${token.name}' 从未使用过"
        }
    }
}
```

### 10.6.4 分析审计日志

**日志分析脚本**：

```groovy
// 审计日志分析脚本 - 在 Script Console 中运行
import java.time.LocalDateTime
import java.time.format.DateTimeFormatter

def auditLogFile = new File('/var/log/jenkins/audit.log')

if (!auditLogFile.exists()) {
    println "审计日志文件不存在"
    return
}

def startDate = LocalDateTime.now().minusDays(7)
def dateFormatter = DateTimeFormatter.ofPattern("yyyy-MM-dd")

def actionCounts = [:]
def userActionCounts = [:]
def failedActions = []

auditLogFile.eachLine { line ->
    // 解析 JSON 格式日志
    if (line.startsWith("{")) {
        def json = new groovy.json.JsonSlurper().parseText(line)
        def logDate = LocalDateTime.parse(json.timestamp.replace("+08:00", ""))

        // 只分析最近7天
        if (logDate.isAfter(startDate)) {
            // 统计操作类型
            actionCounts[json.action] = (actionCounts[json.action] ?: 0) + 1

            // 统计用户操作
            def userKey = "${json.user}:${json.action}"
            userActionCounts[userKey] = (userActionCounts[userKey] ?: 0) + 1

            // 记录失败操作
            if (json.success == false) {
                failedActions << json
            }
        }
    }
}

println "=== 最近7天审计日志统计 ==="
println "\n操作类型统计（Top 10）:"
actionCounts.sort { -it.value }.take(10).each { action, count ->
    println "  ${action}: ${count} 次"
}

println "\n用户操作统计（Top 10）:"
userActionCounts.sort { -it.value }.take(10).each { userAction, count ->
    println "  ${userAction}: ${count} 次"
}

println "\n失败操作列表:"
failedActions.each { action ->
    println "  ${action.timestamp} - ${action.user} - ${action.action} - ${action.errorMessage ?: 'Unknown error'}"
}
```

```groovy
import com.cloudbees.plugins.credentials.CredentialsProvider

def checkCredentialAccess(String credentialsId, User user) {
    def credential = CredentialsProvider.findCredentialById(
        credentialsId,
        Credentials.class,
        Jenkins.get(),
        Collections.emptyList()
    )

    if (credential == null) {
        return [accessible: false, reason: "凭证不存在"]
    }

    def hasAccess = CredentialsProvider.getCredentials(
        Credentials.class,
        Jenkins.get(),
        user.getACL(),
        Collections.emptyList()
    ).any { it.id == credentialsId }

    return [accessible: hasAccess, reason: hasAccess ? "有权访问" : "无权访问"]
}
```

```groovy

pipeline {

                script {

                        path: 'database/creds/prod-role',

                        token: env.VAULT_TOKEN

                    echo "从 Vault 获取的数据库凭证有效期至: ${dbCreds.leaseExpirationDate}"
                }
            }

        stage('Use Credentials') {
            steps {
                sh '''
                    psql -h db.example.com -U ${DB_USERNAME} -p 5432 mydb
                '''
            }
        }
    }

    post {
        always {
            script {
                // 撤销临时凭证
                if (env.DB_USERNAME && env.VAULT_TOKEN) {
                    vault.revoke(
                        path: 'database/creds/prod-role',
                        vaultUrl: env.VAULT_ADDR,
                        token: env.VAULT_TOKEN
                    )
                    echo "临时数据库凭证已撤销"
```

### 10.8.4 敏感信息保护最佳实践

**1. 禁止在代码中硬编码敏感信息**：

```groovy
// ❌ 错误 - 敏感信息暴露
pipeline {
    steps {
        sh 'mysql -u root -p"password123" -h db.example.com'
    }
}

// ✅ 正确 - 使用凭证
pipeline {
    steps {
        withCredentials([usernamePassword(
            credentialsId: 'mysql-root',
            usernameVariable: 'DB_USER',
            passwordVariable: 'DB_PASS'
        )]) {
            sh 'mysql -u ${DB_USER} -p"${DB_PASS}" -h db.example.com'
        }
    }
}
```

**2. 使用环境变量而非脚本块内变量**：

```groovy
// ❌ 错误 - 变量在 steps 块外可能泄漏
pipeline {
    environment {
        API_KEY = credentials('api-key')
    }
    stages {
        stage('Bad') {
            steps {
                echo "API Key: ${env.API_KEY}"  // 会输出到日志
            }
        }
    }
}

// ✅ 正确 - 在 script 块内使用
pipeline {
    stages {
        stage('Good') {
            steps {
                script {
                    withCredentials([string(credentialsId: 'api-key', variable: 'KEY')]) {
                        echo "API Key: ${KEY}"  // 会被掩码
                    }
                }
            }
        }
    }
}
```

**3. 构建后清理敏感文件**：

```groovy
pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                script {
                    withCredentials([file(credentialsId: 'service-account', variable: 'SA_KEY')]) {
                        // 使用服务账号密钥
                        sh 'gcloud auth activate-service-account --key-file=${SA_KEY}'

                        // 构建完成后清理
                        sh 'rm -f ${SA_KEY}'
                    }
                }
            }
        }
    }

    post {
        always {
            // 确保工作区清理
            cleanWs()
        }
    }
}
```

### 10.9.6 定期安全维护

**月度维护任务**：

```groovy
// 月度安全检查脚本 - 定时执行
import hudson.model.User
import hudson.model.Item
import jenkins.security.ApiTokenProperty
import java.time.LocalDateTime
import java.time.temporal.ChronoUnit

def report = []
def cutoffDate = LocalDateTime.now().minusMonths(3)

// 1. 检查 90 天未活跃的用户
User.getAll().each { user ->
    def lastActivity = user.getProperty(ApiTokenProperty.class)?.tokenStore?.tokens?.last()?.lastUseDate
    if (lastActivity) {
        def daysSince = ChronoUnit.DAYS.between(lastActivity.toInstant(), LocalDateTime.now())
        if (daysSince > 90) {
            report << "警告: 用户 ${user.id} 已 ${daysSince} 天未活动"
        }
    }
}

// 2. 检查是否有用户拥有 Admin 权限但不应拥有
def adminUsers = []
def authStrategy = Jenkins.instance.authorizationStrategy
if (authStrategy instanceof hudson.security.GlobalMatrixAuthorizationStrategy) {
    authStrategy.grantedPermissions.each { permission, users ->
        if (permission.toString().contains('ADMINISTER')) {
            adminUsers.addAll(users)
        }
    }
}

def expectedAdmins = ['admin', 'jenkins-admin']
adminUsers.each { user ->
    if (!expectedAdmins.contains(user)) {
        report << "警告: 非预期用户 ${user} 拥有 Admin 权限"
    }
}

// 3. 检查配置变更
def recentChanges = []
Jenkins.instance.allItems(Item.class).each { item ->
    def lastModified = item.getLastBuild()?.timestamp
    if (lastModified) {
        def daysSince = ChronoUnit.DAYS.between(lastModified.time.toInstant(), LocalDateTime.now())
        if (daysSince < 1) {
            recentChanges << item.fullName
        }
    }
}

// 输出报告
println "=== 月度安全检查报告 ==="
println "生成时间: ${LocalDateTime.now()}"
println "\n发现的问题:"
report.each { println "  - $it" }
println "\n最近 24 小时有变更的 Job:"
recentChanges.each { println "  - $it" }
```

**安全加固脚本**：

```groovy
// 安全加固脚本 - 首次配置 Jenkins 时执行
import hudson.model.User
import hudson.security.AuthorizationStrategy
import hudson.security.SecurityRealm

// 1. 禁用匿名访问
Jenkins.instance.disableSecurity()
Jenkins.instance.enableSecurity()

// 2. 设置安全 realm
Jenkins.instance.setSecurityRealm(Jenkins.instance.securityRealm)

// 3. 配置授权策略 - 矩阵授权
def strategy = new hudson.security.GlobalMatrixAuthorizationStrategy()

// 添加管理员（替换为你的管理员用户名）
strategy.add(hudson.model.Hudson.ADMINISTER, "admin")

// 添加只读用户组
strategy.add(hudson.model.Hudson.READ, "authenticated")

// 设置授权策略
Jenkins.instance.setAuthorizationStrategy(strategy)

// 4. 保存配置
Jenkins.instance.save()

println "安全加固完成！"
println "当前安全配置:"
println "  Security Realm: ${Jenkins.instance.securityRealm}"
println "  Authorization: ${Jenkins.instance.authorizationStrategy}"
```
