# 第6章：Pipeline 流水线

## 6.1 Pipeline 概述

### 什么是 Jenkins Pipeline

Jenkins Pipeline（流水线）是一种将软件从源码阶段到用户手中的整个过程自动化实现的机制。它以代码的形式定义构建、测试、部署等流程，使得构建过程可追溯、可重复、可版本化。

Pipeline 这一概念的核心价值在于：

- **Pipeline as Code**：将构建流程以代码形式存储在 `Jenkinsfile` 中，随源码一起版本管理
- **可追溯**：每次构建的历史完整记录，方便回溯问题
- **可复用**：同一 Pipeline 可应用于多个项目
- **可扩展**：通过共享库（Shared Library）封装可复用逻辑

### 两种 Pipeline 语法

Jenkins 支持两种 Pipeline 语法：

| 特性 | Declarative Pipeline | Scripted Pipeline |
|------|---------------------|-------------------|
| 语法风格 | 声明式，结构固定 | 脚本式，灵活控制 |
| 学习曲线 | 较平缓 | 较陡峭 |
| 复杂度 | 适合大多数场景 | 适合复杂场景 |
| 调试 | 语法错误在运行前即可发现 | 需要运行才能发现错误 |
| 生态支持 | 原生支持 Blue Ocean | 需要手动处理 |

**建议**：大多数场景优先使用 Declarative Pipeline，复杂逻辑可用 `script` 块嵌入 Scripted Pipeline 代码。

## 6.2 Declarative Pipeline 详解

### 6.2.1 基本结构

Declarative Pipeline 遵循固定的结构，最外层为 `pipeline` 块，内部包含多个顶层 sections：

```groovy
pipeline {
    agent any                          // 1. agent：指定执行节点

    options {                          // 2. options：配置选项
        // ...
    }

    triggers {                         // 3. triggers：触发器
        // ...
    }

    environment {                      // 4. environment：环境变量
        // ...
    }

    stages {                           // 5. stages：阶段集合
        stage('Stage 1') {
            steps {                    // 6. steps：步骤
                // ...
            }
        }
        stage('Stage 2') {
            steps {
                // ...
            }
        }
    }

    post {                             // 7. post：构建后处理
        always {
            // ...
        }
    }
}
```

### 6.2.2 agent 详解

`agent` 指定 Pipeline 或 stage 在哪里执行。

#### 常用 agent 配置

```groovy
// 在任意可用节点执行
agent any

// 在指定标签的节点执行
agent { label 'linux && docker' }

// 不分配节点，在 master 执行（较少使用）
agent none

// 使用 Docker 容器作为执行环境
agent {
    docker {
        image 'maven:3.8-openjdk-11'
        label 'docker-enabled'
        args '-v /root/.m2:/root/.m2'
    }
}

// 使用多个 Docker 容器（用于需要多个服务的场景，如 MySQL + App）
agent {
    docker {
        image 'mysql:8.0'
        label 'docker-enabled'
        args '-p 3306:3306 -e MYSQL_ROOT_PASSWORD=secret'
    }
}

// 使用 Kubernetes Pod 模板
agent {
    kubernetes {
        label 'kubernetes-pod'
        defaultContainer 'jnlp'
        yaml '''
apiVersion: v1
kind: Pod
spec:
  containers:
  - name: maven
    image: maven:3.8-openjdk-11
    command: cat
    tty: true
'''
    }
}
```

#### 在 stage 级别使用 agent

可以为不同 stage 指定不同的 agent，实现更精细的资源分配：

```groovy
pipeline {
    agent none

    stages {
        stage('Build') {
            agent { label 'build-node' }
            steps {
                echo 'Building...'
            }
        }

        stage('Test') {
            agent { label 'test-node' }
            steps {
                echo 'Testing...'
            }
        }

        stage('Deploy') {
            agent { label 'deploy-node' }
            steps {
                echo 'Deploying...'
            }
        }
    }
}
```

### 6.2.3 stages 与 steps 详解

`stages` 是 Pipeline 的核心部分，定义了实际执行的工作流程。

#### 基本用法

```groovy
stages {
    stage('Checkout') {
        steps {
            echo 'Cloning repository...'
            git 'https://github.com/example/project.git'
        }
    }

    stage('Build') {
        steps {
            echo 'Building project...'
            sh 'mvn clean package'
        }
    }

    stage('Test') {
        steps {
            echo 'Running tests...'
            sh 'mvn test'
        }
    }

    stage('Deploy') {
        steps {
            echo 'Deploying...'
            sh './deploy.sh'
        }
    }
}
```

#### steps 中常用的命令

```groovy
steps {
    // 输出信息
    echo 'Hello World'
    print 'Variable value: ${VAR}'

    // 执行 shell 命令
    sh 'mvn clean package'
    sh '''
        echo "Multi-line script"
        cd src
        ls -la
    '''

    // 执行 Windows batch 命令
    bat 'dir'

    // 设置环境变量
    env.VAR_NAME = 'value'

    // 调用外部方法（来自共享库）
    sh './gradlew build'
}
```

### 6.2.4 when 条件判断

`when` 用于控制 stage 是否执行。

#### 基本用法

```groovy
stage('Deploy to Production') {
    when {
        expression { params.BRANCH == 'main' }
        expression { currentBuild.resultIsBetterOrEqualTo('SUCCESS') }
    }
    steps {
        echo 'Deploying to production...'
    }
}
```

#### 常用 when 条件

```groovy
stage('Conditional Stage') {
    when {
        // 表达式为 true 时执行
        expression { ENV == 'production' }

        // 分支名称匹配
        branch 'main'
        branch 'feature/*'

        // 不是特定分支
        not { branch 'main' }

        // 多个分支之一
        anyOf { branch 'main'; branch 'develop' }

        // 所有条件都满足
        allOf {
            branch 'main'
            expression { ENV == 'production' }
        }

        // 标签存在
        tag 'v*'

        // 构建参数存在
        buildingTag()

        // 文件存在
        changeset '**/*.java'

        // 与上次构建相比，文件有变化
        changeset pattern: '**/*.java', comparator: 'eq'

        // 环境变量等于某值
        environment name: 'DEPLOY_TO', value: 'production'

        // 阶段状态为特定值
        statusIs 'SUCCESS'

        // 在指定时间内没有构建
        not { triggeredBy 'TimerTrigger' }
    }
    steps {
        echo 'Condition met, executing stage...'
    }
}
```

### 6.2.5 environment 环境变量

#### 全局环境变量

```groovy
pipeline {
    agent any

    environment {
        APP_NAME = 'my-app'
        APP_VERSION = '1.0.0'
        MAVEN_OPTS = '-Xmx512m'
    }

    stages {
        stage('Build') {
            steps {
                echo "Building ${APP_NAME} v${APP_VERSION}"
                sh 'mvn clean package'
            }
        }
    }
}
```

#### stage 级环境变量

```groovy
stages {
    stage('Build') {
        environment {
            BUILD_TOOL = 'maven'
            JAVA_HOME = '/opt/jdk-11'
        }
        steps {
            echo "Using ${BUILD_TOOL}"
            sh '${JAVA_HOME}/bin/java -version'
        }
    }
}
```

#### 使用 credentials 获取敏感信息

```groovy
pipeline {
    agent any

    environment {
        // 使用 Jenkins 中存储的 credentials
        SSH_KEY = credentials('ssh-key-for-deployment')
        NPM_TOKEN = credentials('npm-token-secret')
        DOCKER_USERNAME = credentials('docker-hub-username')
        DOCKER_PASSWORD = credentials('docker-hub-password')
    }

    stages {
        stage('Deploy') {
            steps {
                echo 'Deploying with credentials...'
                // 在脚本中使用环境变量
                sh 'echo $SSH_KEY > keyfile'
            }
        }
    }

    post {
        always {
            // 清理敏感文件
            sh 'rm -f keyfile'
        }
    }
}
```

### 6.2.6 options 配置选项

#### 常用 options

```groovy
pipeline {
    agent any

    options {
        // 构建超时时间
        timeout(time: 1, unit: 'HOURS')

        // 构建失败重试次数
        retry(3)

        // 禁用并发构建
        disableConcurrentBuilds()

        // 保留构建历史记录数
        buildDiscarder(logRotator(numToKeepStr: '30'))

        // 在上一个构建成功前，禁用触发器
        disableResume()

        // 保持参数化构建的原始参数
        preserveStashes()

        // 设置 Pipeline 的描述
        echo 'Pipeline description'

        // 跳过默认的 checkout
        skipDefaultCheckout()
    }

    stages {
        stage('Example') {
            steps {
                echo 'Options applied'
            }
        }
    }
}
```

#### 与 timeout 配合的 stage 级超时

```groovy
stages {
    stage('Long Running Task') {
        options {
            timeout(time: 30, unit: 'MINUTES')
        }
        steps {
            // 可能运行很长时间的任务
            sh './long-running-script.sh'
        }
    }
}
```

### 6.2.7 triggers 触发器

#### Cron 表达式触发

```groovy
pipeline {
    agent any

    triggers {
        // 每周一到周五早上9点
        cron '0 9 * * 1-5'

        // 每天凌晨2点
        cron '0 2 * * *'

        // 每15分钟触发一次
        cron 'H/15 * * * *'

        // 工作日每2小时
        cron 'H 9-17/2 * * 1-5'
    }

    stages {
        stage('Build') {
            steps {
                echo 'Scheduled build triggered'
            }
        }
    }
}
```

#### 轮询 SCM 触发

```groovy
triggers {
    // 每5分钟检查一次代码变化
    pollSCM 'H/5 * * * *'
}
```

#### 多触发器组合

```groovy
triggers {
    cron '0 9 * * 1-5'
    githubPush()
    pollSCM('H/15 * * * *')
}
```

### 6.2.8 parameters 参数化构建

```groovy
pipeline {
    agent any

    parameters {
        // 字符串参数
        string(name: 'BRANCH', defaultValue: 'main', description: '要构建的分支')

        // 多行字符串参数
        text(name: 'BUILD_NOTES', defaultValue: '', description: '构建说明')

        // 布尔参数
        booleanParam(name: 'SKIP_TESTS', defaultValue: false, description: '跳过测试')

        // 选择参数
        choice(name: 'ENV', choices: ['dev', 'staging', 'prod'], description: '部署环境')

        // 密码参数（会加密显示）
        password(name: 'API_TOKEN', defaultValue: '', description: 'API Token')

        // 文件参数
        file(name: 'ARTIFACT', description: '要上传的文件')

        // 运行时参数
        run(name: 'LAST_SUCCESSFUL_BUILD', description: '上次成功构建')
    }

    stages {
        stage('Build') {
            steps {
                echo "Building branch: ${params.BRANCH}"
                echo "Environment: ${params.ENV}"
                echo "Skip tests: ${params.SKIP_TESTS}"
            }
        }
    }
}
```

### 6.2.9 post 构建后处理

`post` 用于在 Pipeline 执行完成后执行清理、通知等操作。

#### post 块条件

```groovy
pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                echo 'Building...'
            }
        }
    }

    post {
        // 总是执行
        always {
            echo '不管构建成功还是失败都会执行'
            cleanWs()  // 清理工作空间
        }

        // 仅在构建成功时执行
        success {
            echo 'Build succeeded!'
            emailext(
                subject: "构建成功: ${env.JOB_NAME} - ${env.BUILD_NUMBER}",
                body: "构建成功，点击查看: ${env.BUILD_URL}",
                to: 'team@example.com'
            )
        }

        // 仅在构建失败时执行
        failure {
            echo 'Build failed!'
            emailext(
                subject: "构建失败: ${env.JOB_NAME} - ${env.BUILD_NUMBER}",
                body: "构建失败，点击查看: ${env.BUILD_URL}",
                to: 'team@example.com'
            )
        }

        // 仅在构建不稳定时执行（如测试失败）
        unstable {
            echo 'Build is unstable'
        }

        // 仅在构建被中断时执行
        aborted {
            echo 'Build was aborted'
        }

        // 在构建结束后（无论成功失败）执行，通常用于清理
        cleanup {
            echo 'Cleaning up...'
        }
    }
}
```

## 6.3 Scripted Pipeline 详解

### 6.3.1 基本语法

Scripted Pipeline 使用 Groovy 脚本语言编写，语法更加灵活，但结构不如 Declarative 规范。

```groovy
// 节点选择
node('docker-enabled') {
    // 阶段定义
    stage('Checkout') {
        checkout scm
    }

    stage('Build') {
        // 变量定义
        def mvnHome = tool name: 'Maven-3.8'
        env.PATH = "${mvnHome}/bin:${env.PATH}"

        // 执行构建
        sh 'mvn clean package'
    }

    stage('Test') {
        // 条件执行
        if (env.BRANCH_NAME == 'main') {
            sh 'mvn test'
        } else {
            echo 'Skipping tests for non-main branch'
        }
    }

    stage('Deploy') {
        if (currentBuild.result == 'SUCCESS') {
            sh './deploy.sh'
        }
    }
}
```

### 6.3.2 变量与数据类型

```groovy
node {
    // 字符串
    def appName = 'my-app'
    def version = "1.0.0"

    // 列表
    def branches = ['feature-a', 'feature-b', 'hotfix']

    // 映射/字典
    def config = [
        'dev': 'dev.example.com',
        'staging': 'staging.example.com',
        'prod': 'prod.example.com'
    ]

    // 使用变量
    stage('Deploy') {
        echo "Deploying ${appName} v${version}"

        // 遍历列表
        for (int i = 0; i < branches.size(); i++) {
            echo "Processing branch: ${branches[i]}"
        }

        // 访问映射
        echo "Dev endpoint: ${config['dev']}"
    }
}
```

### 6.3.3 方法定义

```groovy
// 在 pipeline 外部定义方法
def buildArtifact(String version) {
    echo "Building version: ${version}"
    sh "mvn clean package -Dversion=${version}"
    return true
}

def notify(String channel, String message) {
    echo "Sending notification to ${channel}: ${message}"
}

pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                script {
                    def result = buildArtifact('1.0.0')
                    if (result) {
                        notify('#devops', 'Build succeeded')
                    }
                }
            }
        }
    }
}
```

### 6.3.4 异常处理

```groovy
node {
    stage('Risky Operation') {
        try {
            sh 'curl -s http://api.example.com/health'
            echo 'API is healthy'
        } catch (Exception e) {
            echo "Error occurred: ${e.message}"
            currentBuild.result = 'FAILURE'
        } finally {
            echo 'Cleanup in finally block'
        }
    }

    stage('Another Stage') {
        steps {
            script {
                // 抛出异常
                if (true) {
                    error 'Something went wrong'
                }
            }
        }
    }
}
```

### 6.3.5 循环与条件

```groovy
node {
    stage('Process Items') {
        script {
            def items = ['item1', 'item2', 'item3']

            // for 循环
            for (def item in items) {
                echo "Processing ${item}"
            }

            // each 循环
            items.each { item ->
                echo "Processing with each: ${item}"
            }

            // 条件语句
            def envName = 'prod'
            if (envName == 'prod') {
                echo 'Production environment'
            } else if (envName == 'staging') {
                echo 'Staging environment'
            } else {
                echo 'Other environment'
            }

            // switch 语句
            def action = 'deploy'
            switch (action) {
                case 'build':
                    echo 'Building...'
                    break
                case 'test':
                    echo 'Testing...'
                    break
                case 'deploy':
                    echo 'Deploying...'
                    break
                default:
                    echo 'Unknown action'
            }
        }
    }
}
```

## 6.4 错误处理与重试

### 6.4.1 retry 步骤

`retry` 用于在步骤失败时自动重试：

```groovy
pipeline {
    agent any

    stages {
        stage('Deploy with Retry') {
            steps {
                retry(3) {
                    echo 'Attempting deployment...'
                    sh './deploy.sh'
                }
            }
        }

        stage('API Call with Retry') {
            steps {
                script {
                    def maxRetries = 5
                    def retryCount = 0
                    def success = false

                    while (!success && retryCount < maxRetries) {
                        try {
                            retryCount++
                            echo "Attempt ${retryCount}/${maxRetries}"
                            sh 'curl -s http://api.example.com/deploy'
                            success = true
                        } catch (Exception e) {
                            if (retryCount >= maxRetries) {
                                error "Failed after ${maxRetries} attempts"
                            }
                            echo "Attempt failed, retrying in 10 seconds..."
                            sleep 10
                        }
                    }
                }
            }
        }
    }
}
```

### 6.4.2 retry 与 when 条件结合

```groovy
stages {
    stage('Deploy') {
        steps {
            retry(3) {
                script {
                    if (currentBuild.result == 'FAILURE') {
                        error 'Previous build failed, skipping retries'
                    }
                    sh './deploy.sh'
                }
            }
        }
    }
}
```

### 6.4.3 完整的错误处理模式

```groovy
pipeline {
    agent any

    options {
        timeout(time: 30, unit: 'MINUTES')
        retry(2)
    }

    stages {
        stage('Build and Test') {
            steps {
                script {
                    try {
                        echo 'Running build...'
                        sh 'mvn clean package'

                        echo 'Running tests...'
                        sh 'mvn test'

                    } catch (Exception e) {
                        echo "Build failed: ${e.message}"
                        currentBuild.result = 'FAILURE'
                        throw e  // 重新抛出异常，让 Pipeline 状态反映失败
                    }
                }
            }
        }

        stage('Deploy') {
            when {
                expression { currentBuild.result == 'SUCCESS' }
            }
            steps {
                script {
                    try {
                        echo 'Starting deployment...'
                        sh './deploy.sh'
                        echo 'Deployment successful'

                    } catch (Exception e) {
                        echo "Deployment failed: ${e.message}"
                        // 发送告警通知
                        emailext(
                            subject: "部署失败: ${env.JOB_NAME}",
                            body: "部署失败，请检查: ${env.BUILD_URL}",
                            to: 'oncall@example.com'
                        )
                        throw e
                    }
                }
            }
        }
    }

    post {
        failure {
            echo 'Pipeline failed, sending notification...'
            emailext(
                subject: "Pipeline 失败: ${env.JOB_NAME}",
                body: """
                    Pipeline 执行失败
                    Job: ${env.JOB_NAME}
                    Build: ${env.BUILD_NUMBER}
                    URL: ${env.BUILD_URL}
                """.stripIndent(),
                to: 'team@example.com'
            )
        }

        success {
            echo 'Pipeline completed successfully'
        }
    }
}
```

### 6.4.4 超时处理

```groovy
pipeline {
    agent any

    stages {
        stage('Long Running Task') {
            options {
                timeout(time: 1, unit: 'HOURS')
            }
            steps {
                script {
                    try {
                        echo 'Starting long running task...'
                        sh '''
                            # 模拟长时间运行的任务
                            for i in {1..100}; do
                                echo "Step $i"
                                sleep 60
                            done
                        '''
                    } catch (Exception e) {
                        if (e instanceof java.util.concurrent.TimeoutException) {
                            echo 'Task timed out!'
                            currentBuild.result = 'FAILURE'
                        }
                        throw e
                    }
                }
            }
        }
    }
}
```

## 6.5 共享库（Shared Library）开发与使用

### 6.5.1 共享库概述

Shared Library 是 Jenkins Pipeline 的可复用代码库，可以在多个 Pipeline 之间共享逻辑。适合将通用的构建、测试、部署逻辑抽取为共享库，避免重复代码。

### 6.5.2 共享库目录结构

标准共享库目录结构：

```
vars/
├── myStep.groovy          # 步骤定义文件
├── myStep.txt             # 帮助文档（可选）
├── myPipeline.groovy      # 完整 Pipeline 定义
└── myPipeline.txt

src/
└── com/
    └── example/
        ├── Tool.groovy    # 类定义（放在 src 下）
        └── Util.groovy

resources/
└── com/
    └── example/
        └── template.txt  # 资源文件
```

### 6.5.3 开发共享库

#### 步骤定义（vars 目录）

在 `vars/myBuild.groovy` 中定义一个步骤：

```groovy
// vars/myBuild.groovy
// 定义一个可复用的构建步骤

def call(String version = 'latest') {
    echo "Building version: ${version}"
    sh "mvn clean package -Dversion=${version}"
}

// 你也可以提供帮助文档，创建 myBuild.txt 文件
```

`myBuild.txt` 内容：

```
Build the project with Maven.

Usage:
  myBuild version: '1.0.0'  // 可选参数说明
```

在 Pipeline 中使用：

```groovy
@Library('my-shared-library') _

pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                // 调用共享库中的步骤
                myBuild '1.0.0'
            }
        }
    }
}
```

#### 完整 Pipeline 定义（vars 目录）

在 `vars/ciPipeline.groovy` 中定义完整的 Pipeline 模板：

```groovy
// vars/ciPipeline.groovy
def call(Map config = [:]) {
    // 默认配置
    def defaultConfig = [
        'appName': 'my-app',
        'version': 'latest',
        'skipTests': false,
        'deployEnv': 'staging'
    ]
    config = defaultConfig + config

    pipeline {
        agent any

        options {
            timeout(time: 30, unit: 'MINUTES')
            buildDiscarder(logRotator(numToKeepStr: '10'))
        }

        stages {
            stage('Checkout') {
                steps {

            }

                }
            }

                    sh "./deploy.sh ${config.deployEnv}"
                }
            }
        }

        post {
            success {

            failure {

            }
        }
    }
}
```

```groovy
// Jenkinsfile for Java Maven project
@Library('jenkins-shared-library') _

pipeline {
    agent {
        docker {
            image 'maven:3.8-openjdk-11'
            label 'docker-enabled'
            args '-v /root/.m2:/root/.m2'
        }
    }

    options {
        timeout(time: 1, unit: 'HOURS')
        buildDiscarder(logRotator(numToKeepStr: '30'))
        disableConcurrentBuilds()
    }

    parameters {
        string(
            name: 'BRANCH',
            defaultValue: 'main',
            description: 'Git branch to build'
        )
        choice(
            name: 'MAVEN_GOAL',
            choices: ['clean package', 'clean install', 'clean verify'],
            description: 'Maven goal to execute'
        )
        booleanParam(
            name: 'RUN_INTEGRATION_TESTS',
            defaultValue: false,
            description: 'Run integration tests'
        )
    }

    environment {
        MAVEN_OPTS = '-Xmx1024m'
        APP_NAME = 'my-java-app'
    }

    triggers {
        githubPush()
        pollSCM('H/5 * * * *')
    }

    stages {
        stage('Checkout') {
            steps {
                echo 'Checking out source code'
                checkout scm
            }
        }

        stage('Build') {
            steps {
                echo 'Building application'
                sh 'mvn ${MAVEN_GOAL} -DskipTests'
            }
        }

        stage('Unit Tests') {
            steps {
                echo 'Running unit tests'
                sh 'mvn test'
            }
        }

        stage('Integration Tests') {
            when {
                expression { params.RUN_INTEGRATION_TESTS }
            }
            steps {
                echo 'Running integration tests'
                sh 'mvn verify -DskipUnitTests'
            }
        }

        stage('Code Analysis') {
            steps {
                echo 'Running code analysis'
                script {
                    try {
                        sh 'mvn sonar:sonar -Dsonar.host.url=http://sonarqube:9000'
                    } catch (Exception e) {
                        echo "SonarQube analysis failed: ${e.message}"
                        // 不阻塞构建，仅记录
                    }
                }
            }
        }

        stage('Package') {
            steps {
                echo 'Packaging application'
                sh 'mvn package -DskipTests'
                archiveArtifacts artifacts: 'target/*.jar', fingerprint: true
            }
        }

        stage('Deploy to Staging') {
            when {
                anyOf {
                    branch 'develop'
                    branch 'main'
                }
            }
            steps {
                echo 'Deploying to staging environment'
                script {
                    def deployer = new com.example.Deployer(this)
                    deployer.deploy('staging', 'my-java-app')
                }
            }
        }

        stage('Deploy to Production') {
            when {
                expression { currentBuild.resultIsBetterOrEqualTo('SUCCESS') }
                branch 'main'
            }
            input {
                message 'Deploy to Production?'
                ok 'Deploy'
                parameters {
                    choice(name: 'CONFIRM', choices: ['yes', 'no'], description: 'Confirm deployment')
                }
            }
            steps {
                echo 'Deploying to production'
                script {
                    if (params.CONFIRM == 'yes') {
                        def deployer = new com.example.Deployer(this)
                        deployer.deploy('production', 'my-java-app')
                    } else {
                        echo 'Deployment cancelled by user'
                    }
                }
            }
        }
    }

    post {
        always {
            echo 'Cleaning workspace'
            cleanWs()
        }

        success {
            echo 'Pipeline succeeded'
            emailext(
                subject: "成功: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                body: """
                    Pipeline 执行成功
                    项目: ${env.JOB_NAME}
                    分支: ${params.BRANCH}
                    构建: ${env.BUILD_NUMBER}
                    URL: ${env.BUILD_URL}
                """.stripIndent(),
                to: 'devops@example.com'
            )
        }

        failure {
            echo 'Pipeline failed'
            emailext(
                subject: "失败: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                body: """
                    Pipeline 执行失败
                    项目: ${env.JOB_NAME}
                    分支: ${params.BRANCH}
                    构建: ${env.BUILD_NUMBER}
                    URL: ${env.BUILD_URL}
                """.stripIndent(),
                to: 'devops@example.com'
            )
        }

        cleanup {
            echo 'Cleanup completed'
        }
    }
}
```

## 6.8 小结

本章详细介绍了 Jenkins Pipeline 的核心概念和实践：

1. **Declarative Pipeline**：适合大多数场景的声明式语法，结构清晰，语法错误可提前发现
2. **Scripted Pipeline**：使用 Groovy 脚本，灵活度高，适合复杂逻辑
3. **核心组件**：agent、stages、steps、when、environment、options、triggers、parameters、post
4. **错误处理**：通过 try/catch、retry、timeout 等机制保证 Pipeline 稳定性
5. **共享库**：通过 @Library 注解复用通用逻辑，提高代码可维护性
6. **最佳实践**：结构化组织、敏感信息安全、性能优化、环境隔离

掌握这些内容后，你能够编写出专业、可维护的 Jenkins Pipeline 脚本，实现企业级的持续集成和持续部署流程。
